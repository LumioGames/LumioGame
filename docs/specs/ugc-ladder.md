# UGC 阶梯

> **状态**：设计中
> **适用范围**：Lumio 全线产品
> **上游**：[`product-direction.md`](product-direction.md)

## 0. 一条必须现在就注意的约束

架构规定 **V1 不允许加载第三方代码**。所以早期的 UGC 只能靠**填数据**实现——改配置、摆地图、写模式描述。

> **这意味着「模式能表达多少东西」必须在第一款游戏时就想清楚。**
> 如果一开始设计得太窄，后面想开放 UGC 就得推翻重来——而在这套架构里，这属于**破坏性变更**，代价很大。

结论：**L2（做模式）的数据格式，要在做炸弹人的同时一起设计**，哪怕炸弹人自己用不上。

## 1. 五级阶梯

| 层 | 玩家能做什么 | 开放时机 | 前置条件 |
|---|---|---|---|
| **L0 调规则** | 改局时、软砖密度、道具权重、初始数值 | **首发即开放** | 无，架构已支持分层配置 |
| **L1 做地图** | 搭地形、放出生点与目标点 | ① 之后 | 地图编辑器 + 地图分享 |
| **L2 做模式** | 定胜负条件、角色、流程阶段 | ② 前后 | **模式数据格式（需现在设计）** |
| **L3 自建服 / Fork** | 开自己的服务器、改我们的代码 | **现在就能开** | 只差文档和一键部署模板 |
| **L4 装 Mod** | 使用别人做的扩展 | 很后面 | 架构上属 P2，需专门决策 |

## 2. 各层展开

### L0 · 调规则（首发即开放）

炸弹人的房主规则面板就是 L0 的全部形态：

- 局时
- 软砖密度、再生速率
- 掉落率、道具与帽子宝箱的池内权重
- 各道具开关、死亡掉帽比例、重生秒数
- 初始火力 / 炸弹数 / 移速

**几乎零成本，但能立刻让服主有事可做。** 这是把"服主"这一层用户激活的最小动作。

### L1 · 做地图

需要两样东西：**编辑器**和**分享渠道**。

编辑器可以从"在游戏内用建造模式搭一张图然后保存"起步，不必一开始就做独立工具。分享渠道初期可以就是一个文件——服主把地图文件放进服务器目录即可。

### L2 · 做模式（最关键、最需要提前设计）

"模式即数据"的意思是：**胜负条件、角色分配、流程阶段、计分规则，全部用配置描述，而不是写代码。**

举例，同一套炸弹人底层，通过数据应该能表达出：
- 标准混战
- 团队赛
- 只有一颗炸弹的"烫手山芋"
- 不能放炸弹、只能踢炸弹的变体

**如果数据格式能覆盖这些，L2 就成立；如果不能，UGC 就永远停在换地图。**

### L3 · 自建服 / Fork（现在就能开）

这是**成本最低、但最能体现定位**的一层：

- 代码是 Apache-2.0，任何人可以 Fork
- 架构里"玩家自建服"是官方支持的部署形态，不是黑魔法

**目前唯一缺的是文档。** 需要：
- 一键开服的部署模板
- "如何改一条规则并跑起来"的上手教程
- Fork 后如何跟上游同步

**建议在 ① 发布时就把 L3 开出去**——它不需要等任何技术前置，只需要写文档。这是最快建立"这真的是开源项目"认知的动作。

### L4 · 装 Mod

架构上属于后置能力，且有明确限制（不能加载原生库、不能绕过运行时契约）。**不在当前规划范围内**，但 L2 的数据格式设计要为它留余地。

## 3. 开放节奏建议

```
① 炸弹人发布  →  L0 调规则 + L3 自建服/Fork（同步开放）
      ↓
    L1 地图编辑器
      ↓
② 起床战争    →  L2 模式数据（格式在 ① 期间就已设计完成）
      ↓
                  L4 Mod（需专门决策）
```

**关键点：L3 不要等。** 它零技术成本，却是"开源平台"这个定位最直接的证据。
