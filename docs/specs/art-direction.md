# 美术风格规范

> **状态**：设计中
> **适用范围**：Lumio 全线产品（统一视觉语言）
> **上游**：[`product-direction.md`](product-direction.md)

## 0. 唯一目标

「3D 体素地形 + 2D 角色 + 俯视角」在市面上几乎没有先例。最接近的参考是 **Core Keeper**（俯视+挖掘+联机，但纯 2D）和 **Don't Starve**（2D 角色 + 2.5D 场景）。

这是辨识度机会，但风险很实在：**规整的方块几何**和**手绘的平面角色**是两种材质语言，很容易看起来像「贴纸贴在乐高上」。

> **本规范的所有条款，都服务于一个目标：让方块和角色看起来属于同一个世界。**

## 1. 风格定调

**手绘卡通 + 硬描边 + 有限色板。**

| 要素 | 口径 |
|---|---|
| 质感 | 手绘卡通，不追写实，不用 PBR |
| 描边 | **角色必须有硬描边**；地形描边更轻或只勾轮廓 |
| 色板 | **有限色板**，全局统一。不允许单个资产自带一套色 |
| 光影 | 风格化二值/三值明暗（cel-shading），不做柔和渐变 |

核心思路：**用"统一的不写实"消解材质冲突**。既然两边都不追求真实，"像不像"就不再是问题，"像不像一家人"才是。

硬描边是把它们缝在一起的针脚——角色有描边、方块有描边，视觉上就成了同一套语言。

## 2. 方块尺寸：战术棋盘感

这不是技术参数，是**产品气质**决策。

| 方块大小 | 世界感 | 适合 |
|---|---|---|
| 小（0.5 米以下） | 造型细腻，但建造感弱、**破坏读数模糊** | 装饰性游戏 |
| 中（1 米，Minecraft 式） | "可进入的世界"，建造感强 | 沙盒、生存 |
| **偏大 + 明确网格** | **战术棋盘**，一眼读懂地形格局 | **俯视竞技（我们）** |

**结论：1 格 = 1 米，且保留明确的格线感。角色约占 1 格宽、1.2 格高。**

理由是策划性的：俯视竞技游戏，玩家必须**一眼看懂"哪里能走、哪里刚被炸掉"**。棋盘感在这里不是妥协，是优点。角色约等于一格，让"我在哪一格"永远无歧义——这对炸弹人是刚需。

大方块的另一个好处：**"少了一格"视觉上极其清晰**。破坏类玩法靠这个建立反馈。

## 3. 角色规格

| 项 | 规格 | 理由 |
|---|---|---|
| 比例 | **Q 版 2–3 头身**（大头） | 俯视角下角色在屏幕上很小，写实比例会糊成一团。Among Us / 蛋仔 / 糖豆人全是这个解 |
| 朝向数 | **8 向** | 4 向对炸弹人够用，但 ③ 需要瞄准。**按 8 向做，资产才能跨产品复用** |
| 呈现方式 | Y 轴 billboard（始终面向相机、保持站立） | 平躺会穿模进地形 |
| 描边 | 硬描边，**不随距离衰减** | 保证小尺寸下的剪影清晰 |
| 接地阴影 | **强制**，每个角色脚下一个 | 见 §5 |

## 4. 相机与投影

| 项 | 规格 |
|---|---|
| 投影 | **正交（Orthographic）** |
| 俯角 | **55°–65°**（待原型验证） |
| 旋转 | **固定不可旋转** |

**为什么正交**：方块网格永远对齐、不产生透视畸变，风格统一；且角色 sprite 只需要有限朝向，不用处理透视缩放——这对 AI 批量生成资产极其友好。

**为什么不是正上方 90°**：完全垂直俯视会让 2D 角色只剩一个头顶，表情和造型全部作废。55°–65° 能同时看到角色正面和地形格局。

**为什么固定不可旋转**：8 向 sprite 的前提就是相机不转。相机一转，朝向数就得翻倍。

## 5. 光照与接地

- 单一方向光 + 环境光，**不做实时阴影**
- 角色不接受动态光照，用**统一的风格化着色**（避免 2D 角色在 3D 光照下露馅）
- **每个角色、每个可拾取物、每个炸弹，脚下必须有接地阴影**

> 接地阴影不是装饰。**俯视角下它是唯一的空间锚点**——没有它，玩家无法判断物体是在地面上还是浮空，角色会"飘"。这是这套画面最容易翻车的地方。

## 6. 配色与竞技可读性

俯视 + 多人 + 快节奏，可读性是硬需求，不是美术偏好。

| 规则 | 说明 |
|---|---|
| **地形低饱和，角色高饱和** | 角色永远要从背景里跳出来。地形是舞台，不是主角 |
| **队伍识别不能只靠颜色** | 考虑色盲和小屏幕。颜色 + 剪影 + 图标，至少两条并行 |
| **危险区域画在地面上** | 炸弹范围、毒圈、陷阱——必须有地面指示，不能只有空中特效 |
| **可交互物有恒定高光** | 可拾取、可破坏、可交互的东西要能一眼挑出来 |
| **UI 不遮挡角色脚下** | 脚下是接地阴影和地面指示的区域，UI 不能压在上面 |

## 7. 资产生产与 AI 管线

选手绘卡通的一个关键理由：**美术产能最高**。

2D sprite 相对 3D 骨骼角色，制作成本塌方式下降，而且 sprite sheet 可以被 AI 批量生成和迭代，rigged 3D 模型不行。这直接支撑"一个引擎托多款游戏"和"UGC 角色"两个长期目标。

代价是**玩家自己画角色的门槛偏高**（相比像素风）。缓解方式：提供角色模板 + 换色/配件系统，让 UGC 从"换装"起步，而不是从"从零画一个角色"起步。

## 8. 反面清单（会毁掉这套画面的做法）

1. **角色和地形都用高饱和** → 画面糊成一团，看不清谁是谁
2. **省掉接地阴影** → 所有东西都在飘，空间关系崩溃
3. **方块做小** → 破坏没有读数，炸掉一块看不出来
4. **上写实光照 / PBR** → 2D 角色立刻露馅，两种材质开始打架
5. **队伍只靠颜色区分** → 色盲玩家和小屏幕玩家直接出局
6. **允许相机旋转** → 8 向 sprite 体系崩溃
7. **每个资产自带色板** → 多款游戏之间失去统一感，平台定位失效

## 9. 待原型验证的项

以下条款是**推断，不是结论**，必须在抛弃型原型里实拍验证：

- 相机俯角具体取值（55° / 60° / 65°）
- 描边粗细是否随镜头缩放变化
- 手绘角色与方块地形在实际运动中是否真的"像一家人"
- 8 向在快速移动时是否够用（会不会看出跳向）

**验收方式**：截图给不认识这个项目的人看，问两个问题——"这好看吗"、"这是什么游戏"。
