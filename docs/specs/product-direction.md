# Lumio 产品定位

> **状态**：设计中
> **适用范围**：Lumio 全线产品
> **下游文档**：[`art-direction.md`](art-direction.md)、[`ugc-ladder.md`](ugc-ladder.md)、各产品设计稿

## 1. 一句话定位

**Lumio 是一个开源的多人小游戏平台**——用「体素世界 + 2D 角色 + 俯视角」的统一视觉语言，承载一系列**可自建服、可改造**的联机小游戏。

## 2. 为什么是平台，不是单品

体素、俯视角、派对游戏，市面上都有人做。**真正没有人做的是「开源 + 玩家自建服 + 可 Fork」。**

参考路径很清楚：Minecraft 的小游戏服务器生态（起床战争、躲猫猫、跑酷）本质上就是一个 UGC 平台，Roblox 是它的终极形态。但两者都是封闭的——你不能改引擎，不能真正拥有自己的服务器。

而 Lumio 的技术架构**天生就是奔着多产品去的**：支持多款游戏同时在线、模式可以是纯数据、玩家自建服是官方支持的部署形态。

> **策略：先用自研玩法开路，再开放创作能力。**
> 不赌单个爆款，但也不空转做工具——用 1～3 款自研产品把引擎、观感和社区跑通，同时把创作能力逐层放开。

## 3. 三层目标用户

| 层 | 是谁 | 我们给他什么 | 决定什么 |
|---|---|---|---|
| **玩家** | 玩 Among Us / 糖豆人 / 蛋仔派对的轻竞技派对用户 | 好玩、开黑、短局 | **决定死活** |
| **服主** | 想开自己服务器、自己定规则的社区组织者 | 一键开服 + 规则可调 | 决定粘性 |
| **创作者** | 做地图、做模式的人 | 地图编辑器 → 模式编辑器 | **决定天花板** |

开源真正的受众是第二、三层。但**没有第一层，第二三层不会出现**——服主不会为一个没人玩的游戏开服。所以首发产品必须先在"好玩"上站住。

## 4. 四条差异化

1. **开源可 Fork**（Apache-2.0）——玩家可以改任何东西，包括我们不同意的部分
2. **自建服是一等公民**——不是"我们施舍的功能"，而是官方支持的部署形态
3. **统一视觉语言**——多款游戏共享美术观感与资产，玩家换游戏不换世界
4. **赛后回放**——引擎天生完整记录每局操作，"重看当时发生了什么"几乎是白送的能力

第 4 条值得单独说：这是所有联机对抗游戏体验最差的一环（吵架永远吵不明白）。我们能直接放录像。

## 5. 产品阶梯

三款不是三个孤立项目，是**一条难度递增、每步只新增一个维度**的验证链。

| | 产品 | 局时 / 人数 | 这一步要证明什么 | 新增的挑战 |
|---|---|---|---|---|
| **①** | 体素炸弹人 | 约 6 分钟滚动局 / 8–100 人（官方房上限 100） | 体素破坏好不好玩、帽子社交动态转不转得起来、**画面成不成立**、**100 人同房跑不跑得动** | 基线 + 100 人负载 |
| **②** | 起床战争俯视改编 | 15–20 分钟 / 16 人 | 建造 + 团队 + 局内经济 | 长局、队伍协作、建造深度 |
| **③** | 逃离鸭科夫 | 20–30 分钟 / 10–15 人 | 持久化背包、PvPvE、撤离张力 | **跨局存档经济**、AI、高风险容错 |

### 各自的使命

- **① 炸弹人**——**回答"这个画面组合到底好不好看"**。规则极简、局时短、地图随人数缩放，把变量压到最低，只暴露两个问题：好不好玩、好不好看。它同时站上架构的第一阶段目标负载（单房间 100 人，ADR 0011），把 100 人同房的技术风险前置到首发暴露。交付顺序按 ADR 0013：先 headless 逻辑层（跑得动、跑得对、可重放），再接浏览器客户端验证好不好玩，画面最后。
- **② 起床战争**——第一款有"深度"的产品。证明我们能承载建造、团队配合和局内经济，而不只是快节奏小游戏。
- **③ 逃离鸭科夫**——**商业潜力最大的一款**。塔科夫品类的痛点极其明确：硬核、阴郁、劝退新人。"可爱鸭子 + 撤离玩法"是一个真实的市场空位——保留撤离的核心张力（带东西进去、活着带更多出来、死了全丢），但把调性从压抑改成滑稽。它也最吃我们的差异化：撤离玩法天生适合玩家自建服（自定义掉落率、地图、难度）。

## 6. 明确不做什么

| 不做 | 原因 |
|---|---|
| MMO / 大世界 | 架构是房间制，单房间目标负载 100 人，不是无缝世界 |
| 开放世界持续在线 | 每局独立地图，局结束即回收 |
| 首发技能/段位匹配 | 引擎目前没有匹配；「房间目录 + 快速加入」已登记为 ① 的入口依赖（[`risks-and-engine-asks.md`](risks-and-engine-asks.md) A6），**房间码是保底起点**；技能匹配等有人再说 |
| V1 代码 Mod | 架构规定 V1 不加载第三方代码，早期 UGC 只能靠数据 |
| 首发接 Unity 等游戏引擎 | 后续客户端暂定浏览器，逻辑先行、表现最后接（ADR 0013）；Unity / HybridCLR 降级为后续候选 |
| 买量驱动的商业化 | 开源项目，先做社区和口碑 |

## 7. 成功判据

每款产品有一个**可判定的**成功问题：

- **① 炸弹人**：拉一个不认识这个项目的人中途进房，能不能 **30 秒看懂谁在赢，并自愿留满 3 局以上**？满房 100 人时这条判据仍须成立。
- **② 起床战争**：20 分钟的局时，中途退出率能不能压住？
- **③ 逃离鸭科夫**：玩家会不会**心疼自己的仓库**？（跨局资产的情感投入是这个品类的命门）

平台层面的判据：**第一个不是我们的人开的服，什么时候出现。**
