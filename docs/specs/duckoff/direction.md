# 逃离鸭科夫 · 方向稿

> **状态**：设计中（方向级，不展开细节）
> **序位**：阶梯 ③
> **上游**：[`../product-direction.md`](../product-direction.md)、[`../art-direction.md`](../art-direction.md)

## 1. 使命与市场判断

**三款里商业潜力最大的一款。**

塔科夫品类的痛点极其明确：**极度硬核、画面阴郁、劝退新人**。而"可爱鸭子 + 撤离玩法"是一个真实的市场空位——

> 保留撤离的核心张力（带东西进去、活着带更多出来、死了全丢），
> 但把调性从**压抑**改成**滑稽**。

品类可行性参考：**Zero Sievert**（俯视撤离射击）已经证明了俯视角能承载这个品类。而我们的手绘卡通风格正好提供了塔科夫做不到的调性差异。

它也最吃我们的差异化：**撤离玩法天生适合玩家自建服**——自定义掉落率、地图、难度、复活规则，每个服都能有自己的规矩。这正好落在"开源小游戏平台"的定位上。

## 2. 核心循环

```
准备（选装备带进去）→ 进图 → 搜刮 → 遭遇（PvP / PvE）
    ↓                                      ↓
  成功撤离                                死亡
    ↓                                      ↓
战利品进仓库                          带进去的全丢
    ↓                                      ↓
    └──────────→ 下一局 ←──────────────────┘
```

**情感核心**：不是"打赢"，是**"心疼"**。玩家必须真的舍不得自己的仓库，这个品类才成立。

## 3. 局制规格（暂定）

| 项 | 规格 |
|---|---|
| 人数 | 10–15 人 / 局 |
| 局时 | 20–30 分钟 |
| 对抗 | **PvPvE**——玩家之间对抗 + AI 敌人 |
| 撤离 | 地图边缘多个撤离点，部分有条件（需道具/需等待） |

## 4. 最大未知数：跨局存档

**这是 ③ 与 ①② 的根本区别。**

炸弹人和起床战争都是**一局结束数据清零**。鸭科夫需要仓库、装备、经济在局与局之间**持续存在**。

这意味着需要**账号级持久化数据**——而目前架构里只有"单局存档/迁移"的概念，**没有"玩家账号资产"这一层**。

需要定义的数据模型：

| 数据 | 说明 |
|---|---|
| 仓库 | 玩家跨局持有的物品集合 |
| 出装 | 带进本局的装备（死亡即失去） |
| 货币 | 交易与购买 |
| 进度 | 任务、声望、解锁 |

**这是 ③ 立项前必须先谈妥的事**，见 [`../risks-and-engine-asks.md`](../risks-and-engine-asks.md)。

## 5. 调性设计

可爱不等于没有紧张感。调性的目标是**"滑稽的高风险"**：

- 角色是鸭子，动作滑稽，死亡表现夸张但不血腥
- 但**损失是真实的**——装备真的会没
- 音效和节奏保持紧张（脚步声、远处枪响），视觉保持轻松

这个反差本身就是卖点：**看起来人畜无害，玩起来心跳加速。**

## 6. 相对 ①② 的新增维度

| 维度 | ① 炸弹人 | ② 起床战争 | ③ 逃离鸭科夫 |
|---|---|---|---|
| 数据生命周期 | 单局 | 单局 | **跨局持久化** |
| 敌人 | 只有玩家 | 只有玩家 | **玩家 + AI** |
| 失败代价 | 无 | 输一局 | **真实资产损失** |
| 局时 | 2–3 分钟 | 15–20 分钟 | **20–30 分钟** |

## 7. 待解决

| 问题 | 说明 |
|---|---|
| **跨局存档数据模型** | 架构里不存在这一层，见 §4 |
| **断线重连** | 30 分钟局时 + 死亡掉装备，掉线 = 玩家资产损失。**这是会让人退游的**，③ 立项前必须解决 |
| AI 敌人 | 引擎有 Bot 基础设施，但战斗 AI 是全新工作量 |
| 新手保护 | 硬核品类的最大流失点，需要设计低风险入门局 |
| 自建服的经济平衡 | 服主可改掉落率 → 官方服与社区服的资产是否互通 |
