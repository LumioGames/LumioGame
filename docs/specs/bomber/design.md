# 体素炸弹人 · 设计稿

> **状态**：设计中
> **序位**：Lumio 首发产品（阶梯 ①）
> **上游**：[`../product-direction.md`](../product-direction.md)、[`../art-direction.md`](../art-direction.md)

## 1. 使命

**它的首要任务不是赚钱，是回答三个问题：「这个画面组合到底好不好看、这套破坏玩法到底好不好玩、帽子塔能不能自发制造出『围攻帽王』的社交戏剧」。**

因此设计原则是**把所有变量压到最低**：规则极简、地图小、局时短、不做养成。任何"以后可能有用"的系统一律不进首发。

一句话规则（30 秒讲清的版本）：**「炸人抢帽子，帽子最多的赢；死了掉帽子，几秒复活。」**

> 核心循环与会话模型的定调依据见 ADR [`0006`](../../../.spec/decisions/0006-bomber-hat-scoring-rolling-room.md)（取代早期淘汰制方案）。

## 2. 核心循环

```
        发育：炸软砖 → 掉道具/帽子宝箱 → 变强/得帽
          ↑                                ↓
   重生（数秒） ← 被炸死·帽子散落 ← 炸掉对手·捡他的帽子
          ↑                                ↓
          └── 帽子垒高 → 成为帽王 → 被全场围攻 ──┘

   会话：局计时结束 → 结算（15 秒）→ 自动下一局（房间连轴转，随时进出）
```

帽子经济只有两条通道：**宝箱=发行**（把帽子注入场内），**击杀=转移**（帽子在玩家间流动）。谁都能看见谁最富——帽子塔就长在头顶上。

## 3. 产品支柱

五条可证伪的支柱，用来否掉未来的具体提案：

| # | 支柱 | 这意味着 | 这不意味着 |
|---|---|---|---|
| 1 | **帽子塔就是计分板** | 局势长在世界里，中途进场者一眼看懂谁在赢；否掉任何把主计分藏进 UI 面板的提案 | 没有任何 UI（计时、结算仍有） |
| 2 | **领先自带风险，制衡靠玩家不靠数值** | 帽王更显眼、更被觊觎，围攻是自发行为；否掉「帽子多移速慢」类数值惩罚，也否掉给帽王的数值奖励 | 系统不为帽王的可见性做任何事 |
| 3 | **死亡是节奏不是惩罚** | 唯一死亡代价是帽子散落；否掉长重生 CD、死亡扣分、死亡清道具、出局观战 | 死亡无代价（帽子就是代价） |
| 4 | **随时能进，进来就懂** | 中途加入是一等公民，新系统不得提高进场理解成本；否掉第二计分资源、开局仪式流程 | 玩法没有深度（道具与地形博弈仍在） |
| 5 | **一局是一场围绕帽王的戏剧** | 发行→积累→帽王→围攻→崩塌哄抢→新王，一局内多次轮回；否掉让帽子流转停滞的设计（如帽子绑定不掉落） | 固定剧本或强制平均分配戏份 |

## 4. 局制规格

| 项 | 规格 |
|---|---|
| 人数 | 目标在场 **8–12 人**，随中途进出浮动；成局下限与上限待验证 |
| 模式 | 首发只做**帽子乱斗（FFA 计分）**；团队帽子赛作为第二模式候选（兼作模式数据格式的试金石，见 [`../ugc-ladder.md`](../ugc-ladder.md) §0） |
| 局时 | **5–10 分钟**滚动局，倾向先测 5 分钟（推断待验证） |
| 胜负 | 计时结束，**头顶帽子最多者胜** |
| 平局 | 帽数并列即并列同胜，不加赛 |
| 中途进出 | 任意时刻可加入（局末锁入期除外，见 §11）；中途退出者帽子当场散落回流 |

## 5. 地图规格

**尺寸：19 × 19 格**（基准图；人数上限若提高需 23 × 23，待验证）

三类格子：

| 类型 | 说明 | 分布 |
|---|---|---|
| **硬砖** | 不可破坏 | 固定阵列：行列均为偶数索引的交叉点 |
| **软砖** | 可被炸掉，可能掉道具/宝箱 | 随机填充剩余空格的 **65%** |
| **空地** | 可通行 | 其余 |

**出生/重生点**：8 个，沿地图外圈均匀分布，兼作重生点。每个点保证 **L 形 3 格安全区**（该点 + 相邻两方向各一格为空地），避免落地即死。

**对称性**：地图左右/上下镜像对称，重生点彼此等价。软砖分布可随机，但必须**镜像同步**。

**软砖再生**：滚动局会把软砖耗尽，导致后半局无方块可炸、无掉落来源。软砖按固定间隔在**无人区域**再生，直至恢复目标密度（速率待验证）。再生是低频方块写入，量级远低于爆炸破坏，不新增跨 World 事务风险。

## 6. 操作方案

一套玩法，两套操作。

| 动作 | PC | 移动端 |
|---|---|---|
| 移动 | WASD / 方向键 | 左侧虚拟摇杆 |
| 放炸弹 | 空格 | 右下主按钮 |
| 主动道具 | Shift | 右下副按钮 |

**移动手感**：自由八向移动（非格子对齐），但带**转角自动修正**——玩家贴着墙角走时自动吸附进通道。这是现代炸弹人手感的关键，没有它会频繁卡墙角。

**移动端布局**：两个按钮都在右下，拇指自然覆盖范围内。摇杆区域不与角色重叠（否则手指挡住自己）。

## 7. 炸弹机制（核心）

### 7.1 基础规则

| 项 | 数值 |
|---|---|
| 引爆时间 | **2.5 秒** |
| 爆炸判定持续 | 0.5 秒 |
| 爆炸形状 | 十字（上下左右四方向） |
| 初始火力 | 1 格 |
| 初始可同时放置 | 1 颗 |

### 7.2 爆炸传播

- 遇**硬砖**：立即阻断
- 遇**软砖**：摧毁该格后阻断（只吃第一层）
- 遇**玩家**：击杀
- 遇**其他炸弹**：**立即连锁引爆**

连锁引爆是这个玩法的爽点来源，必须做对——一串炸弹接连炸开的节奏感是核心记忆点。

### 7.3 掉落

软砖被炸开后 **30% 概率**产生掉落物——道具或**帽子宝箱**（池内权重见 §9）。掉落物停留至被拾取，可被后续爆炸摧毁。

## 8. 道具清单

### 增益（8 种）

| 道具 | 效果 | 上限 |
|---|---|---|
| **火力+** | 爆炸范围 +1 格 | 6 |
| **炸弹+** | 可同时放置 +1 | 6 |
| **速度+** | 移速 +0.35 格/秒 | 6.0 格/秒 |
| **踢弹** | 撞到炸弹可将其踢出 | 有/无 |
| **穿墙** | 可穿过软砖 | 有/无 |
| **遥控引爆** | 改为手动引爆（副按钮） | 有/无 |
| **护盾** | 免疫一次爆炸，消耗后消失 | 可叠 2 层 |
| **钻头** | 主动技，直接挖掉面前一格软砖 | 有/无，5 秒冷却 |

「钻头」是体素特色道具——它是**主动的、有资源成本的方块改动**，正好落在引擎为"消耗资源改方块"设计的主路径上。

### 减益（2 种，制造变数）

| 道具 | 效果 | 持续 |
|---|---|---|
| **反向操作** | 移动方向反转 | 5 秒 |
| **失控放弹** | 强制持续放炸弹 | 5 秒 |

减益道具外观与增益**明确区分**（红色调 + 不同图标），但仍会被误吃——这是设计意图，不是缺陷。

> 帽子与帽子宝箱**不是道具**：帽子没有任何数值效果，规格见 §9。

## 9. 帽子系统（核心）

### 9.1 获取：发行与转移

| 通道 | 规则 | 性质 |
|---|---|---|
| **帽子宝箱** | 软砖掉落池的一种掉落物，拾取得 **1 顶**（数值待验证） | 发行——解决开局全场零帽的冷启动 |
| **中央大宝箱** | 周期性刷新在地图中心，含 **3–5 顶**（周期与数量待验证） | 发行 + 节奏器——周期性制造全场冲突热点（候选，原型验证节奏后定去留） |
| **击杀散落** | 死者帽子**全部**散落在死亡点周围可通行格（全掉 vs 半掉待验证，首发倾向全掉——戏剧最大化） | 转移——帽子在玩家间流动的唯一方式 |
| **退出回流** | 中途退出者帽子当场散落 | 守恒——帽子不随人离场蒸发 |

### 9.2 堆叠与通胀控制

帽子在头顶**物理堆叠**，塔高即分数，无单人数值上限——制衡靠散落与围攻，不靠封顶。

持续发行会让帽子通胀、单顶贬值，需要回收阀，两个候选（待验证，可并用）：

- **发行封顶**：场上帽子总量 ≥ 人数 × K 后，宝箱停止出帽；
- **散落超时消失**：散落帽子 X 秒无人拾取即消失。

### 9.3 帽王可见性

帽子塔本身就是标识（支柱 1/2）——最高的塔自然最显眼。**不默认**追加小地图标记、王冠特效等额外指示；若原型发现俯视角下塔高对比不够醒目，再按待验证项引入（见 §15）。

### 9.4 死亡结算

一击即死（护盾可挡，挡下则帽子不掉）；死亡时帽子散落，**道具成长不清空**——死亡代价单一化（支柱 3），滚雪球已由成长上限拦截（§10）。若原型出现强者恒强，再议道具回退（待验证）。

### 9.5 帽子明确不做的

- **无数值加成**：帽子不加移速/火力/防御——纯计分物（支柱 2 双向：帽王不吃惩罚也不吃奖励）；
- **无种类差异**：首发只有一种帽子；帽子外观/皮肤/收藏属账号级持久化，被引擎前置（[`../risks-and-engine-asks.md`](../risks-and-engine-asks.md) A5）阻塞，记远期不进首发。

## 10. 数值框架

| 参数 | 初始 | 每级 | 上限 |
|---|---|---|---|
| 移速 | 3.5 格/秒 | +0.35 | 6.0 |
| 火力 | 1 格 | +1 | 6 |
| 炸弹数 | 1 | +1 | 6 |

**上限存在的意义**：防止滚雪球。前期领先的玩家如果无上限成长，后半局会变成单方面屠杀，破坏多人局的乐趣。

**成长节奏**：预期玩家在 60 秒内拿到 3–4 个道具进入"火力 3 / 炸弹 3"的舒适区。滚动局下死亡不清成长，全场会趋于满配均势——中后期的差距只剩帽子与操作（推断待验证）。

## 11. 会话与房间

**滚动房间模型**：房间常驻，一局接一局连轴转；玩家随时进、随时走，服务器可同时开多个房间。

```
快速加入 / 房间码 → 进入房间（任意时刻）
   → 局中：立即入场（局末锁入期改为观战等下一局）
   → 局计时结束 → 结算 15 秒 → 自动下一局（房间保持）→ ……
```

**双入口**：

| 入口 | 定位 | 依赖 |
|---|---|---|
| **快速加入** | 默认入口：把玩家丢进一个未满的官方参数房间 | 引擎侧「房间目录 + 快速加入」轻量能力——**已登记为 ① 的入口依赖**（[`../risks-and-engine-asks.md`](../risks-and-engine-asks.md) A6）；不是技能/段位匹配 |
| **房间码** | 保底入口 + 好友开黑 + 自建服/自定义规则房 | 无，首发可用 |

**快速加入只进官方默认参数的房间**；房主改过规则的房间走房间码或房间列表——避免新玩家被丢进认不出的规则变体（推断待验证）。

**局末锁入**：最后 N 秒（待验证，约 30）不再放新人入局，避免进场即结算；锁入期玩家观战等下一局。

**房主可调规则（L0 UGC，首发即开放）**：
- 局时
- 软砖密度、再生速率
- 掉落率、道具与帽子宝箱的池内权重
- 各道具开关、死亡掉帽比例、重生秒数
- 初始火力/炸弹数/移速

这是 UGC 阶梯的第一级，几乎零成本，但能立刻让服主有事可做。

## 12. 死亡、重生与观战

- **死亡**：即死 + 帽子散落。死亡瞬间的帽子飞散要做足表现——它是全场哄抢的发令枪（表现细节归美术，可读性约束见 [`../art-direction.md`](../art-direction.md)）。
- **重生**：数秒后（3–5 秒待验证）在重生点复活；带短暂**重生保护**（1–2 秒无敌 + 闪烁，放弹即解除，时长待验证）；选点避开最近的威胁（规则待验证）。
- **观战**：本模式没有死亡观战等待（支柱 3）；观战只存在于局末锁入期与结算间歇。

## 13. 结算与留存

结算页展示：

- 帽数排名、**帽王时长**（本局持有最高塔的累计时间）
- 击杀数、放弹数、破坏方块数、拾取道具数
- **赛后回放入口**（差异化功能，见 [`../product-direction.md`](../product-direction.md) §4）
- 连胜提示

**首发不做账号进度系统**（等级、皮肤解锁、赛季）。留存靠局内爽感和房间社交，不靠养成。这符合 §1 的"把变量压到最低"；帽子皮肤类外观养成同此，且另被 A5 阻塞（见 §9.5）。

## 14. 平衡原则

1. **不许滚雪球**——成长有上限（§10），帽子零数值加成（§9.5）
2. **重生绝对公平**——地图镜像对称，重生点彼此等价
3. **运气可以有，但不能决定胜负**——掉落是随机的，但帽子只能靠抢：财富分配由冲突决定，不由掉落决定
4. **死得快不如死得明白**——每次死亡玩家都要能立刻看出"我被什么炸死的"，爆炸范围必须画在地面上

## 15. 待验证项

> 数值来源纪律：本稿数值除标注「引用」外均为**推断待验证**；本表是权威清单，逐项写明验证方式（均在原型对局中实测）。

| 项 | 待验证 |
|---|---|
| 引爆 2.5 秒 | 是否太长（拖沓）或太短（来不及跑） |
| 移速 3.5 格/秒 | 与 19×19 地图是否匹配 |
| 软砖 65% + 再生速率 | 开局是否封闭；滚动局中后期密度是否稳定 |
| 掉落率 30% + 帽子宝箱权重 | 成长节奏与帽子发行节奏是否符合 §10/§9 预期 |
| 局时 5 vs 10 分钟 | 一局戏剧轮回（§3 支柱 5）完整且不冗长的最短局时 |
| 人数弹性区间 | 成局下限（2 人？）与上限（12？）；19×19 在两端是否成立 |
| 死亡掉帽比例 | 全掉 vs 半掉：翻盘烈度与挫败感的平衡 |
| 帽子通胀阀 | 发行封顶 vs 散落超时消失，取一或并用（§9.2） |
| 中央大宝箱 | 去留、刷新周期、单箱帽数（§9.1） |
| 重生参数 | 重生秒数、保护时长、选点规则（§12） |
| 局末锁入秒数 | 约 30 秒的取值（§11） |
| 帽子塔俯视可读性 | 俯视 55°–65° 下塔高对比是否醒目——**进 B1 画面验证清单**（[`../risks-and-engine-asks.md`](../risks-and-engine-asks.md)）；不醒目则引入帽王额外指示（§9.3） |
| 终局张力 | 纯计分的最后一分钟是否平淡；若是，引入终局演出（原「死亡收缩」机制是候选，按 ADR [`0006`](../../../.spec/decisions/0006-bomber-hat-scoring-rolling-room.md) 已从核心规则摘除） |
| 转角自动修正 | 强度取值，卡墙角频率 |
| 快速加入 | 引擎侧「房间目录」能力的排期（A6）；落地前房间码单入口是否影响验证 |

**总验收**：拉一个不认识这个项目的人中途进房——能否 **30 秒内看懂「谁在赢、我该干嘛」**，并且**自愿留满 3 局以上**？
