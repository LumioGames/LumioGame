## 1. 使命

当前正式迁移的补充裁定：[ADR0047](../../../.spec/decisions/0047-bomber-m2-six-bombs-and-fixed-skill-values.md)固定六形态与无等级数值；[ADR0048](../../../.spec/decisions/0048-bomber-m2-map-packages-and-interaction-boundaries.md)确定三档地图、金箱穿透、被动踢弹糖、冰桥与狂暴边界。数值仍待真实引擎验证。

**这份设计稿要回答四个问题：「这套破坏玩法到底好不好玩、帽子塔能不能自发制造出『围攻帽王』的社交戏剧、100 人在同一张棋盘上跑不跑得动、这个画面组合到底好不好看」。**

回答顺序按 ADR 0013 固定：**先证明跑得动、跑得对、可重放（headless 逻辑层），再以真实 C# 客户端与 Bot 证明玩法，画面最后。** 当前正式 A–D 范围的浏览器仅作只读旁观；浏览器可玩属于后续客户端宿主工作。任何「以后可能有用」的系统一律不进首发；首发内容按 §16 切片实现，每阶段以量化门通过。

**北极星**（ADR 0038，五条诉求都写成可判定标准）：

| 诉求 | 标准 |
|---|---|
| 简单 | 规则 30 秒讲清；新人要懂的概念 **≤ 6 个**；任何拾取不按键、不做选择；屏幕上每样东西一眼能认 |
| 乐趣 / 快乐 | 每 10 秒至少一次正反馈（拾取、炸开、命中）；连锁、爆装、击杀表现拉满 |
| 竞技 | 胜负靠操作与判断，不靠运气；**所有威胁都看得见**；技巧上限在布连锁、遥控时机、踢弹与抢中心 |
| 成就感 | 成长看得见（帽塔、体型、心数）；击倒 Boss 全场播报；**每局每人都有一张高光卡** |

产品记忆点一句话：**连锁爆炸制造爽感，帽子越高心越多、强者成为 Boss，Boss 倒台全场哄抢。** 值得做成产品的不是「体素 + 炸弹人 + 很多技能」，而是**百人帽王乱斗：体素是可破坏舞台，炸弹是冲突工具，帽子是看得见的实力，活到最后才算赢。**

一句话规则（30 秒讲清的版本，ADR 0038）：**「炸开积木吃糖变强，帽子越高、心越多；炸倒别人他会爆一地；越往中间宝箱越好。每人至少三颗心，死后三秒复活——但最后的决赛圈里死了就出局，圈外有毒，圈会一直缩到只剩一格。活到最后者赢；时间到还有好几个人活着，帽子最多的赢。」**

**新人要懂的六个概念**（支柱 7 的预算，ADR 0038）：① 炸弹与连锁；② 三种糖（火力 / 炸弹 / 速度）= 帽子 = 更多心；③ 特殊炸弹：一个槽，踩到就换；④ 角色技（Shift）+ 最爱炸弹；⑤ 越往中间宝箱越好；⑥ 决赛圈。材质、护城河、爆炸桶、金心、补给通过场上物体与一句话提示学会，不进首局讲解。

## 2. 核心循环

```
        发育：炸积木 / 开资源箱（木箱 → 铁箱 → 金箱，越靠中心越好）→ 掉糖果 / 血包 / 特殊炸弹 / 金心 → 变强（帽子↑ 心数↑）
          ↑                                    ↓
   重生（3 秒） ← 被炸死·强化与特殊炸弹各半掉、金心全掉（帽塔变矮） ← 炸掉对手·捡他掉下的强化、特殊炸弹和金心（帽塔变高）
          ↑                                    ↓
          └── 帽子垒高、心数变多 → 帽王光柱 / Boss 心条 → 被分区乃至全场围攻 ──┘

   决赛圈：积木剩 < 20% 或剩最后 115 秒 → 不再复活·圈外中毒·圈分段一直缩到 1×1（与核心同心）·圈内落强力宝箱 → 死即出局，只剩 1 人立即结束（§4.2）
   会话：选角（沿用上次）→ 局终 → 领奖台 + 高光卡 + 结算表（约 16 秒，Top-10）→ 自动下一局（房间连轴转，随时进出）
```

**帽子 = 强化数的表现**（ADR 0028），**帽子越多心越多**（ADR 0039）：头顶几顶帽子就是身上几个强化，每 4 顶帽子心数上限 +1（最多 +2），再加金心（最多 +3），封顶 8 心。强化、特殊炸弹与金心各两条通道：**积木 / 资源箱 / 补给掉落 = 发行**、**死亡掉落 = 转移**（ADR 0025 / 0039 / 0041）；角色技不流动（§8.0），特殊炸弹与金心不计帽数（§9.5）。谁都能看见谁最强——帽子塔长在头顶上，帽王头顶还有光柱，Boss 头顶常驻心条。

## 3. 产品支柱

九条可证伪的支柱，用来否掉未来的具体提案（7–9 由 ADR 0038 新增，支柱 2 由 ADR 0038 修订）：

| # | 支柱 | 这意味着 | 这不意味着 |
|---|---|---|---|
| 1 | **帽子塔是局部实力榜，Top-10 是全局摘要** | 屏幕内谁最强（强化最多）一眼可见；全局只给 Top-10 侧栏、帽王光柱与屏幕边缘方向箭头；决赛圈起 Top-10 按 §4 排名口径（存活者在前）；否掉把主计分藏进 UI 面板、否掉全员帽数小地图 | 没有任何 UI（计时、Top-10、结算仍有）；也不意味着帽子多就赢——活到最后才赢（§4） |
| 2 | **领先自带风险，成长规则人人相同** | 成长让人更耐打（帽子给心，ADR 0039）是全员同一条规则；帽王更显眼、更被觊觎，围攻是自发行为；否掉「帽子多移速慢」类数值惩罚，也否掉**只给帽王**的数值加成 | 系统不为帽王的可见性做任何事（光柱、箭头、Boss 心条正是为可见性做的）；也不意味着领先者无敌——心数封顶 8、死亡掉一半、毒圈按上限等比（ADR 0039） |
| 3 | **死亡是节奏不是惩罚** | 常规阶段死亡代价只有三项：已吃强化每级 50% 落地（帽塔同步变矮）、特殊炸弹 50% 落地、金心全部落地（角色技不掉；ADR 0025 / 0039 / 0041），3 秒后复活；否掉长重生 CD、死亡扣分、强化全清。**唯一例外是决赛圈**（每局最后 ≤ 115 秒，§4.2）：死即出局、观战到结算 | 死亡无代价（强化、特殊炸弹与金心就是代价）；也不意味着可以在常规阶段引入出局 |
| 4 | **随时能进，进来就懂** | 中途加入是一等公民，新系统不得提高进场理解成本；进房只多一步——**单屏五选一选角**（默认预选上次角色，ADR 0044）；拾取一律走过即生效（特殊炸弹踩到就换，ADR 0041），**不做任何确认、不加按键**；否掉第二计分资源、多步开局仪式、菜单式拾取 | 玩法没有深度（角色技、最爱炸弹、连锁布置、踢弹与抢中心仍在） |
| 5 | **一局是一场围绕帽王的戏剧** | 发行→积累→帽王 / Boss→围攻→崩塌哄抢→新王，在分区内多次轮回，光柱把分区戏剧升级为全场戏剧；否掉让帽子、特殊炸弹或金心流转停滞的设计（如特殊炸弹绑定不掉落）；**角色技是唯一允许的绑定**——身份不是财富、不计帽数（ADR 0030） | 固定剧本或强制平均分配戏份 |
| 6 | **同一套规则从 8 人到 100 人** | 数值不随人数变，只有地图档位随人数缩放；否掉只在大人数下才成立的机制（如 ≥50 人才触发的事件） | 8 人房与 100 人房体验完全一样（密度与戏剧规模自然不同） |
| 7 | **30 秒六概念** | 新人要懂的概念不超过 6 个（§1 清单）；新系统要么落进已有概念，要么替换一个；否掉任何需要记规则表才能用的系统（如元素 × 功能矩阵、看不见的等级数值） | 局内没有新东西可学——材质、护城河、爆炸桶、金心靠场上物体与一句话提示自然学会 |
| 8 | **威胁全可见** | 所有伤害来源都画在地上或角色身上（火焰、留火、冰冻、毒圈、光环、爆炸桶）；否掉隐身（如草丛藏人）与看不见的持续伤害 | 没有信息差——站位、遥控弹何时引爆、对手捡了什么特殊炸弹仍要玩家自己判断 |
| 9 | **人人有高光** | 每局每人至少一个成就时刻：局中里程碑弹字、局末每人一张高光卡（§13，ADR 0043）；否掉只奖励前三名的结算 | 人人平等——排名公式只有一个（§4），高光卡不影响名次 |

### 3.1 爽感时刻

玩法必须稳定交付的「爽」，每条挂钩支柱并标成本类别：**表现层** = 客户端本地表现（零服务器成本、不复制）；**服务器事件** = 一条广播事件；**内容** = GAS 数据或美术资产。表现层全部在 Stage 1 起接入（ADR 0013：逻辑先行），逻辑层只保证事件与数据存在。

| 时刻 | 触发 | 表现 | 支柱 | 成本 |
|---|---|---|---|---|
| 连锁 | 同一爆炸链 ≥ 3 颗 | 「×N 连锁」弹字、屏幕震动随 N 增强、50–80ms 本人定帧（不暂停服务器与他人）；首次 ×5 / ×8 另有里程碑弹字；连锁秒杀见 §7.5 | 5 / 9 | 表现层 |
| 单杀 | 本人击杀任意玩家 | 「击飞 XX！+N」弹字 + 专属击杀音（8 秒内音高递增）+ 70 ms 本人定帧 + 镜头冲击（ADR 0043） | 5 | 表现层 |
| 多杀 | 同一爆炸链击杀 ≥ 2 | 「双杀 / 三杀 / 一锅端（≥4）」弹字 + 音效 | 5 | 服务器事件 + 表现层 |
| 连杀 | 8 秒内连续击杀 / 不死连杀 3 / 5 / 8 | 双杀 / 三杀 / 四杀 / 暴走；大杀特杀 / 主宰 / 超神（本人横幅 + 击杀栏，ADR 0043）；别人的三杀及以上与大杀特杀 / 主宰 / 超神也播带名字的横幅，双杀只挂击杀栏标签（ADR 0044） | 5 / 9 | 表现层 |

## 4. 局制规格

| 项 | 规格 |
|---|---|
| 人数 | **8–100 人弹性**是后续产品阶梯，100 人需经 Stage 3 性能门；当前正式收敛档位为 **8 人 · 19×19 回归、12 人 · 23×23 默认、16 人 · 27×27 对照**（ADR 0044；网页原型 `?map=27` 为 16 人）。正式配置尚未迁入后两档，不以旧 8 人骨架宣称完成。 |
| 模式 | 首发只做**帽子乱斗（FFA 计分）**；团队帽子赛作为第二模式候选（兼作模式数据格式的试金石，见 [`../ugc-ladder.md`](../ugc-ladder.md) §0） |
| 局时 | **封顶 4 分钟**滚动局（ADR 0035，取代 0031 的 7 分钟）：常规阶段最长到 2:05，决赛圈固定 115 秒；**约 2 分钟开圈**——高强度对局约 1:45（再生停止）进入决赛圈、多数约 3:10 以唯一存活者结束，最晚 4:00（推断待验证；A/B 封顶 5 分钟 ≈ 3 分钟开圈） |
| 胜负 | **活到最后者胜**（ADR 0031）：决赛圈内只剩 1 人存活即在致死的同一 Tick 立即结束，他是第 1 名（0 帽也算）；到时间上限仍 ≥ 2 人存活，存活者按帽数（= 强化数，§9）降序排名；出局者一律排在全部存活者之后，出局越晚名次越前。Top-10 上榜 |

### 4.2 决赛圈（最后一命）

ADR 0025 取代 0014「终局只是演出、不用致死收缩圈」；ADR 0031 让决赛圈一直缩到 1×1、打出唯一胜者。决赛圈把「资源耗尽后的空旷后半局」变成一局的高潮：人越来越少、圈越来越小、每一次死亡都算数。

| 项 | 规格（全部推断待验证，除注明「引用」） |
|---|---|
| 触发 | 资源或时间先到先触发：剩余可破坏砖（积木 + 资源箱，再生补回的计入）< 开局的 **20%**，或局时只剩 **115 秒**（封顶 4 分钟下即 2:05）；资源触发**只在软砖再生停止后**生效（ADR 0026；ADR 0035 起再生在距时间触发 20 秒即 1:45 停止，§5）。原型实测高强度对局一律在 1:45 由资源触发（ADR 0035） |
| 时长 | 固定 **115 秒**；资源先触发时局终 = 触发 + 115 秒，整局封顶 4 分钟（引用：§4）；只剩 1 人立即结束 |
| 复活 | 触发后死亡**不再复活**即「出局」：强化、特殊炸弹与金心**全部**掉落（帽数归零，§9.4），观战到结算；触发时已在重生倒计时中的**照常复活一次**，落点取当前安全圈内 |
| 安全圈 | 棋盘中心正方形，**6 段一直缩到 1×1**；19×19 档（内场 17×17）相对触发：+10 s **13×13**、+35 s **9×9**、+55 s **7×7**、+75 s **5×5**、+95 s **3×3**、+110 s **1×1**（棋盘正中心一格）、+115 s 局终；每段前 10 秒地面画出下一圈边界。**27×27 档（内场 25×25，原型默认，ADR 0040）**：+10 s **19×19**、+30 s **13×13**、+45 s **9×9**、+60 s **7×7**、+75 s **5×5**、+95 s **3×3**、+110 s **1×1**；23×23 档：+10 s 15、+30 s 11、+50 s 7、+75 s 5、+95 s 3、+110 s 1。其余档位：末三段同为 5×5 / 3×3 / 1×1，之前按内场边长等比插段、段间 ≥ 15 秒；1×1 取离棋盘中心最近的可通行非铁皮格 |
| 末段清场 | 5×5 / 3×3 / 1×1 **生效的那一刻**清掉新安全圈内全部积木与资源箱：不掉落、不计破坏数，表现复用积木碎块；**只清积木与资源箱**——铁皮、爆炸桶、强力宝箱（不开启，仍只能 3 次独立炸弹命中开启）、糖果不动，未爆炸弹不清（引信 ≤ 2.1 秒）；保证最后安全格每局都进得去。19×19 档一次最多 21 格（5×5 扣 4 根铁柱），3×3 为 5 格十字 |
| 毒圈 | 圈外：5×5 生效前每 1000 ms **−1 点**（每秒 −0.5 心，满血 6 秒毒死）；5×5 生效起每 1000 ms **−2 点**（每秒 −1 心，满血 3 秒）；**按受害者心数上限等比**：每 1000 ms 扣 ⌈段点数 × 当前上限 / 6⌉ 点，任何上限下满血约 6 秒 / 3 秒毒死（ADR 0039）；重生保护与泡泡都**不**免疫；毒死按自杀口径（`Killer == Victim`），死因 = 毒圈（新增 `Cause`，见 §12） |
| 强力宝箱 | 每段收缩预告时在**下一圈内**随机空地落 1 个，**1×1 段不落**（19×19 共 5 个、27×27 共 6 个）；永不落在中心格，3×3 段之前也不落在 5×5 内的中心十字上（1×1 格因此至少留 3 个入口）；占格、挡路挡火，**3 次独立炸弹命中**开启（同链多颗各算一次，引用：§8.6 小补给箱口径）；喷出火力+ / 炸弹+ / 速度+ 各 1 + 血包 1 + **特殊炸弹 1**（§8.2）+ 20% **金心**（ADR 0039），谁捡归谁；吃到喷出的强化帽塔照常 +1（ADR 0028） |
| 结束与胜负 | 存活（未出局）≤ 1 → 在致死的同一 Tick 立即结算，唯一存活者第 1 名；115 秒到仍 ≥ 2 人存活 → 存活者按帽数排名；口径见 §4 |
| 表现 | 横幅「决赛圈！不能复活，圈外有毒」；地面画当前圈（毒雾 / 紫色边界）与下一圈预告线；HUD 显示存活人数、下次收缩倒计时与当前毒速；出局者看到「你已出局 · 观战中」与名次 |

设计意图：决赛圈是人数减少后的**密度补偿**、**唯一的出局机制**，也负责**打出唯一胜者**——圈一路缩到 1 格、5×5 起毒速翻倍，把最后几个人逼到同一处交战（ADR 0031）；常规阶段仍然是「死亡是节奏」（支柱 3）。毒圈是区域伤害 Effect、零方块写入；末三段清场是三次一次性批量写入（19×19 ≤ 21 格，低于一次满火力爆炸的 24 格，引用：约束 5、§7.4）。掉线在决赛圈内等于出局，115 秒与 4 分钟两个上限把没有快速重连（约束 3）的风险框住。

## 5. 地图规格：人数-地图联动

密度用**两个指标**分开定义（ADR 0014；数值推断待验证）：

| 指标 | 含义 | 目标 |
|---|---|---|
| `potential_walkable_cells_per_player` | 软砖炸光后的潜在**可放弹格** / 人 | 26–30 |

### 5.0 三圈三级资源（ADR 0040）

「越往中间宝箱越好」是新人六概念之一（§1）。按到棋盘中心的切比雪夫距离 d 分三圈，资源箱以**形状与材质**区分（不只靠颜色），数量四象限镜像（27×27 档，全部推断待验证）：

| 圈 | 资源箱 | 数量 | 内容 | 积木掉率 |
|---|---|---|---|---|
| 外圈 d ≥ 9（一级） | 木箱，1 次命中 | 16 | 糖果 / 血包 | 25% |
| 中圈 5 ≤ d ≤ 8（二级） | 铁箱，1 次命中 | 12 | 50% 特殊炸弹 + 1 糖果 | 35% |
| 核心 d ≤ 4（三级） | 金箱，2 次独立炸弹命中（同链多颗各算一次） | 4 | 1 特殊炸弹 + 2 糖果，20% 金心 | 45% |

- 出生在外圈；节奏 = 外圈发育 → 中圈 → 抢核心；核心与决赛圈同心（§4.2），核心中央 3×3 空地广场是中央大补给落点（§8.6）。
- 核心外一圈是护城河（§5.1），四边中点的陆桥是进核心的卡点。
- 三档参数引用ADR0048：19档核心d≤2、中圈3–5、外圈≥6，木/铁/金箱8/4/4；23档核心d≤3、中圈4–7、外圈≥8，箱12/8/4；27档沿用上表。三档使用同一M2规则，旧19档关卡保留为迁移fixture。
- 再生时约 1/6 长成当圈等级的资源箱（本节「软砖再生」）。

**地形分层**（ADR 0016）：地形是三维的，Stage 0a 只用两层——`z = -1` 地面层（地面、水方格、冰桥）与 `z = 0` 砖层（硬砖、软砖、空地、资源箱、爆炸桶），`z ≥ 1` 预留。实体（玩家、炸弹、掉落物）恒在 `Z = 0`，Stage 0a 不做垂直移动，爆炸只向 ±X / ±Y 四个水平方向传播。「破坏后露出地面」在这个模型下就是把砖层置空、露出下面的地面层。

**引擎坐标映射**（ADR 0019）：上面这套是**游戏坐标**，玩法代码只认它。上游体素契约的竖直轴是 `y` 且**无符号**（Section 键 `s:<x>:<y>:<z>` 的 y 限 0~15，世界高 256 格），负竖直坐标在键语法上不可表示，所以 `z = -1` 不能直接过边界。映射是 **游戏 (X, Y, Z) → 引擎 (x = X, z = Y, y = Z + 1)**：地面层 → 引擎 `y = 0`，砖层 → 引擎 `y = 1`。映射只出现在 `ITerrainStore` 的实现里，本节及以下全部按游戏坐标叙述。61×61×2 在引擎侧是 16 个 Section（4×4，竖直只占层号 0）。

三类格子（均在砖层 `z = 0`）：

| 类型 | 说明 | 分布 |
|---|---|---|
| **硬砖** | 不可破坏 | 偶数行列交叉点，三档排除核心和水域；精确模板见ADR0048。后续分区档另构成分区墙 |
| **软砖** | 可被炸掉，按所在圈的掉率掉糖果 / 血包（§5.0 / §7.4）；资源箱另见 §5.0 | 先预留箱和桶，所有初始可破坏占格物合计不超过潜在可放弹格的 **65%**；安全区优先，不能额外再铺65%积木（ADR0048，推断待验证） |
| **空地** | 可通行 | 其余 |
| **补给点** | 分区小补给箱与中央大补给落点（§8.6） | 每分区中心 1 个小补给箱、棋盘中心 1 个大补给落点 |

**分区墙**：硬砖墙把棋盘切成分区，每段墙中点留 **3 格缺口**（推断待验证）。分区是「经典密度的小竞技场」——100 人的遭遇仍是 4–8 人规模，帽王戏剧先在分区内轮回。决赛圈通道常开（§4.1）。

**补给点地形**（规则见 §8.6）：后续分区档小补给箱立在中心一格；23与27档中央大补给落在核心 **3×3空地广场**（ADR0040/0044），四周陆桥保持中心可达。19档同样留中央3×3空地但关闭补给（ADR0048）。历史5×5围院只作迁移对照；三档真实补给、圈清场与中心可达须多种子验证。

**方位语言**：四象限镜像对称会让四个角看起来一样，玩家需要一个「我在哪」的答案。这由 §5.3 断言 8 的**象限地标轮廓**单独承担——**不做象限地色**（ADR 0017：材质目录不为纯外观差异加 4 行；且 §9.6 要求关键目标不只靠颜色，纯地色方案本就不合格）。（推断待验证；Stage 2 起）

**出生 / 重生点**：**动态选点**取代固定 8 点——选当前人数最少的分区，在其中随机取可通行格，距任一玩家与炸弹 **≥ 6 格**（推断待验证），并保证 **L 形 3 格安全区**（该点 + 相邻两方向各一格为空地；不满足则清掉 ≤ 2 格软砖，属微量方块写入）。Stage 0 的 19×19 无分区，只取「距威胁 ≥ 6 格 + L 形安全区」。网页原型 27 档：16 个出生点在外圈，两两 ≥ 6 格（ADR 0040）。

正式引擎的出生搜索按稳定顺序穷举一次合法格，再由引擎随机流在合格候选中选点；不得无限随机重试。无合法格时保留待出生资格，下一业务帧重新评估当前世界，不复用已拒绝的体素事务，也不放宽安全条件偷选威胁格（推断待验证，验证见 §15）。

**对称性**：棋盘四象限镜像对称，分区彼此等价；软砖分布可随机，但必须镜像同步。

**软砖再生**：滚动局会把软砖耗尽，导致后半局无方块可炸、无掉落来源。软砖按固定间隔**只在无人区域**批量再生，直至恢复目标密度（速率待验证）；距时间触发还剩 20 秒时停止再生（封顶 4 分钟下即 1:45，ADR 0035，原 60 秒 = ADR 0026；决赛圈内自然不再生）。再生是低频批量写入，量级远低于爆炸破坏。**19×19 档同样再生**（ADR 0026）：每 8 秒补回至多 2 组四象限镜像积木、直到回到开局的 60%，只长在非水、非出生安全区、格上无物、离活人与炸弹 ≥ 3 格的位置（数值推断待验证）。**27×27 档**：每 8 秒至多 4 组，约 1/6 长成当圈等级的资源箱（ADR 0040，推断待验证）。

### 5.1 场景材质：什么能炸、炸了变成什么

三档地图模板、硬柱排除和阶梯支流按ADR0048：水格28/44/60、硬柱48/80/104、潜在可放弹格213/317/461；初始至少空出75/111/162格。这些是模板计数，不代表SDK底图验收。再生每8秒至多2/3/4组，桶初始和同时上限4/8/8；每个组先以1/32尝试桶（须留足整组名额），其余以1/6成为圈级箱，否则为积木。所有产物共用该次组数和安全条件，预算按最坏全部成功计算。

**地面效果**（走在上面）：护城河——移速 −30%、**不能手动放炸弹**（准入拒绝，不扣库存、不创建炸弹、不发 `BombPlaced`）、**不溺水**（ADR 0042）；已存在的引信弹滑入水时立即熄灭并恰好返还一次容量。冰桥——可走、不减速、可放弹。火地（火焰弹留火）**不是**地面材质，而是炸弹实体留火阶段的覆盖范围（§7.3，ADR 0017）——**按暴露时长伤害：连续站满 1 秒 −1 心（−2 点），之后每满 1 秒再 −1 心，可致死**（§12）。地面层是「砖被炸掉后露出的东西」。

**破坏后的样子**：一律「露出地面 + 材质对应的残留」——积木碎块飞溅、资源箱裂开、爆炸桶焦痕。残留是贴花与粒子（表现层），不是方块；软砖再生按原配比补回（推断待验证）。

**表现**（ADR 0042）：护城河是流动的深蓝水面，进水有水花，火焰撞到水面有白汽与「嗤」声；冰桥用白色系，与水区分；每种材质轮廓与色相一眼可辨（§5.3 断言 7）。

### 5.3 场景可玩性需求（给地图生成器的明确要求）

冰桥生命周期按ADR0048：从成功结冰Tick起8秒，重复冰冻不续期，融化与结冰同Tick时融化优先；旧代数回执不能改新桥。融化成功后该格所有未爆炸弹（包括静止和遥控弹）熄灭，库存或狂暴名额各只返还一次。

每张棋盘必须满足以下断言，生成器不满足即重生成；断言以固定 Seed 样本回归（数值推断待验证）：

1. **两个密度指标**同时落在目标带（本节表头），按**可放弹格**统计。
2. **按圈布置**（ADR 0040 / 0042）：27 档外圈木箱 16、中圈铁箱 12、核心金箱 4、爆炸桶每象限 2（外圈、中圈各 1）；核心外一圈护城河 + 四边中点 4 座陆桥 + 4 条斜向支流；23/27 档核心中央 3×3 空地广场。Stage 2 起的分区档另加每分区 1 个小补给箱。旧 19×19 关卡仅作正式迁移回归数据；M1 原型使用小水塘，护城河与桶仍是 M2 设计。
3. **护城河约占 8% 格子**（推断待验证）；陆桥 ≥ 4 座、每座是陆地；水**不得封死分区缺口或出生安全区**，水边至少留 1 格陆路绕行；**支流不得连到外墙**——否则等于一条横跨全图、火焰打不穿的走廊。
4. **每个可通行格 10 格内可到达一处掩体**（3 秒 × 3.5 格/秒 的换算，按可通行路径长度而非直线距离），软砖全部炸光后重算仍成立。**掩体**定义为「相邻四格中至少有一个是硬砖的可通行格」（ADR 0017：原文只写「一处掩体」而未定义，无法机器判定）。
5. **无死角**：软砖全炸光后任意两可通行格连通，核心经陆桥可达；出生 L 形安全区不含水方格与爆炸桶。（原「出生后 3 秒内不存在不可反应的夹击格」已按 ADR 0017 删除——它未被形式化因而不可机器判定，其意图由重生保护 3 秒、距威胁 ≥ 6 格、L 形安全区三重保障覆盖；作为**体验指标**仍保留在本节表头上方。）
6. **对称与等价**：四象限镜像；补给点、资源箱、护城河与支流、爆炸桶镜像同步。
7. **可读性**：同屏可见材质 ≤ 6 种；三种资源箱与爆炸桶必须在俯视下与积木一眼区分（进 B1）。
8. **地标**：每象限 1 个铁皮地标轮廓（生成器模板，如动物剪影）作方位语言——这是方位的唯一来源，象限地色已取消。

## 6. 操作方案

一套玩法，两套操作。桌面浏览器键鼠优先；触屏浏览器不承诺首发（ADR 0013）。

| 动作 | PC | 触屏 |
|---|---|---|
| 移动（四向，§6.1） | WASD / 方向键 | 左侧虚拟摇杆 |
| 放炸弹 | 空格 | 右下主按钮 |
| 角色技（CD 显示在 HUD） | Shift | 右下副按钮 |
| 引爆遥控弹（持有遥控弹时，ADR 0041） | 长按空格 ≥ 300 ms（点按仍是放弹，不加新键） | 长按放弹键 |
| 飞踢（飞腿袋鼠专属，ADR 0044） | Shift | 副按钮 |
| 选角 | 点击角色卡 | 点击角色卡 |

**触屏布局**：放弹主按钮与技能副按钮都在右下（副按钮显示技能图标与 CD），拇指自然覆盖范围内。摇杆区域不与角色重叠（否则手指挡住自己）。

### 6.1 手感规则（冻结，逻辑层实现）

**四向 + 停**（引用：内核契约 v2 `方向` 枚举，ADR 0021 / 0032），加以下九条冻结规则（ADR 0014 / 0032 / 0050；强度取值推断待验证）：

1. **转角自动修正**：贴着墙角走时自动吸附进通道，吸附阈值 **0.5 格**（连续转角 6 Tick 内降到 **0.25 格**）；不把玩家吸进危险方向。
2. **同按两个方向走得通的那个**：新按下的方向优先；走不通时沿旧方向继续滑行（沿墙滑动），新方向一旦走得通立即转入；两个都走不通才停（ADR 0032）。反方向键不作为回退方向；自动选择不走进危险方向；触屏摇杆副轴 ≥ 主轴一半时算作第二个方向。由规则层判定，客户端不读地形做决定。
3. **炸弹总是落在最近的合法格中心**。
4. **离格穿透**：玩家刚放下自己的炸弹时，在离开该格前可以穿过它；离开后重新进入会被炸弹阻挡。
5. **放弹输入缓冲 125 ms**（ADR 0018 由区间 100–150 收敛为单值，取中点；A/B 100 / 150）：刚进入合法格时自动执行。
6. **权威判定**：移动预测和爆炸命中以服务器权威结果为准，客户端只预测自身移动与放弹表现。
7. **没有碰撞箱，视觉占地 ≤ 0.7 格**：逻辑上玩家是通道中心线上的一个点，玩家之间互不阻挡（ADR 0032）；玩偶脚圈直径 0.7 格、朝移动方向前伸 ≤ 0.35 格，停在墙前不与墙体视觉重叠；脚圈、接触阴影与双脚严格画在插值后的逻辑位置；方向光阴影不得把头影投到前方墙面。
8. 这几条对「顺不顺手」的影响大于增加第五种炸弹形态；Stage 0a 用 Bot 命令流回放验证规则本身，Stage 0b 起用真人验证手感。
9. **按住匀速、短按至少一步、同 Tick 至多一步**（ADR 0050）：一条移动输入 = 一个逻辑 Tick 的意图采样，一步 = 移速 × 一个 Tick（引用：20 Hz 见内核契约 §5，移速 3.5 格/秒见 §15，即每步 0.175 格）。按住时客户端每个预测步恰好采样一条，两端同一 Tick 至多走一步，多收的顺延到后续 Tick（顺延有界，超出上限才拒绝），不在同一 Tick 多走；短按（按下到松开不足一个 Tick）恰好走 1 步并更新朝向，按下沿与短按方向锁存到被下一次采样消费，松键也不丢；松键即停，服务器不替玩家续走移动，转向缓冲（第 1 条）的续行由客户端发「停」采样驱动并进入预测。客户端卡顿后逐步补步，**最多 5 步、累计截断 250 ms**（引用原型 `local-host.ts` 的 `MAX_CATCH_UP` 与 250 ms 截断；手感推断待验证，见 §15），超出部分不补。同一采样内次序固定为移动 → 放弹 → 技能，放弹落在本步移动之后的位置。

## 7. 炸弹机制（核心）

### 7.1 基础规则

| 项 | 首轮默认值 | A/B 值 |
|---|---:|---|
| 引爆时间 | **2.1 秒** | 1.8 / 2.1 / 2.4 秒 |
| 爆炸危险判定持续 | **0.4 秒**（ADR 0018 由区间 0.35–0.4 收敛为单值，取 A/B 中档） | 0.3 / 0.5 秒 |
| 爆炸形状 | 十字（上下左右四方向）；炸弹槽技能可改形态（§8.4） | — |
| 初始火力 | **2 格** | 1 / 2 格 |
| 初始可同时放置 | 1 颗 | 固定 1 |
| 对玩家伤害 | 每颗炸弹 −1 心 = **−2 个半心点**（§12），与火力无关 | — |

（全部推断待验证；ADR 0014 以 v0.4 首轮默认值替换旧推定值。理由：3.5 格/秒 × 2.5 秒引信下玩家可在引爆前移动约 8.75 格，火力 1 只覆盖一格，早期炸弹主要用于挖墙、缺少对人威胁。）

### 7.2 爆炸传播

传播沿 ±X / ±Y 四个水平方向逐格推进，**每一步同时读两层**——地面层 `z = -1`（水方格在这一层却要挡火）与砖层 `z = 0`：

- 遇**硬砖**（砖层）：立即阻断，不覆盖该格
- 遇**软砖**（砖层）：摧毁该格后阻断（只吃第一层；穿透弹例外，见 §7.3）
- 遇**水方格**（地面层）：**覆盖该格后停**——站在水里的人会被炸到，但火焰不穿过水（§5.1）
- 遇**玩家**：−1 心（§12）；冰冻弹同样扣心，再冻结存活者（§7.3）
- 遇**爆炸桶**：0.1 秒后以火力 3 引爆，计入连锁，带上触发者的炸弹效果（§5.1）
- 遇**其他炸弹**：**立即连锁引爆**，并入同一 ChainId

连锁引爆是这个玩法的爽点来源，必须做对——一串炸弹接连炸开的节奏感是核心记忆点。

### 7.3 炸弹形态：标准弹 + 六种特殊炸弹（ADR0041/0044/0047）

M2 特殊炸弹槽决定形态，槽空时为标准弹。所有形态共用 7.1 / 7.2 的传播规则，直击一律 −1 心；差别在**爆炸留下什么、何时引爆、火焰去哪**，每种剪影与爆炸形状都不同，不靠颜色区分（支柱 7 / 8）。下表是 M2 设计，**不表示 M1 已实装**。正式 `BombKind` 身份须在迁移 ledger 后冻结；[ADR0047](../../../.spec/decisions/0047-bomber-m2-six-bombs-and-fixed-skill-values.md)落实 ADR0044 的中毒保留，M2 为一槽六形态，不新增槽位或等级。

| 形态 | `BombKind` | 一句话 | 规则（推断待验证） | 一眼可辨 |
|---|---|---|---|---|
| 标准弹 | 0 | 十字，−1 心 | — | 橙火 |
| 火焰弹 | 2 | 爆完十字留火 | 火焰覆盖格留火 1.5 秒，按暴露时长伤害（§5.1 火地）；融化冰桥 | 火线在地上停留 |
| 冰冻弹 | 1 | 冻住被炸到的人 | 存活者冻结 2 秒（M2 无等级，ADR0047）（不能移动、放弹、放角色技；可被炸）；之后受伤立即解除并给 1 秒控制免疫；覆盖到的水格结冰桥 8 秒 | 白色冰晶、被冻者包在冰块里 |
| 遥控弹 | 7（原型扩值） | 自己决定何时引爆 | 持有期间自己放的炸弹不走引信，长按空格 ≥ 300 ms 一起引爆（并入同一连锁）；8 秒兜底自爆 | 天线 + 闪烁指示灯 |
| 集束弹 | 4 | 四个端点各再炸一次 | 爆炸后每臂末格各生一颗子弹，0.5 秒后以火力 1 十字引爆，同一连锁、归投弹者；子弹与母弹共用「同弹同人一次」、合计算宝箱 1 次命中；子弹不计炸弹数与帽数、不可踢 | 四朵小爆炸 |
| 穿透弹 | 3 | 火焰穿过积木一路烧到铁皮 | 遇积木 / 资源箱摧毁后继续传播；铁皮挡住，爆炸桶被引爆并挡住，水面覆盖后停 | 长箭头形火焰 |
| 中毒弹 | 保留原中毒身份，待 ledger 核验 | 命中后两次缓慢掉血 | 直击后存活者中毒4秒，第2/4秒各半心；当前生命已有中毒时只结算新直击，不叠加、不刷新、不改来源 | 带孔药瓶轮廓与中毒状态标记 |

**中毒弹保留并削弱**（ADR0044/0047）：M1旧三级共毒掉0.5/1/1心，仅作迁移数据。M2作为第六形态使用相同来源与换槽规则，直击−1心，随后固定两跳共−1心、可致死；原来源保留到结束。泡泡或血包解毒，满血但中毒也可吃血包；死亡清除且不传给后继生命。同Tick解毒在周期阶段前抑制，本Tick不再接纳新中毒；末跳/到期Tick的再命中只结算直击，原末跳后退场。每次重施加用独立Effect完整身份，已发行的旧结果照实消费但不能修改新实例。确定性边界表见ADR0047，实际生产接线和有界结果仍依[收敛计划](../../../games/101-bomber/.spec/plans/2026-09-28-prototype-convergence.md)验证。

**几何上全部形态都是十字**（ADR 0017）：差别在伤害语义、余烬、引爆时机与 `PierceLayers`；集束的子弹是 0.5 秒后独立的新十字。因此**不设形状枚举**。

**爆炸不建实体，由炸弹实体持有**（ADR 0017）：炸弹引信到点后不销毁，转入爆炸态——先是火焰阶段（`dangerWindowMs`，进入覆盖格即受伤，同弹对同人最多一次），火焰弹再接一段留火阶段，然后销毁。十字覆盖范围用**四臂实际到达格数**（上 / 下 / 左 / 右，传播算完后写入、已含地形阻断）描述；客户端据此直接绘制火焰，中途加入者也能看到进行中的爆炸。100 人满负载下同时存在的爆炸态炸弹约 12 个，取代原先每秒 100–300 个爆炸格实体。

### 7.4 掉落

积木被炸开后按所在圈的概率产生掉落物——外圈 **25%** / 中圈 **35%** / 核心 **45%**（ADR 0040；19×19 旧口径 30%），积木只掉**糖果与血包**（池内权重推断待验证）。资源箱按圈掉落（§5.0）：特殊炸弹只出自铁箱、金箱、补给与强力宝箱，金心只出自金箱、中央大补给与强力宝箱。狂暴糖只出自中央大补给（§8.6）。掉落物停留至被拾取，可被后续爆炸摧毁；**例外：死者掉出的强化、特殊炸弹与金心落地后 3 秒内不会被爆炸摧毁**（ADR 0029 / 0039 / 0041，推断待验证，A/B 2 / 5 秒），保护期内罩一层淡金色泡泡、最后 0.8 秒闪烁。负面拾取不进官方房（§8.5）。

**方块写入封顶**（引用：约束5，[`../risks-and-engine-asks.md`](../risks-and-engine-asks.md) A8）：单次爆炸最多摧毁24格（火力上限6×4向）；无等级穿透按剩余射程传播。100人每秒100–300格和同Tick约1200格只是Stage3的历史压测估算，不能覆盖当前新生产者。**连锁不设人为裁断上限**（ADR0016）；实际空间由完整生产者与寿命预算约束，同Tick闭包不能为削峰改成下一Tick。正式三档重新核算并按§17.2埋点。

### 7.5 连锁结算口径（逻辑瞬时、表现可解释）

ADR 0014 冻结：

- 同一颗炸弹对同一玩家最多命中一次；
- 同一 ChainId 对同一玩家的结算伤害不超过受害者当前心数上限（3–8 心，ADR 0039）；
- 服务器可在同一 Tick 完成权威结算，逐颗炸弹各出一条伤害事件（来源、主人、ChainId）；
- 客户端把多次受伤以极短节奏表现为「×N Chain」，不得看起来像单次爆炸莫名满血死亡；
- 死亡回顾列出每个伤害来源的炸弹、主人与 ChainId（ADR 0018 定来源归属；正式 v3 使用完整 `NetEntityId`，不得截成 Raw 单整数）；
- 冻结、燃烧等后续效果不得偷偷计入「看不见的第四次命中」。

**同弹命中记忆的实现口径**（[ADR 0046](../../../.spec/decisions/0046-bomber-bounded-rule-memory.md)，部分取代 0017）：权威去重记忆归炸弹组件，以 `Scope.None` / `Authority.Server` / `[Persist]` 进入引擎现有快照与 StateHash，不复制。键使用本局稳定 Participant 的完整身份；目标 Life/generation 与 pending/applied 分列，死亡重生不清旧炸弹记忆，旧结果不得改绑新生命。拒绝的 pending 可释放，成功的零伤害冻结接触也要去重；结果关联只能使用已批准的 GAS 接缝。连锁同时保存预留与实际伤害，上限取受害者当前 maxHealthPoints。

### 7.6 旧 19×19 首轮对象预算与规则记忆

本节是 2026-09-27 引擎首轮的**旧预算包络**，仅适用 19×19、固定 8 个 Participant 与当时已列出的生产来源（[ADR 0046](../../../.spec/decisions/0046-bomber-bounded-rule-memory.md)）。下列数字为推断待验证，不是实测并发，也**不能覆盖**新的 12/23、16/27、三级箱、补给、狂暴、集束子弹、爆炸桶与冰桥。正式准入前须对所有有效 overlay 和新增生产者、驻留寿命重新推导，使用引擎 Tick 换算和 checked 算术；不足、溢出或未知来源拒绝准入，不静默裁物。

P 为 Participant 数；A 为面积；Q 为每 Participant/Tick 接受和预留的放弹次数（旧默认 6，跨生命、退款和同 Tick 递归累计）；F/D/B 为引信/危险/已启用残留寿命；W 为火墙最长寿命；S 为创建预留、端点与退休的额外 cohort（旧暂定 2，尚缺生产证明）。当前业务相可见的炸弹均参加同 Tick 连锁，不附加下一 Tick 资格延迟。若真实 pending 或退休超过 S，须先证明有限上界再扩容。

| 对象 | 旧最低容量公式 | 旧默认推导值 |
|---|---|---:|
| 炸弹 | P × Q × (F + D + B + S) | 8×6×(42+8+0+2)=2496 |
| 掉落 | A + 4×O×(floor(max(0,M−C−L)/R)+1) + H×K | 361+8×31+5×5=634 |
| 火墙 | P × 每人每 Tick 最大墙施放数 × (W+S) | 8×1×(40+2)=336 |

M 为局时、C 为圈时长、L 为再生停止提前量、R 为再生间隔、O 为镜像组数，H 为旧强力宝箱发行数 5，K 为旧奖励数（技能开 5 / 关 4）。旧独立 profile 共用供给至少 2784/698/336；旧默认最低 2496/634/336。组合必须重新计算，不能把独立最大值当组合授权。初始地形只发行一次、掉率按最坏全部成功；死亡是财富转移而非新增发行。

主动放弹/火墙先预留，失败必须发生在库存、CD、保护与位移副作用之前；地形产出须在致因提交前预留，真实写格/解绑成功才发行。死亡掉落先进入 Participant 所有、不可花费的持久 pending，实际落地才转移所有权；无合法格时保留并重查当前地形。普通掉落不超时；容量耗尽不能删旧弹、缩火区、丢已接受伤害或财富。宝箱只记 RequiredHits 个不同完整 BombId，每弹另记有限 ChestId；失败清 pending 后保留饱和计数，须由后来新弹重试。事务 ID 保存 SDK 原始 string 并用 Ordinal 比较，配 MatchId、SubmittedTick 与具体操作/格子关联，不截短。

重叠光环/火墙对同一生命共用连续暴露时钟，覆盖不倍伤；所选来源仍覆盖就保持，失效才按开始 Tick、完整来源 Participant/实体、种类/技能稳定排序换源，换源不清进度。脉冲下单时快照来源及目标 Life；光环随施放生命终止，火墙持续到期。命中、接触、连锁、暴露归因、转移与预留都要有限容量、释放条件和真实快照证据。`Persist` 不承诺活动局存档重启，缺耦合规则记忆的恢复必须拒绝。

## 8. 角色、特殊炸弹与最爱炸弹（Stage 5 起，可选切片；网页原型已提前）

正式版以本节 M2 设计为目标，角色技和特殊炸弹仍由独立 Feature Flag 控制。**网页原型当前实现的是 M1**：五角色、三槽、等级、组合、中毒与麻痹仍在；M2一槽六形态、护城河/冰桥/爆炸桶尚未实装。ADR0047落实保留中毒和袋鼠最爱，ADR0044的非默认踢弹与其他试玩修订继续有效。正式迁移须同时改schema、生产者和预算，不能把策划定值或M1现状写成M2已完成；实施与证据见[正式收敛计划](../../../games/101-bomber/.spec/plans/2026-09-28-prototype-convergence.md)。

**术语**：**角色技** = 角色专属技能（主动用 Shift，或被动），开局自带、永不掉落；**特殊炸弹** = 地上可拾取、占唯一特殊炸弹槽的炸弹形态（§7.3）；**最爱炸弹** = 每个角色各有一种，捡到时角色技升级；**强化** = 火力+ / 炸弹+ / 速度+（§8.5），只有强化计帽数（§9）；**金心** = 心数上限 +1 的高级道具（§8.5，ADR 0039）。

**踢弹（ADR 0044 取代 ADR 0041 的「人人默认会踢」）**：踢弹不是默认能力。**飞腿袋鼠的专属主动技「飞踢」**——按 Shift 把面朝方向上相邻、或隔一格（中间是空地）的静止炸弹一脚踢出，一直滑到被挡住；面前没有可踢的炸弹则施放失败、不进冷却；冷却 4 秒；击杀仍归炸弹主人；只属于袋鼠、不进糖池。另有**被动踢弹糖，罕见掉落**（糖池里约 3%），捡到后走进静止的炸弹就能踢。两种踢法的滑行规则相同：8 格/秒滑行，在积木 / 铁皮 / 资源箱 / 爆炸桶 / 宝箱 / 其他炸弹前一格停下；**玩家不挡**（移动本就没有玩家碰撞）；引信照走（遥控弹不走引信）；滑进第一格水即熄灭、炸弹数返还（§5.2）；集束子弹不可踢。

**实现口径**：每个角色技 = GAS Ability（激活）+ Effect（时长 / 属性修正）+ Tag；无敌、冻结 = Tag + 时长；回春 = 周期性瞬时回血 Effect；特殊炸弹 = 一个爆炸形态参数 + 余烬 Effect；最爱炸弹 = 角色技上的条件 Effect。零新框架，角色表、特殊炸弹表、最爱表都是数据，兼作 L2 UGC 表达力的试金石。全部内容必须有 Bot 使用路径、服务器权威判定和表现预算。

被动踢弹糖的正式来源与转移引用ADR0048：积木、木/铁/金箱的每个随机糖果位以3/100替代为一份踢弹糖；不替换明确指定的强力宝箱/中央补给强化位，也不改变六特殊形态等权池或每次奖励数量。资格不叠加、不计帽，重复留地；死亡失去并一次掉出，保护3秒，落点不足保留持久pending；后继生命不继承。技能Flag关时不发行/施放。

| **火力+** | 爆炸范围 +1 格 | 6 | 0 |
| **炸弹+** | 可同时放置 +1 | 6 | 0 |
| **速度+** | 移速 +0.35 格/秒 | 6.0 格/秒 | 0 |
| **血包** | 回1心=2个半心点并解毒（§12）；满血未中毒不拾取，满血但中毒可消耗血包只解毒 | 当前心数上限 | 1 |
| **金心** | 心数上限 +1 心并回满这一心；不算帽子（ADR 0039） | 3 颗 | 原型已提前 |

糖果不占槽。**死亡时已吃的强化每级 50% 概率掉落**（火力+ / 炸弹+ / 速度+，推断待验证，A/B 30% / 100%；ADR 0025）：掉出的强化散落在死亡点周围可通行格，谁捡归谁（落地后 3 秒内炸不掉，§7.4），死者最低保留初始值；血包不是强化、不掉落；**金心死亡全掉**（ADR 0039），落地同享 3 秒防爆，玩偶身边环绕金心、HUD 金色心格。死者复活后因此变弱，击杀者与哄抢者因此变强——强化与帽子一样在玩家间流动（支柱 5）。

**狂暴糖（稀有；M1 网页原型已实现，ADR 0040 / 0044）**：只出自中央大补给（§8.6）。吃到即回满血并进入 **6 秒有界狂暴**：引爆时间缩为 1.2 秒；**同时在场的额外狂暴弹最多 6 颗，爆后可补**，相邻放置至少隔 5 Tick；免疫自己的狂暴弹、不免疫敌弹。狂暴弹不计普通炸弹库存与帽数；生产寿命和并发上限须进入新预算，不能把 6 当作一生只能放 6 次。外观全身红光 + 音乐加速，全场可见。

正式边界引用ADR0048：狂暴弹固定标准形态，不继承特殊槽；6秒到期停止新生产，在场弹继续保留期限和来源。自免绑定投出时的完整Life，到期仍自免，死亡后的新Life不继承。Participant并发账跨生命保留，死亡/换槽/到期不提前退款；已狂暴时重复糖不拾取、不续期。当前每局只有一份中央狂暴糖。

| 减益 | 效果 | 持续 | 落点 |
|---|---|---|---|
| **反向操作** | 移动方向反转 | 5 秒 | **自定义房 / 房主规则**，官方房关闭 |
| **失控放弹** | 强制持续放炸弹 | 5 秒 | 同上 |

官方默认房不掉负面拾取（ADR 0014）：在 100 人、三心、连锁与大量特效同时存在时，它们制造的是无法解释的死亡，并破坏玩家对输入的信任；核心模式证明好玩后再决定是否进入公开匹配。减益外观与糖果 / 技能糖**明确区分**（红色调 + 不同图标）。

**旧稿道具去向**（ADR0041经0044/0047修订）：踢弹由袋鼠主动技或罕见被动糖获得；冲刺 → 闪现；遥控引爆 → 遥控弹；分裂弹 → 集束弹；护盾由金心上限承担。**中毒弹为第六特殊形态**；麻痹弹等旧M1形态不进入M2。旧等级、组合和三槽只作M1迁移数据，不是M2生产规则。

> 帽子**不是技能**：帽子不加任何攻击数值、不占槽，只通过心数上限表达（§9.5）。特殊炸弹与金心也不是强化：不计帽数、不受强化上限。

### 8.6 补给：炸哪里才能变强

补给回答 100 人棋盘上「我该去哪」——它是固定地点的目标、特殊炸弹与金心的发行口之一、也是引导人群聚集的绞肉机。地形见 §5「补给点地形」。取代旧稿「有 HP 的据点宝箱」（ADR 0014）：固定 HP 在 8 人时要围攻、在 100 人中央聚集时瞬间被打空，无法同时落入 20–60 秒的争夺窗口。

| 项 | 小补给箱（每分区中心） | 中央大补给（棋盘中心围院） |
|---|---|---|
| 开启 | **3 次独立炸弹命中**后开启（同一爆炸链的多颗各算一次） | **不用 HP**：固定时刻**提前 10–15 秒预告**（全场横幅 + 光柱），到时自动落地并开启 |
| 次数 / 刷新 | 开启后 60–90 秒刷新 | 每局 1–2 次；最后一次落在决赛圈开始时（与决赛圈强力宝箱不叠加，§4.2） |
| 战利品 | 基础糖果 ×3 + 血包 ×1，散落箱旁 | 糖果 ×5 + 血包 ×2 + 狂暴糖 ×1 + 特殊炸弹 ×2 + 金心 ×1（ADR 0039 / 0040）；**公开喷发，谁捡归谁** |
| 广播 | 不广播 | 预告与开启全场横幅；光柱与帽王光柱以颜色 + 轮廓 + 图标 + 音型区分 |
| 人数缩放 | 数值不变（支柱 6），只有箱数随分区数缩放 | 全档位恒 1 个 |
| 阶段 | Stage 2 | Stage 3（定时补给）；网页原型 27 档已提前：0:50 预告、1:00 在核心中央 3×3 广场开启、每局 1 次（ADR 0040） |

（全部数值推断待验证）

- **不做最后一击归属**：战利品散落、开放哄抢——不需要伤害归属逻辑。
- **帽子随强化走**：补给只出糖果 / 血包 / 特殊炸弹 / 金心；帽子不是独立资源，吃到补给里的强化帽塔自然变高（ADR 0028）。
- **实现口径**：小补给箱 = 带命中计数的实体，爆炸触及施加 +1 命中 Effect；中央补给 = 定时器 + 落地事件 + 战利品散落，复用帽子散落路径；围院 = 地图生成器模板；光柱与横幅复用帽王光柱与全场事件通道。零新框架。

## 9. 帽子系统（核心）：帽子 = 强化数的表现

ADR 0028（取代 0027，并取代 0011 / 0014 / 0025 里「帽子是独立计分资源」的全部条款）：**不再有独立的帽子资源。帽子只是表现——头顶叠几顶帽子，就表示这个人身上有几个强化。**

### 9.1 帽数怎么来

| 项 | 规则 |
|---|---|
| 帽数定义 | **帽数 = 当前强化级数之和** = (火力 − 初始火力) + (炸弹数 − 初始炸弹数) + 速度级数（(移速 − 初始移速) / 每级增量，向上取整）；纯派生值，不单独存、不单独结算。血包不是强化、不计入 |
| 增加 | 吃一个强化（积木 / 资源箱掉落、死者掉出、补给与决赛圈宝箱喷出）帽数 +1；强化已达上限不能拾取，帽数也不变 |
| 减少 | 常规阶段死亡：强化每级 50% 掉落（§8.5），帽数同步减少；决赛圈死亡（出局）：强化**全部**掉落，帽数归零 |
| 击杀 | 不再单独铸帽；击杀的收益 = 死者掉在地上的强化，谁捡归谁（捡到即 +1 帽） |
| 上限 | 由强化上限决定（§10：火力 6、炸弹 6、移速 6.0）：首轮默认最多 4 + 5 + 8 = 17 顶（推断待验证） |
| 心数 | **帽子越多心越多**：每 4 顶帽子心数上限 +1，最多 +2（ADR 0039）；另有金心最多 +3，封顶 8 心（§12） |

地上不再有「帽堆」（HatPile）：流动的是强化道具本身，帽子只跟着强化数变。

### 9.2 堆叠表示

帽子在头顶**物理堆叠**，但**最多画 4 顶**、自下而上逐层缩小（ADR 0037）：帽数 ≤ 4 时有几顶画几顶；帽数 > 4 时塔顶上方显示「×N」金色徽章（N = 真实帽数），帽王皇冠戴在封顶后的塔顶，避免遮挡角色与战场；领奖台同一规则。吃强化时一顶帽子落到头顶（目标层 = min(帽数, 4)）；掉强化时帽子从头顶飞向掉出的强化。

### 9.3 帽王可见性

- **屏幕内帽塔 = 局部实力榜**（支柱 1）：强化最多的人塔最高、最显眼。
- **Top-10 侧栏**（PC）/ **Top-5 + 本人**（触屏）：名字 + 帽数（= 强化数）；决赛圈起按 §4 排名口径排序（存活者在前、出局者灰显）。
- **帽王 = 帽数最多且 ≥ 1 的玩家**（并列保留现任）；第一名且 ≥ N 顶（N 待验证）时头顶竖起光柱，全图可见其方向；玩具世界口径「聚光灯」，表现归美术。
- **屏幕边缘帽王方向箭头**：首发必做（ADR 0014，原候选升级）。
- 大补给光柱与帽王光柱必须以颜色 + 轮廓 + 图标 + 音型区分（不只靠颜色）。

### 9.4 死亡结算

血量归零即死（§12）；常规阶段死亡代价 = 强化每级 50% 落地（帽塔同步变矮）+ 特殊炸弹 50% 落地 + 金心全部落地（角色技不掉，§8.2），3 秒后复活；**决赛圈内死亡 = 出局**：强化、特殊炸弹与金心全部落地（帽数归零）、不再复活，观战到结算（§4.2）。

### 9.5 帽子明确不做的

- **帽子不加攻击数值，只加心**：它是强化数的读数；强化的数值效果照常（火力、炸弹数、移速），帽子另外只通过心数上限表达（每 4 顶 +1 心、最多 +2；ADR 0039 修订原「帽子本身没有数值」）；
- **不随特殊炸弹与金心增加**：角色技、特殊炸弹与金心都不计帽数（ADR 0039 / 0041）；只数火力 / 炸弹 / 速度三种强化；
- **无种类差异**：首发只有一种帽子；帽子外观 / 皮肤 / 收藏属账号级持久化，被引擎前置（[`../risks-and-engine-asks.md`](../risks-and-engine-asks.md) A5）阻塞，记远期不进首发。

**风险（进 §15）**：分数即实力——领先者同时最强，滚雪球风险高于「帽子无数值」的旧模型；制衡靠强化上限、死亡掉一半、决赛圈与全场围攻帽王。帽子给心（ADR 0039）让领先者同时更耐打，风险进一步上升；另靠心数封顶 8、毒圈按上限等比与「击倒 Boss」全场播报制衡。后期多人顶到上限会并列，并列按 §4 平局规则排序。

### 9.6 可读性与死亡可解释（正式功能，不是美术收尾）

首发必含（ADR 0014；Stage 1 起接表现，逻辑层先保证事件与数据存在）：

- 屏幕边缘帽王方向箭头；Top-10（PC）/ Top-5 + 本人（触屏）；
- 本人准备放置的炸弹显示预计十字范围；**不给场上每颗炸弹全程绘制范围**（100 人时是视觉网格噪声）；
- 所有炸弹最后约 0.4 秒有清晰危险脉冲；
- 伤害来源与连锁归属实时提示；
- **帽子与强化的流向可见**（ADR 0025 / 0028）：吃强化时一顶帽子落到头顶、显示「+1」；死亡时帽子从头顶飞向掉出的强化，掉出的强化带死者颜色的光圈；开局倒数期间显示一句话规则（§1）；
- **死亡回顾**：击杀者、炸弹类型、连锁长度、最后两个伤害来源；
- **技能可读**（ADR 0030 / 0041）：本人角色技（含冷却）与特殊炸弹两格常驻 HUD（角色技标 Shift，最爱炸弹金边）；每种特殊炸弹剪影独有、不与强化糖共用图标，捡到时显示名字 + 一句话；他人的特殊炸弹从其放下的炸弹外观读出，不给他人冷却条；火焰格、留火、泡泡与冻结必须画出来，技能致死的死亡回顾写明施放者与技能名；**Boss（心数上限 ≥ 6）头顶常驻心条**（ADR 0039）；
- 帽王、大补给、危险爆炸与血量变化同时使用轮廓、图标、文字、音效或震动，**关键目标不只靠颜色**；
- 屏幕震动、动态模糊与全屏效果可降到 0；高频闪光通过光敏检查；
- 定帧只作用于本人客户端，不暂停服务器或其他玩家模拟。

## 10. 数值框架

| 参数 | 初始 | 每级 | 上限 |
|---|---|---|---|
| 移速 | 3.5 格/秒（A/B 3.3 / 3.5 / 3.8） | +0.35 | 6.0 |
| 火力 | 2 格（A/B 1） | +1 | 6 |
| 炸弹数 | 1 | +1 | 6 |
| 心数上限 | 3 心 | 帽子每 4 顶 +1 心（最多 +2）；金心每颗 +1 心（最多 +3） | 8 心（ADR 0039） |

（全部推断待验证；五个角色的初始值完全相同，ADR 0030/0044）

**上限存在的意义**：防止滚雪球。前期领先的玩家如果无上限成长，后半局会变成单方面屠杀，破坏多人局的乐趣。

**成长节奏**：预期玩家在 60 秒内拿到 3–4 个糖果进入"火力 4 / 炸弹 3"的舒适区（推断待验证）。死亡掉一半强化（§8.5），所以全场不会一边倒地趋于满配——连续存活的人更强，被击杀的人变弱、击杀者可以把他的强化捡走（推断待验证：死亡掉落率与「复活变弱」的挫败感见 §15）。

### 10.1 中途加入补偿：只补战力，不补分数

局中后段的老玩家接近上限（死亡只掉一半强化），新加入者裸装进场与「中途加入是一等公民」冲突。ADR 0014 定：

- 不获得帽子、特殊炸弹或金心（角色技照常自带）；
- 每经过完整 **120 秒**补 1 个随机基础升级，**最多 2 个**，优先补当前最低的火力 / 炸弹数 / 速度；
- 仍需通过游玩获得后续成长。

（数值推断待验证；Stage 1 起。）

## 11. 会话与房间

**滚动房间模型**：房间常驻，一局接一局连轴转；玩家随时进、随时走，服务器可同时开多个房间。

```
快速加入 / 房间码 → 进入房间（任意时刻）→ 选角（单屏，默认上次）
   → 局中：立即入场（决赛圈期间改为观战等下一局）
   → 局终（只剩 1 人，或 4 分钟封顶）→ 领奖台 + 结算表约 16 秒 → 自动下一局（房间保持，按人数重选地图档位；结算页可换角色）→ ……
```

**双入口**：

| 入口 | 定位 | 依赖 |
|---|---|---|
| **快速加入** | 默认入口：把玩家丢进一个未满的官方参数房间 | 引擎侧「房间目录 + 快速加入」轻量能力——**已登记为 ① 的入口依赖**（[`../risks-and-engine-asks.md`](../risks-and-engine-asks.md) A6）；Stage 4 需要；不是技能 / 段位匹配 |
| **房间码** | 保底入口 + 好友开黑 + 自建服 / 自定义规则房 | 无，首发可用 |

**快速加入只进官方默认参数的房间**；房主改过规则的房间走房间码或房间列表——避免新玩家被丢进认不出的规则变体（推断待验证）。

**局末锁入 = 决赛圈**：决赛圈期间（≤ 115 秒，§4.2）不再放新人入局——进场即出局或进场即结算都没有意义；锁入期玩家观战等下一局。

### 11.1 房间填充策略（Stage 4）

地图只在局开始时选档、局中不变；滚动房的密度由**房间目录**控制，不在局中重建地图（ADR 0014）：

- 快速加入优先填充已有官方房，达到目标占用带后再开新房；
- 每档设置「目标人数区间」与滞回，避免频繁开关房；
- 低人口房在结算阶段提示并合并到另一个房间；
- 下一局按预计留存人数与排队人数重新选地图档；
- 局中地图不缩放、不瞬移玩家；最多容忍一局（≤ 4 分钟）的临时密度偏差；
- 自定义房不自动合并。

（目标区间与滞回值推断待验证。）

**房主可调规则（L0 UGC，首发即开放）**：
- 局时、房间人数上限、地图档位锁定与分区开关
- 软砖密度、再生速率
- 掉落率、糖果 / 血包 / 减益的池内权重（减益只在自定义房可开）、各圈资源箱内容与掉率、特殊炸弹池各种开关与权重、最爱炸弹开关
- 特殊炸弹掉落率、死亡掉强化比例、金心掉落比例、重生秒数
- 角色开关（关掉角色技 = 角色只剩外观）、决赛圈段表与毒速
- 补给箱开关、命中次数与刷新周期、中央补给次数与时刻、狂暴糖开关
- 心数上限公式（帽子给心、金心上限）、血包权重、留火时长、护城河开关
- 初始火力 / 炸弹数 / 移速

这是 UGC 阶梯的第一级，几乎零成本，但能立刻让服主有事可做。复杂房主规则编辑 UI 首发不做，首发以配置文件形态开放。

## 12. 血量、死亡、重生与观战

**血量**（定调依据 ADR 0012，由 0014 重申，单位与粒度由 ADR 0017 修订，心数上限由 ADR 0039 修订；全部数值推断待验证）：

| 项 | 规则 |
|---|---|
| 血量单位 | 权威单位是**半心点**（ADR 0017）：`healthPointsPerHeart = 2`；基础 `maxHealthPoints = 6` 点即 **3 颗心**（整数，引用 config IntegerOnly 纪律）；重生满血 |
| 心数上限 | **每人一个上限** = 6 + 2·min(2, ⌊帽数 / 4⌋) + 2·min(3, 金心数) 点，即 3–8 心（ADR 0039）；跨阈值时新心是满的；帽子与金心只在死亡时减少，存活期间上限只升不降 |
| 爆炸伤害 | 每颗炸弹的爆炸触及 −1 心（−2 点），与火力无关；同一爆炸链每颗炸弹各算一次，同一颗炸弹对同一人只算一次，同链对同人不超过其当前上限——**单发削血，连锁秒杀**（结算口径 §7.5） |

- **重生**：常规阶段 **3 秒**（A/B 3 / 4 秒）后在动态出生点满血复活（§5）；决赛圈内不复活（§4.2）；带 **3 秒重生保护**（无敌 + 闪烁，**放弹即解除**——ADR 0017 把保护从 1.5 秒抬到 3 秒，而「放弹即解除」必须保留：否则三秒无敌会被用来冲进人堆放弹；施放火焰光环同样解除，ADR 0030）。
- **观战**：常规阶段没有死亡观战等待（支柱 3）；观战只存在于决赛圈出局后、决赛圈锁入期与结算间歇，最长约 115 秒 + 结算。

## 13. 结算与留存

结算分两段（共约 16 秒，推断待验证；原「12–15 秒」按用户 2026-09-25 要求加入领奖台后延长）：

1. **领奖台（约 10 秒，必做）**——成就感的来源，不能只是一张表：
   - 3D（或 2D 带角色模型）的领奖台，积木搭成，第 1 / 2 / 3 名分站中 / 左 / 右三级台阶，台面标名次数字与颜色（金 / 蓝 / 橙），**不只靠颜色**。
   - 前三名玩偶**戴着本局最终的帽子塔**站上去：第 1 名跳跃欢呼 + 皇冠 + 聚光灯 + 彩纸，第 2 名挥手，第 3 名拍手；其余玩家排在台下鼓掌，决赛圈出局者垂头。
   - 每级台阶上方显示名次、名字、帽数；本人上台时显示「你拿到了第 N 名！」，未上台时显示本人名次。
   - 镜头从全景缓推到台前（本段允许镜头运动，常规对局的「不给玩家旋转」不适用）。
   - 排名按 §4（ADR 0031）：存活者在前（时间到按帽数降序），出局者在后（出局越晚越前），并列同名次。台上站前三行、台阶标真实名次（并列时出现两个「1」，都戴皇冠）；同名次按玩家 id 排版。第 1 名 = 唯一存活者，或时间到时存活者中帽数最多者。
2. **高光卡 + 结算表（约 6 秒）**：
   - **本人高光卡**（ADR 0043，支柱 9）：每人一张本局最亮眼的一项，按各人相对全场最突出的一项分配、尽量不重复；候选：最长连锁、最多击杀、帽王最久、拆迁王、Boss 猎人、绝境逃生（1 心活下来）、金心收藏家、搬运工（拾取最多）；覆盖率 100%，不影响名次
   - **Top-10 榜**、本人名次与「击败了 X% 的玩家」、**帽王时长**（本局持有最高塔的累计时间）
   - 击杀数、放弹数、破坏方块数、拾取数、最佳连锁、最高帽数、最高心数、角色、本局特殊炸弹与是否拿到最爱、结束方式（唯一存活 / 同 Tick 全灭 / 时间到）
   - **个人最佳**（ADR 0043）：本机记住最佳连锁、最多击杀、最好名次、帽王最久，刷新时显示「新纪录！」；读写失败时照常显示（约束 7：无账号持久化，正式版需账号级存储，见 [`../risks-and-engine-asks.md`](../risks-and-engine-asks.md) A5）
   - **留局 / 下一局按钮**（倒计时结束自动下一局）与「换角色」（依 §8.0 的 Warmup 提交边界生效；个人停留选角页不暂停房间）
   - 连胜提示

**首次游玩提示**只有三条，完成动作后永久消失，不做独立长教程：「放炸弹，炸开积木」「捡糖，帽子越高心越多」「往中间走，宝箱更好」。选角界面每个角色一句话技能说明（§8.0），不计入三条提示。

**首发不做账号进度系统**（等级、皮肤解锁、赛季）。留存靠局内爽感和房间社交，不靠养成。**玩家可见的完整比赛回放首发不做**（ADR 0014）；引擎侧命令录制、State Hash 与故障复现回放保留为 QA / 可靠性能力，不等于产品功能。赛后回放作为差异化能力（[`../product-direction.md`](../product-direction.md) §4）进后续路线图。帽子皮肤 / 角色与技能外观类养成另被 A5 阻塞（见 §9.5）。

## 14. 平衡原则

1. **不许滚雪球**——糖果有上限（§10）；帽子只通过心数上限表达，且心数封顶 8、毒圈按上限等比（§9.5 / §12，ADR 0039）
2. **重生绝对公平**——棋盘四象限对称，动态出生点远离威胁
3. **运气可以有，但不能决定胜负**——掉落与特殊炸弹是随机的，但强化、特殊炸弹与金心都能靠杀和抢易手；资源箱按圈固定、可预期（§5.0）：财富分配由冲突决定，不由掉落决定
4. **死得快不如死得明白**——每次死亡玩家都要能立刻看出"我被什么炸死的"，爆炸范围与留火必须画在地面上，死亡回顾必须列出来源（§7.5 / §9.6）；每次掉心同理（支柱 8：威胁全可见）
5. **特殊炸弹与金心是流动的不是终身的**——死亡时按 §8.2 / §8.5 落地易主；否掉绑定 / 不可掉落的特殊炸弹；唯一例外是角色技（身份不是财富，不计帽数，ADR 0030 / 0041）
6. **同一套规则从 8 人到 100 人**——数值不随人数改变，只有地图随人数缩放
7. **爆点可以有，但必须有时限、可反制、来源可争夺**——狂暴糖 6 秒有界、不免疫他人、只出自中央补给；否掉常驻或不可反制的强化
8. **表现可以像无限，实现必须有界**——活跃炸弹、掉落物、表现对象都有配置上限；任何「无限」都有服务端预算
9. **排名只有一个公式**——先看有没有活到最后，再看帽数（§4，ADR 0031）；不加双倍分、不扣落后者分，任何阶段都不引入第二计分公式（ADR 0025）
10. **角色只换打法不换基础数值**——五个角色基础属性完全相同，差异在角色技与M2最爱炸弹。否掉角色专属基础加成、角色解锁与付费角色（ADR0030/0044/0047）
11. **概念有预算**——新人要懂的概念 ≤ 6 个（支柱 7）；加一个系统要先说清它落进哪个已有概念，或替换哪一个（ADR 0038）

**M1原型事实与M2设计边界**（ADR0024/0030/0040–0044/0047）：当前网页原型已含三级资源箱、中央补给、狂暴、五角色/飞踢、旧三槽/等级/组合、中毒与麻痹、菜鸟Bot和高光表现；页面默认12人·23×23。护城河、冰桥、爆炸桶、一槽六形态与无等级组合属于M2设计，尚不能写成原型已实现。M1旧等级/槽位只作正式迁移数据，不能反向冻结M2。正式A–D浏览器只读旁观，真实C#客户端/Bot负责输入。

**首发明确不做**（ADR 0014 / 0030 / 0038 / 0041 / 0042）：账号等级 / 赛季 / 签到 / 数值养成；元素 × 功能组合、技能等级与合成、多技能槽与站立替换；草丛与任何隐身；溺水；筑墙、穿墙；官方房负面拾取；复杂房主规则编辑 UI；团队模式；玩家可见的完整比赛回放；帽子皮肤商城；角色解锁 / 付费角色 / 角色基础属性差异；100 真人公开上线前未经 8/24/48 真人测试；为「体素特色」增加大量会写方块的技能。

**总验收**：拉一个不认识这个项目的人中途进房——能否 **30 秒内看懂「谁在赢、我该干嘛」**，并且**自愿留满 3 局以上**？满房 100 人时这条判据仍须成立。

## 17. 遥测与门槛

逻辑层从 Stage 0a 起就产出遥测（ADR 0013：数据优先）；事件定义归本仓玩法层，Sink 归宿主。

事件至少携带：`matchId`、`playerId`、`tick`、`elapsedMs`、`zoneId`、`hatCount`、`health`（半心点）、`bombPower`、`bombCapacity`、`movementSpeedTier`、`joinElapsedMs`、`characterId`、`skill`（角色技）、`specialBomb`、`maxHealth`（半心点）、`goldHearts`、`ring`（外圈 / 中圈 / 核心）、`killer / source / chainId`（适用时）；`match_end` 另带 `endReason`（sole_survivor / all_down / time_cap）、`survivorCount`、`rank`。

**强化经济指标**（帽子 = 强化数，ADR 0028；改规则前必看）：每分钟发行量（砖 / 箱 / 宝箱）、玩家持有总量、地面总量、一次死亡平均掉落量、被击杀者掉落被敌人捡走的比例、帽王持有比例、顶到上限的人数、每局帽王更替次数。

**特殊炸弹、Boss 与决胜指标**（ADR 0031 / 0039 / 0041 / 0043）：每局特殊炸弹发行（铁箱 / 金箱 / 补给 / 宝箱 / 死亡，按种分列）、更换次数、最爱炸弹拿到率、各特殊炸弹与角色技的使用与致死占比、冰桥与爆炸桶次数；Boss 出现、持续与被击倒比例，金心发行与易手；各角色选择率与胜率；结束方式占比、时间到时存活人数、平均局长、毒死占比、1×1 可进入断言；高光卡覆盖率。

### 17.2 性能指标（必埋）

Tick P50 / P95 / P99 与 Overrun；每秒放弹、引爆与最大活跃炸弹；连锁宽度、深度与单链体素写入；每秒体素批量修改数；权威拾取对象数；每连接 AOI 实体数与复制字节；Snapshot / Delta 比例、Resync 次数；客户端可见特效、粒子、音源与 Draw Call；服务器与客户端内存趋势。

### 17.3 首轮门槛（内部决策线，不是行业基准）

| 维度 | 首轮门槛 |
|---|---|
| 目标理解 | ≥ 80% 新玩家 30 秒内正确说出胜负目标 |
| 首次行动 | 首次放弹中位数 ≤ 10 秒 |
| 进入循环 | 首次拾取 ≤ 15 秒，首次受伤 ≤ 25 秒，首次击杀 ≤ 45 秒 |
| 帽王戏剧 | 每局（≤ 4 分钟）帽王更替 3–6 次；至少一次 10+ 帽倒台 |
| 决胜 | ≥ 85% 局以唯一存活者结束；时间到结束的局存活人数中位 ≤ 2；平均局长 ≤ 4 分钟 |
| 角色平衡 | 五角色胜率与 20% 基线的偏差 ≤ 10 个百分点，分 Bot / 真人统计 |
| 留局 | 首次测试 ≥ 60% 玩家自愿留满 3 局，后续按样本扩大复核 |
| 死亡可解释 | ≥ 90% 玩家能从现场或回顾判断主要死因 |
| 新人理解 | ≥ 80% 新人 30 秒内复述「怎么赢、怎么变强」（ADR 0038） |
| 人人有高光 | 高光卡覆盖率 100%（ADR 0043） |
| 新人保护 | 中途加入后 5 秒受伤率 < 10%，20 秒内完成一次有效行动 |
| 稳定性 | 100 Bot 30 分钟无崩溃、无状态发散；6 小时无持续内存增长 |
| Tick | P99 ≤ Tick 周期 80%，Overrun < 0.1% |
| 无障碍 | 关键目标不只靠颜色；震动 / 抖动可为 0；通过光敏检查 |

「留满三局」不达标时，不先加账号成长与签到奖励掩盖问题；先判断核心循环是否真的提供了第二局理由。**用户测试从灰盒阶段开始**，由真实目标玩家测试，观察行为、不在现场替玩家解释；问题按影响排序并附录像证据。
