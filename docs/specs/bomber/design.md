# 体素炸弹人 · 设计稿

> **状态**：设计中
> **序位**：Lumio 首发产品（阶梯 ①）
> **上游**：[`../product-direction.md`](../product-direction.md)、[`../worldview.md`](../worldview.md)、[`../art-style-pitch.md`](../art-style-pitch.md)；定调依据 ADR [`0013`](../../../.spec/decisions/0013-logic-first-browser-client-no-engine.md)（交付顺序与客户端载体）、[`0014`](../../../.spec/decisions/0014-bomber-v04-stage0-convergence.md)（v0.4 收敛，取代 [`0012`](../../../.spec/decisions/0012-bomber-hearts-replace-one-hit-kill.md) 并重申 [`0011`](../../../.spec/decisions/0011-bomber-100-player-io-gear-slots.md) 其余条款）

## 1. 使命

**这份设计稿要回答四个问题：「这套破坏玩法到底好不好玩、帽子塔能不能自发制造出『围攻帽王』的社交戏剧、100 人在同一张棋盘上跑不跑得动、这个画面组合到底好不好看」。**

回答顺序按 ADR 0013 固定：**先证明跑得动、跑得对、可重放（headless 逻辑层），再证明好玩（浏览器客户端接上后），画面最后。** 任何「以后可能有用」的系统一律不进首发；首发内容按 §16 切片实现，每阶段以量化门通过。

产品记忆点一句话：**连锁爆炸制造爽感，帽子塔公开展示财富，帽王倒台制造全场哄抢。** 值得做成产品的不是「体素 + 炸弹人 + 很多技能」，而是**百人帽王乱斗：体素是可破坏舞台，炸弹是冲突工具，帽子是唯一胜负语言。**

一句话规则（30 秒讲清的版本，不讲装备、材质与补给，玩家理解核心后再通过场上物体学习附加规则）：**「炸开积木拿糖，炸人铸帽，抢走他掉下来的帽子；头顶帽子最多的人会被全场追踪，六分钟后帽子最多者赢。每人三颗心，死后三秒复活。」**

## 2. 核心循环

```
        发育：炸软砖 / 开补给箱 → 掉糖果 / 血包 /（Stage 5 起）装备箱 → 变强（合成升级 / 替换）
          ↑                                    ↓
   重生（3 秒） ← 被炸死·帽子全散·装备半掉 ← 炸掉对手·铸 1 顶帽·捡他的帽子和装备
          ↑                                    ↓
          └── 帽子垒高 → 帽王亮起光柱 → 被分区乃至全场围攻 ──┘

   会话：局计时结束 → 结算（12–15 秒，Top-10）→ 自动下一局（房间连轴转，随时进出）
```

帽子经济两条通道：**击杀 = 铸造**（每次击杀凭空发 1 顶到击杀者头顶）、**击杀 = 转移**（死者帽子散落可拾）。装备经济也是两条：**装备箱 = 发行**、**死亡掉落 = 转移**。谁都能看见谁最富——帽子塔就长在头顶上，帽王头顶还有光柱。

## 3. 产品支柱

六条可证伪的支柱，用来否掉未来的具体提案：

| # | 支柱 | 这意味着 | 这不意味着 |
|---|---|---|---|
| 1 | **帽子塔是局部计分板，Top-10 是全局摘要** | 屏幕内谁最富一眼可见；全局只给 Top-10 侧栏、帽王光柱与屏幕边缘方向箭头；否掉把主计分藏进 UI 面板、否掉全员帽数小地图 | 没有任何 UI（计时、Top-10、结算仍有） |
| 2 | **领先自带风险，制衡靠玩家不靠数值** | 帽王更显眼、更被觊觎，围攻是自发行为；否掉「帽子多移速慢」类数值惩罚，也否掉给帽王的数值奖励 | 系统不为帽王的可见性做任何事（光柱与箭头正是为可见性做的） |
| 3 | **死亡是节奏不是惩罚** | 死亡代价只有两项：帽子全散、每件装备 50% 落地；否掉长重生 CD、死亡扣分、死亡清糖果、出局观战 | 死亡无代价（帽子和装备就是代价） |
| 4 | **随时能进，进来就懂** | 中途加入是一等公民，新系统不得提高进场理解成本；拾取默认走过即生效，**只有会丢掉已有装备的替换需要一次确认**（ADR 0014）；否掉第二计分资源、开局仪式流程、菜单式拾取 | 玩法没有深度（装备搭配与地形博弈仍在） |
| 5 | **一局是一场围绕帽王的戏剧** | 发行→积累→帽王→围攻→崩塌哄抢→新王，在分区内多次轮回，光柱把分区戏剧升级为全场戏剧；否掉让帽子或装备流转停滞的设计（如绑定不掉落） | 固定剧本或强制平均分配戏份 |
| 6 | **同一套规则从 8 人到 100 人** | 数值不随人数变，只有地图档位随人数缩放；否掉只在大人数下才成立的机制（如 ≥50 人才触发的事件） | 8 人房与 100 人房体验完全一样（密度与戏剧规模自然不同） |

### 3.1 爽感时刻

玩法必须稳定交付的「爽」，每条挂钩支柱并标成本类别：**表现层** = 客户端本地表现（零服务器成本、不复制）；**服务器事件** = 一条广播事件；**内容** = GAS 数据或美术资产。表现层全部在 Stage 1 起接入（ADR 0013：逻辑先行），逻辑层只保证事件与数据存在。

| 时刻 | 触发 | 表现 | 支柱 | 成本 |
|---|---|---|---|---|
| 连锁 | 同一爆炸链 ≥ 3 颗 | 「×N 连锁」弹字、屏幕震动随 N 增强、50–80ms 本人定帧（不暂停服务器与他人）；连锁秒杀见 §7.5 | 5 | 表现层 |
| 多杀 | 同一爆炸链击杀 ≥ 2 | 「双杀 / 三杀 / 一锅端（≥4）」弹字 + 音效 | 5 | 服务器事件 + 表现层 |
| 收割 | 一次连续捡起 ≥ 5 顶帽 | 帽塔快速叠高动画、连拾音效音高递增 | 1 / 5 | 表现层 |
| 合成 | 同技能合成升级（Stage 5） | 装备闪光；**每个 Lv3 必须有一眼可见的形态变化** | 4 | 内容 |
| 加冕 | 成为帽王 | 光柱亮起 + 「你是帽王」横幅 + 音乐层 | 1 / 2 | 服务器事件 + 表现层 |
| 倒台 | 帽王死亡 | 全场横幅「X 的 N 顶帽子散落了！」→ 踩踏式哄抢 | 5 | 服务器事件 |
| 补给 | 中央大补给落地开启 | 提前预告 + 落地喷泉式散落 + 全场横幅 | 4 / 5 | 服务器事件 + 表现层 |
| 狂暴 | 吃到狂暴糖（正式 MVP 起） | 全身红光 + 加速音乐 + 6 秒**有界**狂暴（§8.5） | 5 | 内容 |
| 逆袭 | 0 帽玩家击杀帽王后成为帽王 | 「逆袭！」横幅 | 2 / 5 | 表现层 |
| 拆迁 | 单次爆炸链破坏 ≥ 12 格 | 碎块飞溅加强 + 「拆迁 ×N」弹字 | — | 表现层 |
| 绝境 | 1 心逃生后捡到血包 | 心跳音停止 + 回血音效 + 玩偶缝合动画 | 3 | 表现层 |

全场横幅只播大事件（加冕、倒台、大补给预告 / 开启），其余弹字只对本人显示——100 人下横幅刷屏会毁掉可读性（推断待验证）。

## 4. 局制规格

| 项 | 规格 |
|---|---|
| 人数 | **8–100 人弹性**，随中途进出浮动；官方默认房上限 **100**（引用：架构 v1.4 §12「100 人是第一阶段目标负载」；Stage 3 性能门实测后不达标则以实测稳定人数为临时上限，不强行承诺 100） |
| 模式 | 首发只做**帽子乱斗（FFA 计分）**；团队帽子赛作为第二模式候选（兼作模式数据格式的试金石，见 [`../ugc-ladder.md`](../ugc-ladder.md) §0） |
| 局时 | **6 分钟**滚动局（推断待验证；A/B 5 / 6 / 8 分钟） |
| 胜负 | 计时结束，**头顶帽子最多者胜**，Top-10 上榜 |
| 平局 | 帽数并列即并列同胜，不加赛 |
| 中途进出 | 任意时刻可加入（局末锁入期除外，见 §11）；中途退出者帽子与装备当场散落回流；中途加入者只补战力不补分数（§10.1） |

### 4.1 六分钟节奏与终局

| 时间 | 目标节奏 |
|---|---|
| 0:00–1:00 | 破墙、拿糖、形成第一次交战与第一个帽王 |
| 1:00–3:00 | 分区内反复争夺，帽王首次倒台 |
| 3:00–5:00 | 中央补给制造跨区迁移；装备版从此段起出现技能 |
| 5:00–6:00 | **终局**：所有分区通道常开、停止软砖再生、帽王光柱与音乐增强、中央最终补给落地 |
| 6:00–6:12 | 结算：Top、本人、帽王时长、最佳连锁、最高帽数 |
| 6:12–6:15 | 自动准备下一局，可退出或继续 |

终局**只是演出，不改计分公式**：不加双倍分、不扣落后者分、不用致死收缩圈（ADR 0014）。时刻表全部推断待验证。

## 5. 地图规格：人数-地图联动

密度用**两个指标**分开定义（ADR 0014；数值推断待验证）：

| 指标 | 含义 | 目标 |
|---|---|---|
| `potential_walkable_cells_per_player` | 软砖炸光后的潜在可通行格 / 人 | 26–30 |
| `initial_open_cells_per_player` | 开局立即可走的格 / 人 | ≥ 9 |

生成器不只追静态密度，优先追体验指标（Bot 对局与真人对局实测）：首次拾取中位数 ≤ 10 秒、首次见到其他玩家中位数 ≤ 15 秒、首次受伤中位数 ≤ 25 秒、出生后 3 秒内不会被不可反应地夹死、软砖全清后全图连通。

局开始时按在场人数（加预期加入量）选档，局中不变；房主可用 L0 规则锁定档位。

| 在场人数 | 棋盘 | 分区 | 每区约人数 | 进入阶段 |
|---|---|---|---|---|
| ≤12 | 19×19 | 无 | ≤12 | Stage 0 |
| 13–30 | 31×31 | 2×2 | 3–8 | Stage 2 |
| 31–60 | 45×45 | 3×3 | 3–7 | Stage 2 |
| 61–100 | 61×61 | 4×4 | 4–6 | Stage 3 |

（档位与尺寸均为推断待验证）

三类格子：

| 类型 | 说明 | 分布 |
|---|---|---|
| **硬砖** | 不可破坏 | 固定阵列：行列均为偶数索引的交叉点；另构成分区墙 |
| **软砖** | 可被炸掉，可能掉糖果 / 血包 /（Stage 5 起）装备箱 | 随机填充剩余空格的 **65%**（推断待验证） |
| **空地** | 可通行 | 其余 |
| **补给点** | 分区小补给箱与中央大补给落点（§8.6） | 每分区中心 1 个小补给箱、棋盘中心 1 个大补给落点 |

**分区墙**：硬砖墙把棋盘切成分区，每段墙中点留 **3 格缺口**（推断待验证）。分区是「经典密度的小竞技场」——100 人的遭遇仍是 4–8 人规模，帽王戏剧先在分区内轮回。终局通道常开（§4.1）。

**补给点地形**（规则见 §8.6）：小补给箱立在分区中心一格，四周不设围院；中央大补给落在棋盘中心 **5×5 硬砖围院**内，四边中点四个入口，院内无软砖、地面硬砖。围院是故意的死亡陷阱：硬墙不吸收爆炸、入口是卡点，院内哄抢就是支柱 5 的「崩塌哄抢」；院内没有软砖，人群最密处不产生方块写入（引用：[`../risks-and-engine-asks.md`](../risks-and-engine-asks.md) A8）。≤12 人档（19×19）无分区，只有中央落点（推断待验证）。

**象限地色**：四个象限用不同地面材质区分（材质目录加 4 行），给 100 人棋盘一个不看小地图也能说出「我在哪、去哪」的方位语言（推断待验证；Stage 2 起）。

**出生 / 重生点**：**动态选点**取代固定 8 点——选当前人数最少的分区，在其中随机取可通行格，距任一玩家与炸弹 **≥ 6 格**（推断待验证），并保证 **L 形 3 格安全区**（该点 + 相邻两方向各一格为空地；不满足则清掉 ≤ 2 格软砖，属微量方块写入）。Stage 0 的 19×19 无分区，只取「距威胁 ≥ 6 格 + L 形安全区」。

**对称性**：棋盘四象限镜像对称，分区彼此等价；软砖分布可随机，但必须镜像同步。

**软砖再生**：滚动局会把软砖耗尽，导致后半局无方块可炸、无掉落来源。软砖按固定间隔**只在无人区域**批量再生，直至恢复目标密度（速率待验证）；终局停止再生。再生是低频批量写入，量级远低于爆炸破坏。Stage 0 不做再生。

### 5.1 场景材质：什么能炸、炸了变成什么

材质是本仓拥有的 MaterialId 目录里的行（引用：[`../engineering/mvp-placevoxel-content-spec.md`](../engineering/mvp-placevoxel-content-spec.md) §6.2），每种材质一行数据、五个字段：可破坏、阻断爆炸、破坏后残留、掉落、地面效果。Voxel 引擎不解释含义，全部行为在玩法层的爆炸函数与 GAS Effect 里消费。首发同屏可见的材质不超过 6 种，每种轮廓与色相一眼可辨（支柱 4）。

| 材质 | 世界观 | 可破坏 | 阻断爆炸 | 破坏后 | 掉落 | 阶段 |
|---|---|---|---|---|---|---|
| **积木** | 软砖主体，彩色积木 | 是（1 次爆炸） | 是（吃第一层） | 露出地面，碎块飞溅 | 30% 糖果 / 血包 /（Stage 5）装备箱 | 0 |
| **铁皮** | 硬砖、分区墙、补给围院 | 否 | 是 | — | — | 0 |
| **木箱** | 上锁的小木箱 | 是（1 次爆炸或钻头） | 是 | 箱子裂开 | **必掉** 1 个糖果或（Stage 5）装备箱 | 2 |
| **水盆** | 桌面上的水盆 / 护城河（地面，非砖） | 否 | **是**（爆炸到水边停） | — | — | 2 |
| **木头** | 木头玩具积木 | 是（1 次爆炸） | 是 | 露出地面并**留火 1.5 秒**（区域 Effect，不改方块），随后焦痕贴花 | 同积木 | 5 |
| **鞭炮** | 一串鞭炮 | 是（任何爆炸触及） | — | **自身引爆**：火力 2 的十字爆炸，计入爆炸链 | 无 | 5 |
| **冰面** | 冻住的水盆 | 否（会融化） | 否 | 5 秒后化回水 | — | 候选，不排期 |

（配比、时长均推断待验证；阶段列按 ADR 0014「复杂材质交互后移」分期）

**地面效果**（走在上面）：水盆——移速 −30%、**不能放炸弹**（放下即熄灭，炸弹消失）、进入即解除燃烧；火地（木头燃烧中 / 火焰弹留火）——每秒 −1 心（§12）；冰面——惯性打滑。地面是「破坏后露出的东西」，象限地色也是地面材质。

**破坏后的样子**：一律「露出地面 + 材质对应的残留」——积木碎块飞溅、木头留火后焦痕、鞭炮焦痕、木箱裂开。残留是贴花与粒子（表现层），不是方块；软砖再生按原配比补回（推断待验证）。

### 5.2 技能 × 场景交互

交互只有两类合法形态：**读材质改行为**（零写入）与**区域 Effect**（零写入）；会写方块的临时交互只有「冰冻水面」，列为候选不排期（引用：[`../risks-and-engine-asks.md`](../risks-and-engine-asks.md) A8）。筑墙、穿墙、临时冰面首发不做（ADR 0014）。

| 技能 | × 材质 | 结果 | 阶段 |
|---|---|---|---|
| 任何炸弹 | 水盆 | 放在水里立即熄灭；爆炸到水边停 | 2 |
| 踢弹 | 水盆 | 把炸弹踢进水里 = 拆弹（防守核心动作） | 5 |
| 分裂弹 | 水盆 | 子弹落水熄灭 | 暂缓 |
| 火焰弹 | 木头 | 留火时长翻倍 | 暂缓 |
| 火焰弹 | 水盆 | 无留火 | 暂缓 |
| 冰冻弹 | 火地 | 灭火 | 5 |
| 钻头 | 木箱 | 不放弹也能开箱（无声拾荒） | 暂缓 |
| 穿透弹 | 木头 / 积木 | 全线摧毁；木头段全部留火 | 暂缓 |
| 任何爆炸 | 鞭炮 | 引爆，计入连锁 | 5 |
| 筑墙 | 任意地面（水盆除外） | 放一块积木 | 首发不做 |
| 冰冻弹 | 水盆 | 结冰 5 秒：可走、可放弹、打滑（临时方块写入） | 候选，不排期 |

### 5.3 场景可玩性需求（给地图生成器的明确要求）

每张棋盘必须满足以下断言，生成器不满足即重生成；断言以固定 Seed 样本回归（数值推断待验证）：

1. **两个密度指标**同时落在目标带（本节表头）。
2. **每个分区**（Stage 2 起）：1 个小补给箱、1 处水盆（3–6 格池塘或护城河）、木箱 3–5 个；Stage 5 起加鞭炮簇 1–2 处（3–4 格相邻）、木头区 1 片（8–12 格）；其余软砖为积木。Stage 0 的 19×19 只有积木、铁皮、空地。
3. **水盆 ≤ 5% 格子**，只作池塘与护城河，**不得封死分区缺口或出生安全区**；水边至少留 1 格陆路绕行。
4. **每个可通行格 3 秒内可到达一处掩体**（铁皮硬砖阵列保证），软砖全部炸光后仍成立。
5. **无死角**：软砖全炸光后任意两可通行格连通；出生 L 形安全区不含水盆与鞭炮；出生后 3 秒内不存在不可反应的夹击格。
6. **对称与等价**：四象限镜像；补给点、水盆、鞭炮簇镜像同步。
7. **可读性**：同屏可见材质 ≤ 6 种；鞭炮与木箱必须在俯视下与积木一眼区分（进 B1）。
8. **地标**：每象限用象限地色 + 1 个铁皮地标轮廓（生成器模板，如动物剪影）作方位语言。

## 6. 操作方案

一套玩法，两套操作。桌面浏览器键鼠优先；触屏浏览器不承诺首发（ADR 0013）。

| 动作 | PC | 触屏 |
|---|---|---|
| 移动 | WASD / 方向键 | 左侧虚拟摇杆 |
| 放炸弹 | 空格 | 右下主按钮 |
| 主动槽技能 / 替换确认 | Shift | 右下副按钮 |

**触屏布局**：两个按钮都在右下，拇指自然覆盖范围内。摇杆区域不与角色重叠（否则手指挡住自己）。

### 6.1 手感规则（冻结，逻辑层实现）

自由八向移动（非格子对齐），加以下六条冻结规则（ADR 0014；强度取值推断待验证）：

1. **转角自动修正**：贴着墙角走时自动吸附进通道；连续转角只做轻度吸附，不能把玩家拉入危险方向。
2. **炸弹总是落在最近的合法格中心**。
3. **离格穿透**：玩家刚放下自己的炸弹时，在离开该格前可以穿过它；离开后重新进入会被炸弹阻挡。
4. **放弹输入缓冲** 100–150ms：刚进入合法格时自动执行。
5. **权威判定**：移动预测和爆炸命中以服务器权威结果为准，客户端只预测自身移动与放弹表现。
6. 这几条对「顺不顺手」的影响大于增加第五种炸弹形态；Stage 0a 用 Bot 命令流回放验证规则本身，Stage 0b 起用真人验证手感。

## 7. 炸弹机制（核心）

### 7.1 基础规则

| 项 | 首轮默认值 | A/B 值 |
|---|---:|---|
| 引爆时间 | **2.1 秒** | 1.8 / 2.1 / 2.4 秒 |
| 爆炸危险判定持续 | 0.35–0.4 秒 | 0.3 / 0.4 / 0.5 秒 |
| 爆炸形状 | 十字（上下左右四方向）；炸弹槽装备可改形态（§8.4） | — |
| 初始火力 | **2 格** | 1 / 2 格 |
| 初始可同时放置 | 1 颗 | 固定 1 |
| 对玩家伤害 | 每颗炸弹 −1 心（§12），与火力无关 | — |

（全部推断待验证；ADR 0014 以 v0.4 首轮默认值替换旧推定值。理由：3.5 格/秒 × 2.5 秒引信下玩家可在引爆前移动约 8.75 格，火力 1 只覆盖一格，早期炸弹主要用于挖墙、缺少对人威胁。）

### 7.2 爆炸传播

- 遇**硬砖**：立即阻断
- 遇**软砖**：摧毁该格后阻断（只吃第一层；穿透弹例外，见 §8.4）
- 遇**玩家**：−1 心（§12）；冰冻弹例外：冻结不扣心
- 遇**水盆**：阻断（§5.1）
- 遇**鞭炮**：引爆，计入连锁（§5.1）
- 遇**其他炸弹**：**立即连锁引爆**，并入同一 ChainId

连锁引爆是这个玩法的爽点来源，必须做对——一串炸弹接连炸开的节奏感是核心记忆点。

### 7.3 炸弹形态

炸弹槽决定炸弹形态，无装备时为标准弹。所有形态共用 7.1 / 7.2 的传播规则，只改「爆炸形状函数 + 参数」；形态清单与等级见 §8.4。

### 7.4 掉落

软砖被炸开后 **30% 概率**产生掉落物——官方房只掉**糖果与血包**（Stage 5 起加装备箱；池内权重见 §8.2）。木箱**必掉**（§5.1）。狂暴糖默认不进软砖池，只出自中央大补给（§8.6）。掉落物停留至被拾取，可被后续爆炸摧毁。负面拾取不进官方房（§8.5）。

**方块写入封顶**（引用：约束 5，[`../risks-and-engine-asks.md`](../risks-and-engine-asks.md) A8）：单次爆炸最多摧毁 24 格（火力上限 6 × 4 向）；穿透 L3 上限 = 火力全线；100 人满负载估算每秒 100–300 格破坏（推断，Stage 3 压测实测）。

### 7.5 连锁结算口径（逻辑瞬时、表现可解释）

ADR 0014 冻结：

- 同一颗炸弹对同一玩家最多命中一次；
- 同一 ChainId 对同一玩家的结算伤害不超过其心数上限（默认 3）；
- 服务器可在同一 Tick 完成权威结算，逐颗炸弹各出一条伤害事件（来源、主人、ChainId）；
- 客户端把多次受伤以极短节奏表现为「×N Chain」，不得看起来像单次爆炸莫名满血死亡；
- 死亡回顾列出每个伤害来源的炸弹、主人与 ChainId；
- 冻结、燃烧等后续效果不得偷偷计入「看不见的第四次命中」。

## 8. 装备与技能（Stage 5 起，可选切片）

只有核心模式通过 Stage 4 的留局门与可读性门后才开启；若装备使目标理解率、死亡可解释率或网络预算显著恶化，关闭 Feature Flag，以无装备版本发布（ADR 0014）。设计一次写全，实现后置。

### 8.1 三槽模型

| 槽 | 管什么 | 触发 |
|---|---|---|
| **炸弹槽** | 炸弹形态 | 放炸弹时生效 |
| **主动槽** | 一个有冷却的主动技能 | Shift / 副按钮 |
| **被动槽** | 一个常驻效果 | 自动 |

每槽最多 1 个技能，等级 1–3。无装备时：标准弹、无主动、无被动。

### 8.2 来源

| 通道 | 规则 | 性质 |
|---|---|---|
| **装备箱** | 软砖掉落池的一种掉落物，开出随机 Lv1 技能（池内权重待验证） | 发行 |
| **木箱** | 场景里可见的小木箱，炸开或钻开必掉 1 个装备箱或糖果（§5.1） | 发行 + 微目标 |
| **死亡掉落** | 死者每件装备 **50%** 落地，带等级（推断待验证） | 转移 |
| **中央大补给** | 战利品含装备箱 ×3（其中 1 件直出 Lv2）（§8.6） | 发行 + 全场节奏器 |

小补给箱不出装备（§8.6）。

### 8.3 拾取规则

| 情形 | 结果 |
|---|---|
| 该槽为空 | 走过即装备 |
| 同技能 | 走过即等级 +1（合成）；已满级（3）则不拾取，物品留地 |
| 异技能，拾取物等级 ≥ 已装备等级 | **站在物品上按副键确认后替换**，旧装备销毁（「旧装备落地」进待验证）；不确认则不换、物品留地 |
| 异技能，拾取物等级 < 已装备等级 | 不拾取，物品留地 |

效果：地面装备箱开出的全是 Lv1，合成过的玩家不会被路边 Lv1 换掉；只有别人掉落的高级装备能顶替你——「顶替」本身就是击杀的战利品；一次确认堵住「路过误换」，支柱 4 的「无菜单」让渡为「无菜单但有一次确认」（ADR 0014）。回退路径：若确认键让替换率过低，改为只对 Lv3 装备要求确认。

### 8.4 技能池 v0

★ = Stage 5 首测（每槽 2 个，共 6）；其余暂缓。L1 → L3 数值全为**推断待验证**。

| 槽 | 技能 | 效果 | L1 / L2 / L3 |
|---|---|---|---|
| 炸弹 | ★ 标准弹 | 十字，范围 = 火力 | 范围 +0 / +1 / +2 |

### 8.5 糖果与减益（无槽）

| 糖果 | 效果 | 上限 | 阶段 |
|---|---|---|---|
| **火力+** | 爆炸范围 +1 格 | 6 | 0 |
| **炸弹+** | 可同时放置 +1 | 6 | 0 |
| **速度+** | 移速 +0.35 格/秒 | 6.0 格/秒 | 0 |
| **血包** | 回 1 心（§12）；满心不拾取留地 | 心上限 | 1 |

糖果不占槽、死亡不清（支柱 3）。

**狂暴糖（稀有，正式 MVP 起，Stage 0 不含）**：只出自中央大补给（§8.6）。吃到即回满心并进入 **6 秒有界狂暴**（ADR 0014）：引爆时间缩为 1.2 秒、**最多额外放置 6–8 颗**、放置速率上限 4 颗/秒、**免疫自己的狂暴炸弹**；**不免疫他人**，被炸死照常掉帽掉装备；服务端按 `FrenzyPlacementBudget` 强制限制——表现可以「像无限」，实现必须有界（全为推断待验证）。外观全身红光 + 音乐加速，全场可见。

| 减益 | 效果 | 持续 | 落点 |
|---|---|---|---|
| **反向操作** | 移动方向反转 | 5 秒 | **自定义房 / 房主规则**，官方房关闭 |
| **失控放弹** | 强制持续放炸弹 | 5 秒 | 同上 |

官方默认房不掉负面拾取（ADR 0014）：在 100 人、三心、连锁与大量特效同时存在时，它们制造的是无法解释的死亡，并破坏玩家对输入的信任；核心模式证明好玩后再决定是否进入公开匹配。减益外观与糖果 / 装备箱**明确区分**（红色调 + 不同图标）。

**旧稿道具去向**：踢弹 → 被动；穿墙 → 被动「幽灵」（首发不做）；护盾 → 被动「厚棉花」；钻头 → 主动；遥控引爆 → 首发不做。

> 帽子**不是装备**：帽子没有任何数值效果、不占槽，规格见 §9。

### 8.6 补给：炸哪里才能变强

补给回答 100 人棋盘上「我该去哪」——它是固定地点的目标、装备的主要发行口、也是引导人群聚集的绞肉机。地形见 §5「补给点地形」。取代旧稿「有 HP 的据点宝箱」（ADR 0014）：固定 HP 在 8 人时要围攻、在 100 人中央聚集时瞬间被打空，无法同时落入 20–60 秒的争夺窗口。

| 项 | 小补给箱（每分区中心） | 中央大补给（棋盘中心围院） |
|---|---|---|
| 开启 | **3 次独立炸弹命中**后开启（同一爆炸链的多颗各算一次） | **不用 HP**：固定时刻**提前 10–15 秒预告**（全场横幅 + 光柱），到时自动落地并开启 |
| 次数 / 刷新 | 开启后 60–90 秒刷新 | 每局 1–2 次；最后一次落在终局最后一分钟开始时 |
| 战利品 | 基础糖果 ×3 + 血包 ×1，散落箱旁 | 糖果 ×5 + 血包 ×2 + 狂暴糖 ×1 +（Stage 5）装备箱 ×3（其中 1 件直出 Lv2）；**公开喷发，谁捡归谁** |
| 广播 | 不广播 | 预告与开启全场横幅；光柱与帽王光柱以颜色 + 轮廓 + 图标 + 音型区分 |
| 人数缩放 | 数值不变（支柱 6），只有箱数随分区数缩放 | 全档位恒 1 个 |
| 阶段 | Stage 2 | Stage 3（定时补给）；Stage 0/1 不做 |

（全部数值推断待验证）

- **不做最后一击归属**：战利品散落、开放哄抢——不需要伤害归属逻辑。
- **不出帽子**：帽子只来自击杀（ADR 0011）；补给聚人 → 击杀发生在补给 → 帽子照样从那里来。
- **实现口径**：小补给箱 = 带命中计数的实体，爆炸触及施加 +1 命中 Effect；中央补给 = 定时器 + 落地事件 + 战利品散落，复用帽子散落路径；围院 = 地图生成器模板；光柱与横幅复用帽王光柱与全场事件通道。零新框架。

## 9. 帽子系统（核心）

### 9.1 获取：铸造与转移

| 通道 | 规则 | 性质 |
|---|---|---|
| **击杀铸造** | 击杀 +1 顶铸到击杀者头顶；归属 = 打掉最后一颗心的炸弹主人，燃烧致死归火焰弹主人；自杀不铸（推断待验证） | 发行——解决 100 人下大量击杀零帽新人的经济停滞 |
| **击杀散落** | 死者帽子**全部**散落在死亡点周围可通行格（首轮 100%，A/B 70%） | 转移——帽子在玩家间流动 |
| **退出回流** | 中途退出者帽子当场散落，走同一路径 | 守恒——帽子不随人离场蒸发 |

宝箱不出帽：旧稿「帽子宝箱」改为装备箱（§8.2）。

### 9.2 堆叠、散落表示与通胀控制

帽子在头顶**物理堆叠**，塔高即分数，无单人数值上限——制衡靠散落与围攻，不靠封顶。

**数据与表现分离**（ADR 0014，帽子不能一顶对应一个网络实体）：

| 层 | 规则 |
|---|---|
| 权威状态 | 玩家 `HatCount` 整数；死亡时生成 **3–6 个 `HatPile`**，每堆带 `Count`；拾取一次转移整堆；**15 秒**无人拾取即回收（A/B 12 / 15 / 20 秒）；退出走同一散落路径；任意帽数总和守恒，拾取竞争只成功一次 |
| 客户端表现 | 帽子爆开时本地生成若干纯表现小帽子，实际可拾取碰撞体只有 3–6 个；12 顶以内逐顶叠，超过 12 顶用压缩塔段 / 比例缩放 / 循环装饰，避免遮挡角色与战场；数字仍显示真实帽数 |

**通胀纪律**：首轮保留「铸造 + 转移」双通道，不加隐藏衰减；必须先埋点（§17.1 帽子经济指标）再决定是否改规则。A/B 只测「死亡掉 100% vs 70%」「地面 12 / 15 / 20 秒」，每次击杀铸 1 顶不变；不同时改铸造、散落、拾取、超时四个阀门。

### 9.3 帽王可见性

- **屏幕内帽塔 = 局部计分板**（支柱 1）：最高的塔自然最显眼。
- **Top-10 侧栏**（PC）/ **Top-5 + 本人**（触屏）：名字 + 帽数。
- **帽王光柱**：第一名且 ≥ N 顶（N 待验证）时头顶竖起光柱，全图可见其方向；玩具世界口径「聚光灯」，表现归美术。
- **屏幕边缘帽王方向箭头**：首发必做（ADR 0014，原候选升级）。
- 大补给光柱与帽王光柱必须以颜色 + 轮廓 + 图标 + 音型区分（不只靠颜色）。

帽子**不随技能等级增加**；技能强度用装备自身外观表达，保证帽子塔只回答「谁在赢」。

### 9.4 死亡结算

心归零即死（§12）；死亡时帽子全散、每件装备 50% 落地、**糖果不清**——死亡代价只有两项（支柱 3），滚雪球已由糖果上限与装备等级上限拦截（§10）。

### 9.5 帽子明确不做的

- **无数值加成**：帽子不加移速 / 火力 / 防御——纯计分物（支柱 2 双向：帽王不吃惩罚也不吃奖励）；
- **不随技能等级增加**：帽子只代表击杀与掠夺；
- **无种类差异**：首发只有一种帽子；帽子外观 / 皮肤 / 收藏属账号级持久化，被引擎前置（[`../risks-and-engine-asks.md`](../risks-and-engine-asks.md) A5）阻塞，记远期不进首发。

### 9.6 可读性与死亡可解释（正式功能，不是美术收尾）

首发必含（ADR 0014；Stage 1 起接表现，逻辑层先保证事件与数据存在）：

- 屏幕边缘帽王方向箭头；Top-10（PC）/ Top-5 + 本人（触屏）；
- 本人准备放置的炸弹显示预计十字范围；**不给场上每颗炸弹全程绘制范围**（100 人时是视觉网格噪声）；
- 所有炸弹最后约 0.4 秒有清晰危险脉冲；
- 伤害来源与连锁归属实时提示；
- **死亡回顾**：击杀者、炸弹类型、连锁长度、最后两个伤害来源；
- 帽王、大补给、危险爆炸与血量变化同时使用轮廓、图标、文字、音效或震动，**关键目标不只靠颜色**；
- 屏幕震动、动态模糊与全屏效果可降到 0；高频闪光通过光敏检查；
- 定帧只作用于本人客户端，不暂停服务器或其他玩家模拟。

## 10. 数值框架

| 参数 | 初始 | 每级 | 上限 |
|---|---|---|---|
| 移速 | 3.5 格/秒（A/B 3.3 / 3.5 / 3.8） | +0.35 | 6.0 |
| 火力 | 2 格（A/B 1） | +1 | 6 |
| 炸弹数 | 1 | +1 | 6 |
| 装备等级（每槽，Stage 5） | 无 | +1（同技能合成） | 3 |

（全部推断待验证）

**上限存在的意义**：防止滚雪球。前期领先的玩家如果无上限成长，后半局会变成单方面屠杀，破坏多人局的乐趣。

**成长节奏**：预期玩家在 60 秒内拿到 3–4 个糖果进入"火力 4 / 炸弹 3"的舒适区（推断待验证）。滚动局下死亡不清糖果，全场会趋于满配均势——中后期的差距只剩帽子、装备搭配与操作。

### 10.1 中途加入补偿：只补战力，不补分数

糖果死亡不清会让局中后段的老玩家接近上限，新加入者裸装进场与「中途加入是一等公民」冲突。ADR 0014 定：

- 不获得帽子、不获得装备；
- 每经过完整 **120 秒**补 1 个随机基础升级，**最多 2 个**，优先补当前最低的火力 / 炸弹数 / 速度；
- 仍需通过游玩获得后续成长。

（数值推断待验证；Stage 1 起。）

## 11. 会话与房间

**滚动房间模型**：房间常驻，一局接一局连轴转；玩家随时进、随时走，服务器可同时开多个房间。

```
快速加入 / 房间码 → 进入房间（任意时刻）
   → 局中：立即入场（局末锁入期改为观战等下一局）
   → 局计时结束 → 结算 12–15 秒 → 自动下一局（房间保持，按人数重选地图档位）→ ……
```

**双入口**：

| 入口 | 定位 | 依赖 |
|---|---|---|
| **快速加入** | 默认入口：把玩家丢进一个未满的官方参数房间 | 引擎侧「房间目录 + 快速加入」轻量能力——**已登记为 ① 的入口依赖**（[`../risks-and-engine-asks.md`](../risks-and-engine-asks.md) A6）；Stage 4 需要；不是技能 / 段位匹配 |
| **房间码** | 保底入口 + 好友开黑 + 自建服 / 自定义规则房 | 无，首发可用 |

**快速加入只进官方默认参数的房间**；房主改过规则的房间走房间码或房间列表——避免新玩家被丢进认不出的规则变体（推断待验证）。

**局末锁入**：最后 N 秒（待验证，约 30）不再放新人入局，避免进场即结算；锁入期玩家观战等下一局。

### 11.1 房间填充策略（Stage 4）

地图只在局开始时选档、局中不变；滚动房的密度由**房间目录**控制，不在局中重建地图（ADR 0014）：

- 快速加入优先填充已有官方房，达到目标占用带后再开新房；
- 每档设置「目标人数区间」与滞回，避免频繁开关房；
- 低人口房在结算阶段提示并合并到另一个房间；
- 下一局按预计留存人数与排队人数重新选地图档；
- 局中地图不缩放、不瞬移玩家；最多容忍一个六分钟局的临时密度偏差；
- 自定义房不自动合并。

（目标区间与滞回值推断待验证。）

**房主可调规则（L0 UGC，首发即开放）**：
- 局时、房间人数上限、地图档位锁定与分区开关
- 软砖密度、再生速率
- 掉落率、糖果 / 血包 / 减益 / 装备箱的池内权重（减益只在自定义房可开）、技能池各技能开关与权重
- 装备掉落率、击杀铸帽数、死亡掉帽比例、重生秒数
- 补给箱开关、命中次数与刷新周期、中央补给次数与时刻、狂暴糖开关
- 心数上限、血包权重、燃烧开关
- 初始火力 / 炸弹数 / 移速

这是 UGC 阶梯的第一级，几乎零成本，但能立刻让服主有事可做。复杂房主规则编辑 UI 首发不做，首发以配置文件形态开放。

## 12. 血量、死亡、重生与观战

**血量**（定调依据 ADR 0012，由 0014 重申；全部数值推断待验证）：

| 项 | 规则 |
|---|---|
| 心数 | 每人 **3 颗心**（整数，引用 config IntegerOnly 纪律）；重生满心；先不测 5 心 |
| 爆炸伤害 | 每颗炸弹的爆炸触及 −1 心，与火力无关；同一爆炸链每颗炸弹各算一次，同一颗炸弹对同一人只算一次，同链对同人不超过心数上限——**单发削血，连锁秒杀**（结算口径 §7.5） |
| 燃烧 | 火焰弹直击后附加：每秒 −1 心，L1 1s / L2 2s / L3 3s；**首版最多追加 1 心或设为非致死**；泡泡或血包解除；燃烧中玩偶冒烟、倒计时可见 |
| 血包 | 糖果池与补给战利品；回 1 心，满心不拾取留地 |
| 回血 | 只有血包与厚棉花 L3 的脱战回血；不做自然回血——残血必须去找血包 |
| 残血表现 | 本人：1 心时屏幕边缘红晕 + 心跳音；他人：玩偶破损三档（完好 / 露线 / 露棉花），首版可用受击后 3 秒显示的小血条代替（进 B1） |

血量要制造的是「残血逃生 / 追杀残血」的张力：被炸一下不死，但一心残血在 100 人棋盘上跑向最近的血包或补给，是全局最紧张的 10 秒。

- **死亡**：心归零即死 + 帽子全散（§9.2 HatPile）+ 每件装备 50% 落地。死亡瞬间的帽子与装备飞散要做足表现——它是全场哄抢的发令枪（表现细节归美术，世界观基线见 [`../worldview.md`](../worldview.md) §2）。
- **重生**：**3 秒**（A/B 3 / 4 秒）后在动态出生点满心复活（§5）；带 **1.5 秒重生保护**（无敌 + 闪烁，放弹即解除）。
- **观战**：本模式没有死亡观战等待（支柱 3）；观战只存在于局末锁入期与结算间歇。

## 13. 结算与留存

结算页展示：

- **Top-10 榜**、本人名次与「击败了 X% 的玩家」、**帽王时长**（本局持有最高塔的累计时间）
- 击杀数、放弹数、破坏方块数、拾取数、最佳连锁、最高帽数、本局最高装备（Stage 5）
- **留局 / 下一局按钮**（结算 12–15 秒后自动下一局）
- 连胜提示

**首次游玩提示**只有三条，完成动作后永久消失，不做独立长教程：「放炸弹，炸开积木」「捡糖，让炸弹更强」「追光柱，抢最多的帽子」。

**首发不做账号进度系统**（等级、皮肤解锁、赛季）。留存靠局内爽感和房间社交，不靠养成。**玩家可见的完整比赛回放首发不做**（ADR 0014）；引擎侧命令录制、State Hash 与故障复现回放保留为 QA / 可靠性能力，不等于产品功能。赛后回放作为差异化能力（[`../product-direction.md`](../product-direction.md) §4）进后续路线图。帽子皮肤 / 装备外观类养成另被 A5 阻塞（见 §9.5）。

## 14. 平衡原则

1. **不许滚雪球**——糖果与装备等级有上限（§10），帽子零数值加成（§9.5）
2. **重生绝对公平**——棋盘四象限对称，动态出生点远离威胁
3. **运气可以有，但不能决定胜负**——掉落是随机的，但帽子只能靠杀和抢：财富分配由冲突决定，不由掉落决定
4. **死得快不如死得明白**——每次死亡玩家都要能立刻看出"我被什么炸死的"，爆炸范围与留火必须画在地面上，死亡回顾必须列出来源（§7.5 / §9.6）；每次掉心同理，燃烧要有倒计时
5. **装备是流动的不是终身的**——任何等级都可能落地易主；否掉绑定 / 不可掉落装备
6. **同一套规则从 8 人到 100 人**——数值不随人数改变，只有地图随人数缩放
7. **爆点可以有，但必须有时限、可反制、来源可争夺**——狂暴糖 6 秒有界、不免疫他人、只出自中央补给；否掉常驻或不可反制的强化
8. **表现可以像无限，实现必须有界**——活跃炸弹、HatPile、掉落物、表现对象都有配置上限；任何「无限」都有服务端预算
9. **规则不改，只改演出**——终局、补给、光柱都只是把现有规则推向高潮，不引入第二计分公式

## 16. 实现切片：Gate 0 + Stage 0–6

设计一次写全，实现分步；每阶段以**量化玩法门 / 性能门**通过，不以「功能做完」通过（ADR 0014）。按 ADR 0013，逻辑层先行、表现最后接：Stage 0 拆为 0a（headless）与 0b（浏览器客户端）；日历排期不入策划案。团队与仓库归属见 [`../risks-and-engine-asks.md`](../risks-and-engine-asks.md) 与 [`../../../.spec/knowledge/standards/repository-architecture.md`](../../../.spec/knowledge/standards/repository-architecture.md)。

| 阶段 | 内容 | 通过门 | 依赖 |

**总验收**：拉一个不认识这个项目的人中途进房——能否 **30 秒内看懂「谁在赢、我该干嘛」**，并且**自愿留满 3 局以上**？满房 100 人时这条判据仍须成立。

## 17. 遥测与门槛

逻辑层从 Stage 0a 起就产出遥测（ADR 0013：数据优先）；事件定义归本仓玩法层，Sink 归宿主。

### 17.1 玩法事件（必埋）

```text
match_join            first_move            first_bomb_place
first_block_destroyed first_pickup          first_damage_taken
first_damage_dealt    first_kill            hat_pile_spawned
hat_pile_picked       hat_pile_expired      hat_king_changed
supply_announced      supply_opened         death
respawn               match_end             next_match_stay
```

事件至少携带：`matchId`、`playerId`、`tick`、`elapsedMs`、`zoneId`、`hatCount`、`health`、`bombPower`、`bombCapacity`、`movementSpeedTier`、`joinElapsedMs`、`killer / source / chainId`（适用时）。

**帽子经济指标**（§9.2 改规则前必看）：每分钟铸造量、玩家持有总量、地面总量、超时销毁量、帽王持有比例、一次死亡平均散落量、每局帽王更替次数。

### 17.2 性能指标（必埋）

Tick P50 / P95 / P99 与 Overrun；每秒放弹、引爆与最大活跃炸弹；连锁宽度、深度与单链体素写入；每秒体素批量修改数；权威拾取对象数与 HatPile 数；每连接 AOI 实体数与复制字节；Snapshot / Delta 比例、Resync 次数；客户端可见特效、粒子、音源与 Draw Call；服务器与客户端内存趋势。

### 17.3 首轮门槛（内部决策线，不是行业基准）

| 维度 | 首轮门槛 |
|---|---|
| 目标理解 | ≥ 80% 新玩家 30 秒内正确说出胜负目标 |
| 首次行动 | 首次放弹中位数 ≤ 10 秒 |
| 进入循环 | 首次拾取 ≤ 15 秒，首次受伤 ≤ 25 秒，首次击杀 ≤ 45 秒 |
| 帽王戏剧 | 六分钟内帽王更替 3–6 次；至少一次 10+ 帽倒台 |
| 留局 | 首次测试 ≥ 60% 玩家自愿留满 3 局，后续按样本扩大复核 |
| 死亡可解释 | ≥ 90% 玩家能从现场或回顾判断主要死因 |
| 新人保护 | 中途加入后 5 秒受伤率 < 10%，20 秒内完成一次有效行动 |
| 稳定性 | 100 Bot 30 分钟无崩溃、无状态发散；6 小时无持续内存增长 |
| Tick | P99 ≤ Tick 周期 80%，Overrun < 0.1% |
| 无障碍 | 关键目标不只靠颜色；震动 / 抖动可为 0；通过光敏检查 |

「留满三局」不达标时，不先加账号成长与签到奖励掩盖问题；先判断核心循环是否真的提供了第二局理由。**用户测试从灰盒阶段开始**，由真实目标玩家测试，观察行为、不在现场替玩家解释；问题按影响排序并附录像证据。
