## 1. 使命

**这份设计稿要回答四个问题：「这套破坏玩法到底好不好玩、帽子塔能不能自发制造出『围攻帽王』的社交戏剧、100 人在同一张棋盘上跑不跑得动、这个画面组合到底好不好看」。**

回答顺序按 ADR 0013 固定：**先证明跑得动、跑得对、可重放（headless 逻辑层），再证明好玩（浏览器客户端接上后），画面最后。** 任何「以后可能有用」的系统一律不进首发；首发内容按 §16 切片实现，每阶段以量化门通过。

产品记忆点一句话：**连锁爆炸制造爽感，帽子塔公开展示财富，帽王倒台制造全场哄抢。** 值得做成产品的不是「体素 + 炸弹人 + 很多技能」，而是**百人帽王乱斗：体素是可破坏舞台，炸弹是冲突工具，帽子是看得见的实力，活到最后才算赢。**

一句话规则（30 秒讲清的版本，不讲角色技能、材质与补给——技能在选角界面各有一句话说明，玩家理解核心后再通过场上物体学习附加规则）：**「炸开积木拿强化糖，吃一颗头顶就多一顶帽子；被炸死会掉一半强化，谁捡归谁；帽子最多的人会被全场追踪。每人三颗心，死后三秒复活——但最后的决赛圈里死了就出局，圈外有毒，圈会一直缩到只剩一格。活到最后者赢；时间到还有好几个人活着，帽子最多的赢。」**

## 2. 核心循环

```
        发育：炸软砖 / 开木箱与补给箱 → 掉糖果 / 血包 / 技能糖 → 变强（强化 / 合成升级 / 组合进化）
          ↑                                    ↓
   重生（3 秒） ← 被炸死·强化与拾取技能各半掉（帽塔变矮） ← 炸掉对手·捡他掉下的强化和技能（帽塔变高）
          ↑                                    ↓
          └── 帽子垒高 → 帽王亮起光柱 → 被分区乃至全场围攻 ──┘

   决赛圈：积木剩 < 20% 或剩最后 115 秒 → 不再复活·圈外中毒·圈分 6 段一直缩到 1×1·圈内落强力宝箱 → 死即出局，只剩 1 人立即结束（§4.2）
   会话：选角（沿用上次）→ 局终 → 领奖台 + 结算表（约 16 秒，Top-10）→ 自动下一局（房间连轴转，随时进出）
```

**帽子 = 强化数的表现**（ADR 0028）：头顶几顶帽子就是身上几个强化。强化（糖果）与拾取的技能各两条通道：**砖块 / 木箱 / 宝箱掉落 = 发行**、**死亡掉落 = 转移**（ADR 0025 / 0030）；角色专属技能不流动（§8.0），技能也不计帽数（§9.5）。谁都能看见谁最强——帽子塔就长在头顶上，帽王头顶还有光柱。

## 3. 产品支柱

六条可证伪的支柱，用来否掉未来的具体提案：

| # | 支柱 | 这意味着 | 这不意味着 |
|---|---|---|---|
| 1 | **帽子塔是局部实力榜，Top-10 是全局摘要** | 屏幕内谁最强（强化最多）一眼可见；全局只给 Top-10 侧栏、帽王光柱与屏幕边缘方向箭头；决赛圈起 Top-10 按 §4 排名口径（存活者在前）；否掉把主计分藏进 UI 面板、否掉全员帽数小地图 | 没有任何 UI（计时、Top-10、结算仍有）；也不意味着帽子多就赢——活到最后才赢（§4） |
| 2 | **领先自带风险，制衡靠玩家不靠数值** | 帽王更显眼、更被觊觎，围攻是自发行为；否掉「帽子多移速慢」类数值惩罚，也否掉给帽王的数值奖励 | 系统不为帽王的可见性做任何事（光柱与箭头正是为可见性做的） |
| 3 | **死亡是节奏不是惩罚** | 常规阶段死亡代价只有两项：已吃强化每级 50% 落地（帽塔同步变矮）、拾取的技能每个 50% 落地（专属技能不掉；ADR 0025 / 0028 / 0030），3 秒后复活；否掉长重生 CD、死亡扣分、强化全清。**唯一例外是决赛圈**（每局最后 ≤ 115 秒，§4.2）：死即出局、观战到结算 | 死亡无代价（强化和拾取的技能就是代价）；也不意味着可以在常规阶段引入出局 |
| 4 | **随时能进，进来就懂** | 中途加入是一等公民，新系统不得提高进场理解成本；进房只多一步——**单屏四选一选角**（默认预选上次角色，ADR 0030）；拾取一律走过即生效或留地，**不做任何确认**；否掉第二计分资源、多步开局仪式、菜单式拾取 | 玩法没有深度（角色、技能搭配、组合进化与地形博弈仍在） |
| 5 | **一局是一场围绕帽王的戏剧** | 发行→积累→帽王→围攻→崩塌哄抢→新王，在分区内多次轮回，光柱把分区戏剧升级为全场戏剧；否掉让帽子或拾取技能流转停滞的设计（如拾取技能绑定不掉落）；**角色专属技能是唯一允许的绑定**——身份不是财富、不计帽数（ADR 0030） | 固定剧本或强制平均分配戏份 |
| 6 | **同一套规则从 8 人到 100 人** | 数值不随人数变，只有地图档位随人数缩放；否掉只在大人数下才成立的机制（如 ≥50 人才触发的事件） | 8 人房与 100 人房体验完全一样（密度与戏剧规模自然不同） |

### 3.1 爽感时刻

玩法必须稳定交付的「爽」，每条挂钩支柱并标成本类别：**表现层** = 客户端本地表现（零服务器成本、不复制）；**服务器事件** = 一条广播事件；**内容** = GAS 数据或美术资产。表现层全部在 Stage 1 起接入（ADR 0013：逻辑先行），逻辑层只保证事件与数据存在。

| 时刻 | 触发 | 表现 | 支柱 | 成本 |
|---|---|---|---|---|
| 连锁 | 同一爆炸链 ≥ 3 颗 | 「×N 连锁」弹字、屏幕震动随 N 增强、50–80ms 本人定帧（不暂停服务器与他人）；连锁秒杀见 §7.5 | 5 | 表现层 |
| 多杀 | 同一爆炸链击杀 ≥ 2 | 「双杀 / 三杀 / 一锅端（≥4）」弹字 + 音效 | 5 | 服务器事件 + 表现层 |
| 收割 | 一次连续捡起 ≥ 5 顶帽 | 帽塔快速叠高动画、连拾音效音高递增 | 1 / 5 | 表现层 |
| 合成 | 同技能合成升级（Stage 5） | 技能闪光；**每个 Lv3 必须有一眼可见的形态变化** | 4 | 内容 |
| 进化 | 两个不同技能在身上凑齐（§8.4 组合表） | 全场可见的玩偶形态变化（表现归美术）+ 本人横幅「进化：火焰冲刺！」+ 音效 | 4 / 5 | 服务器事件 + 内容 |
| 加冕 | 成为帽王 | 光柱亮起 + 「你是帽王」横幅 + 音乐层 | 1 / 2 | 服务器事件 + 表现层 |
| 倒台 | 帽王死亡 | 全场横幅「X 的 N 顶帽子散落了！」→ 踩踏式哄抢 | 5 | 服务器事件 |
| 补给 | 中央大补给落地开启 | 提前预告 + 落地喷泉式散落 + 全场横幅 | 4 / 5 | 服务器事件 + 表现层 |
| 狂暴 | 吃到狂暴糖（正式 MVP 起） | 全身红光 + 加速音乐 + 6 秒**有界**狂暴（§8.5） | 5 | 内容 |
| 逆袭 | 0 帽玩家击杀帽王后成为帽王 | 「逆袭！」横幅 | 2 / 5 | 表现层 |
| 拆迁 | 单次爆炸链破坏 ≥ 12 格 | 碎块飞溅加强 + 「拆迁 ×N」弹字 | — | 表现层 |
| 绝境 | 1 心逃生后捡到血包 | 心跳音停止 + 回血音效 + 玩偶缝合动画 | 3 | 表现层 |

全场横幅只播大事件（加冕、倒台、大补给预告 / 开启、决赛圈）；进化只给本人横幅、全场看玩偶形态；其余弹字只对本人显示——100 人下横幅刷屏会毁掉可读性（推断待验证）。

## 4. 局制规格

| 项 | 规格 |
|---|---|
| 人数 | **8–100 人弹性**，随中途进出浮动；官方默认房上限 **100**（引用：架构 v1.4 §12「100 人是第一阶段目标负载」；Stage 3 性能门实测后不达标则以实测稳定人数为临时上限，不强行承诺 100） |
| 模式 | 首发只做**帽子乱斗（FFA 计分）**；团队帽子赛作为第二模式候选（兼作模式数据格式的试金石，见 [`../ugc-ladder.md`](../ugc-ladder.md) §0） |
| 局时 | **封顶 7 分钟**滚动局（ADR 0031）：常规阶段最长到 5:05，决赛圈固定 115 秒；高强度对局约 4:05 进入决赛圈、约 6 分钟结束（推断待验证；A/B 封顶 6 / 8 分钟） |
| 胜负 | **活到最后者胜**（ADR 0031）：决赛圈内只剩 1 人存活即在致死的同一 Tick 立即结束，他是第 1 名（0 帽也算）；到时间上限仍 ≥ 2 人存活，存活者按帽数（= 强化数，§9）降序排名；出局者一律排在全部存活者之后，出局越晚名次越前。Top-10 上榜 |
| 平局 | 只在两处出现，都并列同名次、名次跳号（1、1、3）、不加赛：时间到时存活者帽数相同；同一 Tick 出局。最后几人同一 Tick 出局（无人存活）时，他们并列第 1 |
| 中途进出 | 任意时刻可加入（先选角色，§8.0；决赛圈期间除外：锁入观战等下一局，见 §11）；中途退出者强化与拾取的技能当场散落回流；中途加入者只补战力不补分数（§10.1） |

### 4.1 七分钟封顶的节奏与终局

| 时间 | 目标节奏 |
|---|---|
| 0:00–1:00 | 破墙、拿糖、用专属技能打出第一次交战，形成第一个帽王 |
| 1:00–3:00 | 分区内反复争夺，帽王首次倒台；木箱开出技能糖，出现第一次组合进化 |
| 3:00–4:05 | 中央补给制造跨区迁移；4:05（距时间触发 60 秒）停止软砖再生（ADR 0026） |
| 4:05–5:05 | 可破坏砖一旦 < 20% 即进入决赛圈；最晚 5:05（局时只剩 115 秒）由时间触发 |
| 触发–+115 s | **决赛圈**（§4.2）：不再复活、圈外中毒、圈一直缩到 1×1、圈内落强力宝箱、所有分区通道常开、帽王光柱与音乐增强；只剩 1 人立即结束；整局最晚 7:00 |
| 局终–+10 s | **领奖台**：前三名玩偶戴着帽子塔站上领奖台庆祝，其余玩家在台下（§13） |
| +10–+16 s | 结算表：Top、本人、存活 / 出局、**结束方式（唯一存活 / 同 Tick 全灭 / 时间到）**、帽王时长、最佳连锁、最高帽数；倒计时自动下一局，可退出、继续或换角色（下一局生效） |

**排名公式只有一个**（ADR 0031，取代 0025「胜负仍按帽子数」）：先看是否活到最后，再看帽数；不加双倍分、不扣落后者分（0014 / 0025 保留）。时刻表全部推断待验证。

### 4.2 决赛圈（最后一命）

ADR 0025 取代 0014「终局只是演出、不用致死收缩圈」；ADR 0031 让决赛圈一直缩到 1×1、打出唯一胜者。决赛圈把「资源耗尽后的空旷后半局」变成一局的高潮：人越来越少、圈越来越小、每一次死亡都算数。

| 项 | 规格（全部推断待验证，除注明「引用」） |
|---|---|
| 触发 | 资源或时间先到先触发：剩余可破坏砖（积木 + 木箱，再生补回的计入）< 开局的 **20%**，或局时只剩 **115 秒**（封顶 7 分钟下即 5:05）；资源触发**只在软砖再生停止后**生效（ADR 0026：再生在距时间触发 60 秒即 4:05 停止，§5） |
| 时长 | 固定 **115 秒**；资源先触发时局终 = 触发 + 115 秒，整局封顶 7 分钟（引用：§4）；只剩 1 人立即结束 |
| 复活 | 触发后死亡**不再复活**即「出局」：强化与拾取的技能**全部**掉落（帽数归零，§9.4），观战到结算；触发时已在重生倒计时中的**照常复活一次**，落点取当前安全圈内 |
| 安全圈 | 棋盘中心正方形，**6 段一直缩到 1×1**；19×19 档（内场 17×17）相对触发：+10 s **13×13**、+35 s **9×9**、+55 s **7×7**、+75 s **5×5**、+95 s **3×3**、+110 s **1×1**（棋盘正中心一格）、+115 s 局终；每段前 10 秒地面画出下一圈边界。其余档位：末三段同为 5×5 / 3×3 / 1×1，之前按内场边长等比插段、段间 ≥ 15 秒；1×1 取离棋盘中心最近的可通行非铁皮格 |
| 末段清场 | 5×5 / 3×3 / 1×1 **生效的那一刻**清掉新安全圈内全部积木与木箱：不掉落、不计破坏数，表现复用积木碎块；未爆炸弹不清（引信 ≤ 2.1 秒）；保证最后安全格每局都进得去。19×19 档一次最多 21 格（5×5 扣 4 根铁柱），3×3 为 5 格十字 |
| 毒圈 | 圈外：5×5 生效前每 1000 ms **−1 点**（每秒 −0.5 心，满血 6 秒毒死）；5×5 生效起每 1000 ms **−2 点**（每秒 −1 心，满血 3 秒）；重生保护与泡泡都**不**免疫；毒死按自杀口径（`Killer == Victim`），死因 = 毒圈（新增 `Cause`，见 §12） |
| 强力宝箱 | 每段收缩预告时在**下一圈内**随机空地落 1 个，**1×1 段不落**（19×19 共 5 个）；永不落在中心格，3×3 段之前也不落在 5×5 内的中心十字上（1×1 格因此至少留 3 个入口）；占格、挡路挡火，**3 次独立炸弹命中**开启（同链多颗各算一次，引用：§8.6 小补给箱口径）；喷出火力+ / 炸弹+ / 速度+ 各 1 + 血包 1 + **技能糖 1**（Lv1，§8.2），谁捡归谁；吃到喷出的强化帽塔照常 +1（ADR 0028） |
| 结束与胜负 | 存活（未出局）≤ 1 → 在致死的同一 Tick 立即结算，唯一存活者第 1 名；115 秒到仍 ≥ 2 人存活 → 存活者按帽数排名；口径见 §4 |
| 表现 | 横幅「决赛圈！不能复活，圈外有毒」；地面画当前圈（毒雾 / 紫色边界）与下一圈预告线；HUD 显示存活人数、下次收缩倒计时与当前毒速；出局者看到「你已出局 · 观战中」与名次 |

设计意图：决赛圈是人数减少后的**密度补偿**、**唯一的出局机制**，也负责**打出唯一胜者**——圈一路缩到 1 格、5×5 起毒速翻倍，把最后几个人逼到同一处交战（ADR 0031）；常规阶段仍然是「死亡是节奏」（支柱 3）。毒圈是区域伤害 Effect、零方块写入；末三段清场是三次一次性批量写入（19×19 ≤ 21 格，低于一次满火力爆炸的 24 格，引用：约束 5、§7.4）。掉线在决赛圈内等于出局，115 秒与 7 分钟两个上限把没有快速重连（约束 3）的风险框住。

## 5. 地图规格：人数-地图联动

密度用**两个指标**分开定义（ADR 0014；数值推断待验证）：

| 指标 | 含义 | 目标 |
|---|---|---|
| `potential_walkable_cells_per_player` | 软砖炸光后的潜在**可放弹格** / 人 | 26–30 |
| `initial_open_cells_per_player` | 开局立即可走的**可放弹格** / 人 | ≥ 9 |

**可通行 ≠ 可放弹**（ADR 0017）：可通行 = 砖层为空且地面层可走（含水方格）；可放弹 = 可通行且地面层不是水。两个密度指标只统计**可放弹格**——水里放不了炸弹也就打不了，算进去只会让指标虚高。

生成器不只追静态密度，优先追体验指标（Bot 对局与真人对局实测）：首次拾取中位数 ≤ 10 秒、首次见到其他玩家中位数 ≤ 15 秒、首次受伤中位数 ≤ 25 秒、出生后 3 秒内不会被不可反应地夹死、软砖全清后全图连通。

局开始时按在场人数（加预期加入量）选档，局中不变；房主可用 L0 规则锁定档位。

| 在场人数 | 棋盘 | 分区 | 每区约人数 | 进入阶段 |
|---|---|---|---|---|
| ≤12 | 19×19 | 无 | ≤12 | Stage 0 |
| 13–30 | 31×31 | 2×2 | 3–8 | Stage 2 |
| 31–60 | 45×45 | 3×3 | 3–7 | Stage 2 |
| 61–100 | 61×61 | 4×4 | 4–6 | Stage 3 |

（档位与尺寸均为推断待验证）

**地形分层**（ADR 0016）：地形是三维的，Stage 0a 只用两层——`z = -1` 地面层（地面、水方格、冰面）与 `z = 0` 砖层（硬砖、软砖、空地、木箱、木头、鞭炮），`z ≥ 1` 预留。实体（玩家、炸弹、掉落物）恒在 `Z = 0`，Stage 0a 不做垂直移动，爆炸只向 ±X / ±Y 四个水平方向传播。「破坏后露出地面」在这个模型下就是把砖层置空、露出下面的地面层。

**引擎坐标映射**（ADR 0019）：上面这套是**游戏坐标**，玩法代码只认它。上游体素契约的竖直轴是 `y` 且**无符号**（Section 键 `s:<x>:<y>:<z>` 的 y 限 0~15，世界高 256 格），负竖直坐标在键语法上不可表示，所以 `z = -1` 不能直接过边界。映射是 **游戏 (X, Y, Z) → 引擎 (x = X, z = Y, y = Z + 1)**：地面层 → 引擎 `y = 0`，砖层 → 引擎 `y = 1`。映射只出现在 `ITerrainStore` 的实现里，本节及以下全部按游戏坐标叙述。61×61×2 在引擎侧是 16 个 Section（4×4，竖直只占层号 0）。

三类格子（均在砖层 `z = 0`）：

| 类型 | 说明 | 分布 |
|---|---|---|
| **硬砖** | 不可破坏 | 固定阵列：行列均为偶数索引的交叉点；另构成分区墙 |
| **软砖** | 可被炸掉，按掉率掉糖果 / 血包（§7.4）；木箱另有技能糖（§5.1） | 随机填充剩余空格的 **65%**（推断待验证） |
| **空地** | 可通行 | 其余 |
| **补给点** | 分区小补给箱与中央大补给落点（§8.6） | 每分区中心 1 个小补给箱、棋盘中心 1 个大补给落点 |

**分区墙**：硬砖墙把棋盘切成分区，每段墙中点留 **3 格缺口**（推断待验证）。分区是「经典密度的小竞技场」——100 人的遭遇仍是 4–8 人规模，帽王戏剧先在分区内轮回。决赛圈通道常开（§4.1）。

**补给点地形**（规则见 §8.6）：小补给箱立在分区中心一格，四周不设围院；中央大补给落在棋盘中心 **5×5 硬砖围院**内，四边中点四个入口，院内无软砖、地面硬砖。围院是故意的死亡陷阱：硬墙不吸收爆炸、入口是卡点，院内哄抢就是支柱 5 的「崩塌哄抢」；院内没有软砖，人群最密处不产生方块写入（引用：[`../risks-and-engine-asks.md`](../risks-and-engine-asks.md) A8）。≤12 人档（19×19）无分区，只有中央落点（推断待验证）。

**方位语言**：四象限镜像对称会让四个角看起来一样，玩家需要一个「我在哪」的答案。这由 §5.3 断言 8 的**象限地标轮廓**单独承担——**不做象限地色**（ADR 0017：材质目录不为纯外观差异加 4 行；且 §9.6 要求关键目标不只靠颜色，纯地色方案本就不合格）。（推断待验证；Stage 2 起）

**出生 / 重生点**：**动态选点**取代固定 8 点——选当前人数最少的分区，在其中随机取可通行格，距任一玩家与炸弹 **≥ 6 格**（推断待验证），并保证 **L 形 3 格安全区**（该点 + 相邻两方向各一格为空地；不满足则清掉 ≤ 2 格软砖，属微量方块写入）。Stage 0 的 19×19 无分区，只取「距威胁 ≥ 6 格 + L 形安全区」。

**对称性**：棋盘四象限镜像对称，分区彼此等价；软砖分布可随机，但必须镜像同步。

**软砖再生**：滚动局会把软砖耗尽，导致后半局无方块可炸、无掉落来源。软砖按固定间隔**只在无人区域**批量再生，直至恢复目标密度（速率待验证）；距时间触发还剩 60 秒时停止再生（封顶 7 分钟下即 4:05，ADR 0031；决赛圈内自然不再生）。再生是低频批量写入，量级远低于爆炸破坏。**19×19 档同样再生**（ADR 0026）：每 8 秒补回至多 2 组四象限镜像积木、直到回到开局的 60%，只长在非水、非出生安全区、格上无物、离活人与炸弹 ≥ 3 格的位置（数值推断待验证）。

### 5.1 场景材质：什么能炸、炸了变成什么

**方块目录**（世界里存在哪些方块、外观与存储）是平台级公共材质库，归 Voxel 侧；**每个方块在炸弹人里的行为绑定归本仓**、随 `GameReleaseId` 锁定（ADR 0016）——一行数据、六个字段：可破坏、阻断爆炸、破坏后残留、掉落、地面效果、可通行。Voxel 侧按不透明 uint16 存取、不解释含义（引用：`mvp-placevoxel-content-spec.md` §6.2(该文档已随 R-00482 删除)），全部行为在玩法层的爆炸函数与 GAS Effect 里消费。首发同屏可见的材质不超过 6 种，每种轮廓与色相一眼可辨（支柱 4）。

| 材质 | 层 | 世界观 | 可破坏 | 阻断爆炸 | 破坏后 | 掉落 | 阶段 |
|---|---|---|---|---|---|---|---|
| **积木** | 砖 | 软砖主体，彩色积木 | 是（1 次爆炸） | 是（吃第一层） | 露出地面，碎块飞溅 | 30% 糖果 / 血包 | 0 |
| **铁皮** | 砖 | 硬砖、分区墙、补给围院 | 否 | 是 | — | — | 0 |
| **地面** | 地面 | 桌面 / 垫布，砖被炸掉后露出的底 | 否 | 否 | — | — | 0 |
| **木箱** | 砖 | 上锁的小木箱 | 是（1 次爆炸或钻头） | 是 | 箱子裂开 | **必掉** 1 个：Stage 5 起 50% 技能糖，其余糖果 / 血包（§8.2） | 2 |
| **水方格** | 地面 | 桌面上的水 / 护城河 | 否 | **覆盖该格后停**（火焰打到水面，但不穿过） | — | — | 2 |
| **木头** | 砖 | 木头玩具积木 | 是（1 次爆炸） | 是 | 露出地面并**留火 1.5 秒**（炸弹实体的留火阶段，不改方块），随后焦痕贴花 | 同积木 | 5 |
| **鞭炮** | 砖 | 一串鞭炮 | 是（任何爆炸触及） | — | **自身引爆**：火力 2 的十字爆炸，计入爆炸链 | 无 | 5 |
| **冰面** | 地面 | 冻住的水方格 | 否（会融化） | 否 | 5 秒后化回水 | — | 候选，不排期 |

（配比、时长均推断待验证；阶段列按 ADR 0014「复杂材质交互后移」分期）

**地面效果**（走在上面）：水方格——移速 −30%、**不能放炸弹**（放下即熄灭，炸弹消失）、进入即解除燃烧、**每秒 −0.5 心的溺水**（§12）；冰面——惯性打滑。火地（木头燃烧中 / 火焰弹留火）**不是**地面材质，而是炸弹实体留火阶段的覆盖范围（§7.3，ADR 0017）——**每秒 −1 心（−2 点）、可致死**，站上去 3 秒烧死（§12）。地面层是「砖被炸掉后露出的东西」。

**破坏后的样子**：一律「露出地面 + 材质对应的残留」——积木碎块飞溅、木头留火后焦痕、鞭炮焦痕、木箱裂开。残留是贴花与粒子（表现层），不是方块；软砖再生按原配比补回（推断待验证）。

### 5.3 场景可玩性需求（给地图生成器的明确要求）

每张棋盘必须满足以下断言，生成器不满足即重生成；断言以固定 Seed 样本回归（数值推断待验证）：

1. **两个密度指标**同时落在目标带（本节表头），按**可放弹格**统计。
2. **每个分区**（Stage 2 起）：1 个小补给箱、1 处水域（3–6 格池塘或护城河）、木箱 3–5 个；Stage 5 起加鞭炮簇 1–2 处（3–4 格相邻）、木头区 1 片（8–12 格）；其余软砖为积木。Stage 0 的 19×19 只有积木、铁皮、空地。
3. **水方格 ≤ 5% 格子**，只作池塘与护城河，**不得封死分区缺口或出生安全区**；水边至少留 1 格陆路绕行；**连片水域的最长跨度有上限**（推断待验证）——前三条约束都允许一条贯穿全图的护城河，而那等于一条横跨全图、火焰打不穿的走廊。
4. **每个可通行格 10 格内可到达一处掩体**（3 秒 × 3.5 格/秒 的换算，按可通行路径长度而非直线距离），软砖全部炸光后重算仍成立。**掩体**定义为「相邻四格中至少有一个是硬砖的可通行格」（ADR 0017：原文只写「一处掩体」而未定义，无法机器判定）。
5. **无死角**：软砖全炸光后任意两可通行格连通；出生 L 形安全区不含水方格与鞭炮。（原「出生后 3 秒内不存在不可反应的夹击格」已按 ADR 0017 删除——它未被形式化因而不可机器判定，其意图由重生保护 3 秒、距威胁 ≥ 6 格、L 形安全区三重保障覆盖；作为**体验指标**仍保留在本节表头上方。）
6. **对称与等价**：四象限镜像；补给点、水域、鞭炮簇镜像同步。
7. **可读性**：同屏可见材质 ≤ 6 种；鞭炮与木箱必须在俯视下与积木一眼区分（进 B1）。
8. **地标**：每象限 1 个铁皮地标轮廓（生成器模板，如动物剪影）作方位语言——这是方位的唯一来源，象限地色已取消。

## 6. 操作方案

一套玩法，两套操作。桌面浏览器键鼠优先；触屏浏览器不承诺首发（ADR 0013）。

| 动作 | PC | 触屏 |
|---|---|---|
| 移动（四向，§6.1） | WASD / 方向键 | 左侧虚拟摇杆 |
| 放炸弹 | 空格 | 右下主按钮 |
| 主动技能（CD 显示在 HUD） | Shift | 右下副按钮 |
| 选角 | 点击角色卡 | 点击角色卡 |

**触屏布局**：放弹主按钮与技能副按钮都在右下（副按钮显示技能图标与 CD），拇指自然覆盖范围内。摇杆区域不与角色重叠（否则手指挡住自己）。

### 6.1 手感规则（冻结，逻辑层实现）

**四向 + 停**（引用：内核契约 v2 `方向` 枚举，ADR 0021 / 0032），加以下八条冻结规则（ADR 0014 / 0032；强度取值推断待验证）：

1. **转角自动修正**：贴着墙角走时自动吸附进通道，吸附阈值 **0.5 格**（连续转角 6 Tick 内降到 **0.25 格**）；不把玩家吸进危险方向。
2. **同按两个方向走得通的那个**：新按下的方向优先；走不通时沿旧方向继续滑行（沿墙滑动），新方向一旦走得通立即转入；两个都走不通才停（ADR 0032）。反方向键不作为回退方向；自动选择不走进危险方向；触屏摇杆副轴 ≥ 主轴一半时算作第二个方向。由规则层判定，客户端不读地形做决定。
3. **炸弹总是落在最近的合法格中心**。
4. **离格穿透**：玩家刚放下自己的炸弹时，在离开该格前可以穿过它；离开后重新进入会被炸弹阻挡。
5. **放弹输入缓冲 125 ms**（ADR 0018 由区间 100–150 收敛为单值，取中点；A/B 100 / 150）：刚进入合法格时自动执行。
6. **权威判定**：移动预测和爆炸命中以服务器权威结果为准，客户端只预测自身移动与放弹表现。
7. **没有碰撞箱，视觉占地 ≤ 0.7 格**：逻辑上玩家是通道中心线上的一个点，玩家之间互不阻挡（ADR 0032）；玩偶脚圈直径 0.7 格、朝移动方向前伸 ≤ 0.35 格，停在墙前不与墙体视觉重叠；脚圈、接触阴影与双脚严格画在插值后的逻辑位置；方向光阴影不得把头影投到前方墙面。
8. 这几条对「顺不顺手」的影响大于增加第五种炸弹形态；Stage 0a 用 Bot 命令流回放验证规则本身，Stage 0b 起用真人验证手感。

## 7. 炸弹机制（核心）

### 7.1 基础规则

| 项 | 首轮默认值 | A/B 值 |
|---|---:|---|
| 引爆时间 | **2.1 秒** | 1.8 / 2.1 / 2.4 秒 |
| 爆炸危险判定持续 | **0.4 秒**（ADR 0018 由区间 0.35–0.4 收敛为单值，取 A/B 中档） | 0.3 / 0.5 秒 |
| 爆炸形状 | 十字（上下左右四方向）；炸弹槽技能可改形态（§8.4） | — |
| 初始火力 | **2 格** | 1 / 2 格 |
| 初始可同时放置 | 1 颗 | 固定 1 |
| 对玩家伤害 | 每颗炸弹 −1 心 = **−2 个半心点**（§12），与火力无关 | — |

（全部推断待验证；ADR 0014 以 v0.4 首轮默认值替换旧推定值。理由：3.5 格/秒 × 2.5 秒引信下玩家可在引爆前移动约 8.75 格，火力 1 只覆盖一格，早期炸弹主要用于挖墙、缺少对人威胁。）

### 7.2 爆炸传播

传播沿 ±X / ±Y 四个水平方向逐格推进，**每一步同时读两层**——地面层 `z = -1`（水方格在这一层却要挡火）与砖层 `z = 0`：

- 遇**硬砖**（砖层）：立即阻断，不覆盖该格
- 遇**软砖**（砖层）：摧毁该格后阻断（只吃第一层；穿透弹与冰川弹例外，见 §8.4）
- 遇**水方格**（地面层）：**覆盖该格后停**——站在水里的人会被炸到，但火焰不穿过水（§5.1）
- 遇**玩家**：−1 心（§12）；冰冻弹与冰川弹同样扣心，再冻结存活者（§8.4，ADR 0030）
- 遇**鞭炮**：引爆，计入连锁（§5.1）
- 遇**其他炸弹**：**立即连锁引爆**，并入同一 ChainId

连锁引爆是这个玩法的爽点来源，必须做对——一串炸弹接连炸开的节奏感是核心记忆点。

### 7.3 炸弹形态

炸弹槽决定炸弹形态，炸弹槽空时为标准弹。所有形态共用 7.1 / 7.2 的传播规则；形态清单与等级见 §8.4。组合技冰川弹不新增形态：`BombKind = 1` + `PierceLayers = 1`（ADR 0030）。

**几何上五种形态全部是十字**（ADR 0017）：标准弹、冰冻弹、火焰弹、穿透弹的差别在伤害语义与余烬，不在形状；分裂弹的子弹是 0.5 秒后独立的新爆炸、各自又是一次十字。因此**不设形状枚举**，形态差异只用两个参数表达——`BombKind`（伤害与余烬语义）与 `PierceLayers`（遇软砖后可继续的层数）。

**爆炸不建实体，由炸弹实体持有**（ADR 0017）：炸弹引信到点后不销毁，转入爆炸态——先是火焰阶段（`dangerWindowMs`，进入覆盖格即受伤，同弹对同人最多一次），Stage 5 的火焰弹与木头再接一段留火阶段，然后销毁。十字覆盖范围用**四臂实际到达格数**（上 / 下 / 左 / 右，传播算完后写入、已含地形阻断）描述；客户端据此直接绘制火焰，中途加入者也能看到进行中的爆炸。100 人满负载下同时存在的爆炸态炸弹约 12 个，取代原先每秒 100–300 个爆炸格实体。

### 7.4 掉落

软砖被炸开后 **30% 概率**产生掉落物——积木只掉**糖果与血包**（池内权重推断待验证）。木箱**必掉**，Stage 5 起一半是技能糖（§8.2）。狂暴糖默认不进软砖池，只出自中央大补给（§8.6）。掉落物停留至被拾取，可被后续爆炸摧毁；**例外：死者掉出的强化与技能糖落地后 3 秒内不会被爆炸摧毁**（ADR 0029 / 0030，推断待验证，A/B 2 / 5 秒），保护期内罩一层淡金色泡泡、最后 0.8 秒闪烁。负面拾取不进官方房（§8.5）。

**方块写入封顶**（引用：约束 5，[`../risks-and-engine-asks.md`](../risks-and-engine-asks.md) A8）：单次爆炸最多摧毁 24 格（火力上限 6 × 4 向）；穿透 L3 上限 = 火力全线；100 人满负载估算每秒 100–300 格破坏（推断，Stage 3 压测实测）。**连锁不设上限**（ADR 0016）——一条链最坏约 **1200 格落在同一 tick**（100 人、约 50 颗弹并入同一 ChainId），这个尖峰与分帧提交策略归 Voxel 侧与 A8 定，本仓只提供数字并按 §17.2 埋点。

### 7.5 连锁结算口径（逻辑瞬时、表现可解释）

ADR 0014 冻结：

- 同一颗炸弹对同一玩家最多命中一次；
- 同一 ChainId 对同一玩家的结算伤害不超过 `maxHealthPoints`（默认 6 个半心点 = 3 颗心）；
- 服务器可在同一 Tick 完成权威结算，逐颗炸弹各出一条伤害事件（来源、主人、ChainId）；
- 客户端把多次受伤以极短节奏表现为「×N Chain」，不得看起来像单次爆炸莫名满血死亡；
- 死亡回顾列出每个伤害来源的炸弹、主人与 ChainId（`DamageApplied` 带 `SourceBombNetEntityIdRaw`，ADR 0018 补齐）；
- 冻结、燃烧等后续效果不得偷偷计入「看不见的第四次命中」。

**同弹命中记忆的实现口径**（ADR 0017）：「同一颗炸弹对同一玩家最多命中一次」要求按炸弹记录已命中集合。它不复制、不持久，落在服务端的临时结构里，**不作为 Component 字段**。

## 8. 角色、技能与组合进化（Stage 5 起，可选切片）

只有核心模式通过 Stage 4 的留局门与可读性门后才开启；若角色与技能使目标理解率、死亡可解释率或网络预算显著恶化，关闭 Feature Flag：技能全部关闭、角色退化为纯外观（基础属性本就相同），以无技能版本发布（ADR 0014 / 0030）。设计一次写全，实现后置；网页原型已提前实现本节（ADR 0030，仅限原型）。

**术语**：**技能** = 占槽的能力（角色专属技能 / 拾取的技能 / 组合技）；**技能糖** = 地上可拾取的技能，带等级（取代旧稿「装备 / 装备箱」）；**强化** = 火力+ / 炸弹+ / 速度+（§8.5），只有强化计帽数（§9）。

### 8.0 角色

| 角色 | 玩偶 | 专属技能 | 槽 | 选角界面一句话 |
|---|---|---|---|---|
| **棉花兔** | 兔 | 回春 | 被动 | 10 秒没受伤就回 1 颗心，之后每 10 秒再回 1 颗，直到满血 |
| **泡泡鸭** | 鸭 | 泡泡 | 主动 | 吹个泡泡，3 秒无敌（期间不能放炸弹） |
| **闪电猫** | 猫 | 闪现 | 主动 | 向面朝方向瞬移最多 3 格，铁皮挡得住 |
| **火焰熊** | 熊 | 火焰光环 | 主动 | 身边一圈着火 4 秒，敌人每秒掉 1 颗心 |

- **基础属性完全相同**（§7.1 / §10），角色只差一个专属技能（原则 10）。
- **选角**：进房时单屏四选一，默认预选上次角色（客户端本地记住，约束 7）；之后每局沿用，结算页可换、下一局生效；中途加入同样先选再进。全部角色免费、无解锁。
- **专属技能绑定**：开局即在自己的槽里，永不掉落、永不被替换；只能被同技能糖升级（上限 Lv3），或进化成包含它的组合技（§8.4）。这是支柱 5 的唯一例外：身份不是财富，不计帽数（§9.5）。

（首批 4 个角色、技能配对与一句话说明均为推断待验证，见 §15「开局选角」「角色平衡」。）

### 8.1 三槽模型

| 槽 | 管什么 | 触发 |
|---|---|---|
| **炸弹槽** | 炸弹形态 | 放炸弹时生效 |
| **主动槽** | 一个有冷却的主动技能 | Shift / 副按钮 |
| **被动槽** | 一个常驻效果 | 自动 |

每槽最多 1 个技能或 1 个组合技；技能等级 1–3，组合技无等级。开局时专属技能已占它的槽，另两槽为空；炸弹槽空 = 标准弹。

### 8.2 来源

| 通道 | 规则 | 性质 |
|---|---|---|
| **木箱** | 必掉 1 个：**50%** 技能糖（Lv1），其余按 §8.5 糖果 / 血包池（推断待验证，A/B 30% / 70%） | 发行 + 微目标 |

### 8.3 拾取规则

走过技能糖时按顺序判定，命中即停：

| 情形 | 结果 |
|---|---|
| 与身上某个技能在组合表里成对（§8.4） | **立即进化**成组合技，占组合表规定的槽；另一半原所在的槽腾空 |
| 同技能 | 等级 +1（合成）；已 Lv3 不拾取，物品留地 |
| 对应槽为空 | 以技能糖的等级装上 |
| 其余（槽已被别的技能或组合技占着） | 不拾取，物品留地 |

效果：专属技能永远不会被挤掉；拾取不需要任何按键，Shift 只管主动技能（支柱 4）；捡不起的技能糖留给别人，想换技能只能靠组合或死亡掉落。**不做替换确认**（ADR 0030 取代 0014）：角色开局就带主动技能，Shift 兼任「替换确认」会在物品上方撞键。回退路径：§15「占槽不拾取」不达标时另立 ADR 引入替换手势。

### 8.5 糖果与减益（无槽）

| 糖果 | 效果 | 上限 | 阶段 |
|---|---|---|---|
| **火力+** | 爆炸范围 +1 格 | 6 | 0 |
| **炸弹+** | 可同时放置 +1 | 6 | 0 |
| **速度+** | 移速 +0.35 格/秒 | 6.0 格/秒 | 0 |
| **血包** | 回 1 心 = 2 个半心点（§12）；满血不拾取留地 | `maxHealthPoints` | 1 |

糖果不占槽。**死亡时已吃的强化每级 50% 概率掉落**（火力+ / 炸弹+ / 速度+，推断待验证，A/B 30% / 100%；ADR 0025）：掉出的强化散落在死亡点周围可通行格，谁捡归谁（落地后 3 秒内炸不掉，§7.4），死者最低保留初始值；血包不是强化、不掉落。死者复活后因此变弱，击杀者与哄抢者因此变强——强化与帽子一样在玩家间流动（支柱 5）。

**狂暴糖（稀有，正式 MVP 起，Stage 0 不含）**：只出自中央大补给（§8.6）。吃到即回满血并进入 **6 秒有界狂暴**（ADR 0014）：引爆时间缩为 1.2 秒、**最多额外放置 6–8 颗**、放置速率上限 4 颗/秒、**免疫自己的狂暴炸弹**；**不免疫他人**，被炸死照常掉强化与拾取的技能；服务端按 `FrenzyPlacementBudget` 强制限制——表现可以「像无限」，实现必须有界（全为推断待验证）。外观全身红光 + 音乐加速，全场可见。

| 减益 | 效果 | 持续 | 落点 |
|---|---|---|---|
| **反向操作** | 移动方向反转 | 5 秒 | **自定义房 / 房主规则**，官方房关闭 |
| **失控放弹** | 强制持续放炸弹 | 5 秒 | 同上 |

官方默认房不掉负面拾取（ADR 0014）：在 100 人、三心、连锁与大量特效同时存在时，它们制造的是无法解释的死亡，并破坏玩家对输入的信任；核心模式证明好玩后再决定是否进入公开匹配。减益外观与糖果 / 技能糖**明确区分**（红色调 + 不同图标）。

**旧稿道具去向**：踢弹 → 被动；冲刺 → 闪现（瞬移，ADR 0030）；穿墙 → 被动「幽灵」（首发不做）；护盾 → 被动「厚棉花」；钻头 → 主动；遥控引爆 → 首发不做。

> 帽子**不是技能**：帽子没有任何数值效果、不占槽，规格见 §9。技能糖也不是强化：不计帽数、不受强化上限（§9.5）。

### 8.6 补给：炸哪里才能变强

补给回答 100 人棋盘上「我该去哪」——它是固定地点的目标、技能糖的主要发行口之一、也是引导人群聚集的绞肉机。地形见 §5「补给点地形」。取代旧稿「有 HP 的据点宝箱」（ADR 0014）：固定 HP 在 8 人时要围攻、在 100 人中央聚集时瞬间被打空，无法同时落入 20–60 秒的争夺窗口。

| 项 | 小补给箱（每分区中心） | 中央大补给（棋盘中心围院） |
|---|---|---|
| 开启 | **3 次独立炸弹命中**后开启（同一爆炸链的多颗各算一次） | **不用 HP**：固定时刻**提前 10–15 秒预告**（全场横幅 + 光柱），到时自动落地并开启 |
| 次数 / 刷新 | 开启后 60–90 秒刷新 | 每局 1–2 次；最后一次落在决赛圈开始时（与决赛圈强力宝箱不叠加，§4.2） |
| 战利品 | 基础糖果 ×3 + 血包 ×1，散落箱旁 | 糖果 ×5 + 血包 ×2 + 狂暴糖 ×1 +（Stage 5）技能糖 ×3（其中 1 个直出 Lv2）；**公开喷发，谁捡归谁** |
| 广播 | 不广播 | 预告与开启全场横幅；光柱与帽王光柱以颜色 + 轮廓 + 图标 + 音型区分 |
| 人数缩放 | 数值不变（支柱 6），只有箱数随分区数缩放 | 全档位恒 1 个 |
| 阶段 | Stage 2 | Stage 3（定时补给）；Stage 0/1 不做 |

（全部数值推断待验证）

- **不做最后一击归属**：战利品散落、开放哄抢——不需要伤害归属逻辑。
- **帽子随强化走**：补给只出糖果 / 血包 / 技能糖；帽子不是独立资源，吃到补给里的强化帽塔自然变高（ADR 0028）。
- **实现口径**：小补给箱 = 带命中计数的实体，爆炸触及施加 +1 命中 Effect；中央补给 = 定时器 + 落地事件 + 战利品散落，复用帽子散落路径；围院 = 地图生成器模板；光柱与横幅复用帽王光柱与全场事件通道。零新框架。

## 9. 帽子系统（核心）：帽子 = 强化数的表现

ADR 0028（取代 0027，并取代 0011 / 0014 / 0025 里「帽子是独立计分资源」的全部条款）：**不再有独立的帽子资源。帽子只是表现——头顶叠几顶帽子，就表示这个人身上有几个强化。**

### 9.1 帽数怎么来

| 项 | 规则 |
|---|---|
| 帽数定义 | **帽数 = 当前强化级数之和** = (火力 − 初始火力) + (炸弹数 − 初始炸弹数) + 速度级数（(移速 − 初始移速) / 每级增量，向上取整）；纯派生值，不单独存、不单独结算。血包不是强化、不计入 |
| 增加 | 吃一个强化（砖块 / 木箱掉落、死者掉出、决赛圈宝箱喷出）帽数 +1；强化已达上限不能拾取，帽数也不变 |
| 减少 | 常规阶段死亡：强化每级 50% 掉落（§8.5），帽数同步减少；决赛圈死亡（出局）：强化**全部**掉落，帽数归零 |
| 击杀 | 不再单独铸帽；击杀的收益 = 死者掉在地上的强化，谁捡归谁（捡到即 +1 帽） |
| 上限 | 由强化上限决定（§10：火力 6、炸弹 6、移速 6.0）：首轮默认最多 4 + 5 + 8 = 17 顶（推断待验证） |

地上不再有「帽堆」（HatPile）：流动的是强化道具本身，帽子只跟着强化数变。

### 9.2 堆叠表示

帽子在头顶**物理堆叠**，塔高即强化数：12 顶以内逐顶叠，超过 12 顶用压缩塔段 / 比例缩放，避免遮挡角色与战场；数字仍显示真实帽数。吃强化时一顶帽子落到头顶；掉强化时帽子从头顶飞向掉出的强化。

### 9.3 帽王可见性

- **屏幕内帽塔 = 局部实力榜**（支柱 1）：强化最多的人塔最高、最显眼。
- **Top-10 侧栏**（PC）/ **Top-5 + 本人**（触屏）：名字 + 帽数（= 强化数）；决赛圈起按 §4 排名口径排序（存活者在前、出局者灰显）。
- **帽王 = 帽数最多且 ≥ 1 的玩家**（并列保留现任）；第一名且 ≥ N 顶（N 待验证）时头顶竖起光柱，全图可见其方向；玩具世界口径「聚光灯」，表现归美术。
- **屏幕边缘帽王方向箭头**：首发必做（ADR 0014，原候选升级）。
- 大补给光柱与帽王光柱必须以颜色 + 轮廓 + 图标 + 音型区分（不只靠颜色）。

### 9.4 死亡结算

血量归零即死（§12）；常规阶段死亡代价 = 强化每级 50% 落地（帽塔同步变矮）+ 拾取的技能每个 50% 落地（专属不掉，§8.2），3 秒后复活；**决赛圈内死亡 = 出局**：强化与拾取的技能全部落地（帽数归零）、不再复活，观战到结算（§4.2）。

### 9.5 帽子明确不做的

- **帽子本身没有数值**：它只是强化数的读数；强化的数值效果照常（火力、炸弹数、移速），帽子不另加任何东西；
- **不随技能增加**：角色专属技能、拾取的技能、技能等级与组合进化都不计帽数（ADR 0030）；只数火力 / 炸弹 / 速度三种强化；
- **无种类差异**：首发只有一种帽子；帽子外观 / 皮肤 / 收藏属账号级持久化，被引擎前置（[`../risks-and-engine-asks.md`](../risks-and-engine-asks.md) A5）阻塞，记远期不进首发。

**风险（进 §15）**：分数即实力——领先者同时最强，滚雪球风险高于「帽子无数值」的旧模型；制衡靠强化上限、死亡掉一半、决赛圈与全场围攻帽王。后期多人顶到上限会并列，并列按 §4 平局规则排序。

### 9.6 可读性与死亡可解释（正式功能，不是美术收尾）

首发必含（ADR 0014；Stage 1 起接表现，逻辑层先保证事件与数据存在）：

- 屏幕边缘帽王方向箭头；Top-10（PC）/ Top-5 + 本人（触屏）；
- 本人准备放置的炸弹显示预计十字范围；**不给场上每颗炸弹全程绘制范围**（100 人时是视觉网格噪声）；
- 所有炸弹最后约 0.4 秒有清晰危险脉冲；
- 伤害来源与连锁归属实时提示；
- **帽子与强化的流向可见**（ADR 0025 / 0028）：吃强化时一顶帽子落到头顶、显示「+1」；死亡时帽子从头顶飞向掉出的强化，掉出的强化带死者颜色的光圈；开局倒数期间显示一句话规则（§1）；
- **死亡回顾**：击杀者、炸弹类型、连锁长度、最后两个伤害来源；
- **技能可读**（ADR 0030）：本人技能槽与冷却常驻 HUD（主动技能标 Shift）；他人技能只靠玩偶形态与施放表现读出，不给他人冷却条；火焰格、泡泡与冻结必须画出来，技能致死的死亡回顾写明施放者与技能名；
- 帽王、大补给、危险爆炸与血量变化同时使用轮廓、图标、文字、音效或震动，**关键目标不只靠颜色**；
- 屏幕震动、动态模糊与全屏效果可降到 0；高频闪光通过光敏检查；
- 定帧只作用于本人客户端，不暂停服务器或其他玩家模拟。

## 10. 数值框架

| 参数 | 初始 | 每级 | 上限 |
|---|---|---|---|
| 移速 | 3.5 格/秒（A/B 3.3 / 3.5 / 3.8） | +0.35 | 6.0 |
| 火力 | 2 格（A/B 1） | +1 | 6 |
| 炸弹数 | 1 | +1 | 6 |
| 技能等级（每槽，Stage 5） | 专属技能 Lv1，其余槽空 | +1（同技能合成） | 3（组合技无等级） |

（全部推断待验证；四个角色的初始值完全相同，ADR 0030）

**上限存在的意义**：防止滚雪球。前期领先的玩家如果无上限成长，后半局会变成单方面屠杀，破坏多人局的乐趣。

**成长节奏**：预期玩家在 60 秒内拿到 3–4 个糖果进入"火力 4 / 炸弹 3"的舒适区（推断待验证）。死亡掉一半强化（§8.5），所以全场不会一边倒地趋于满配——连续存活的人更强，被击杀的人变弱、击杀者可以把他的强化捡走（推断待验证：死亡掉落率与「复活变弱」的挫败感见 §15）。

### 10.1 中途加入补偿：只补战力，不补分数

局中后段的老玩家接近上限（死亡只掉一半强化），新加入者裸装进场与「中途加入是一等公民」冲突。ADR 0014 定：

- 不获得帽子、不获得拾取技能（专属技能照常自带）；
- 每经过完整 **120 秒**补 1 个随机基础升级，**最多 2 个**，优先补当前最低的火力 / 炸弹数 / 速度；
- 仍需通过游玩获得后续成长。

（数值推断待验证；Stage 1 起。）

## 11. 会话与房间

**滚动房间模型**：房间常驻，一局接一局连轴转；玩家随时进、随时走，服务器可同时开多个房间。

```
快速加入 / 房间码 → 进入房间（任意时刻）→ 选角（单屏，默认上次）
   → 局中：立即入场（决赛圈期间改为观战等下一局）
   → 局终（只剩 1 人，或 7 分钟封顶）→ 领奖台 + 结算表约 16 秒 → 自动下一局（房间保持，按人数重选地图档位；结算页可换角色）→ ……
```

**双入口**：

| 入口 | 定位 | 依赖 |
|---|---|---|
| **快速加入** | 默认入口：把玩家丢进一个未满的官方参数房间 | 引擎侧「房间目录 + 快速加入」轻量能力——**已登记为 ① 的入口依赖**（[`../risks-and-engine-asks.md`](../risks-and-engine-asks.md) A6）；Stage 4 需要；不是技能 / 段位匹配 |
| **房间码** | 保底入口 + 好友开黑 + 自建服 / 自定义规则房 | 无，首发可用 |

**快速加入只进官方默认参数的房间**；房主改过规则的房间走房间码或房间列表——避免新玩家被丢进认不出的规则变体（推断待验证）。

**局末锁入 = 决赛圈**：决赛圈期间（≤ 115 秒，§4.2）不再放新人入局——进场即出局或进场即结算都没有意义；锁入期玩家观战等下一局。

### 11.1 房间填充策略（Stage 4）

地图只在局开始时选档、局中不变；滚动房的密度由**房间目录**控制，不在局中重建地图（ADR 0014）：

- 快速加入优先填充已有官方房，达到目标占用带后再开新房；
- 每档设置「目标人数区间」与滞回，避免频繁开关房；
- 低人口房在结算阶段提示并合并到另一个房间；
- 下一局按预计留存人数与排队人数重新选地图档；
- 局中地图不缩放、不瞬移玩家；最多容忍一局（≤ 7 分钟）的临时密度偏差；
- 自定义房不自动合并。

（目标区间与滞回值推断待验证。）

**房主可调规则（L0 UGC，首发即开放）**：
- 局时、房间人数上限、地图档位锁定与分区开关
- 软砖密度、再生速率
- 掉落率、糖果 / 血包 / 减益的池内权重（减益只在自定义房可开）、木箱技能糖占比、技能糖池各技能开关与权重、组合表各条开关
- 拾取技能掉落率、死亡掉强化比例、重生秒数
- 角色开关（关掉专属技能 = 角色只剩外观）、决赛圈段表与毒速
- 补给箱开关、命中次数与刷新周期、中央补给次数与时刻、狂暴糖开关
- 血量上限、血包权重、燃烧开关、溺水速率
- 初始火力 / 炸弹数 / 移速

这是 UGC 阶梯的第一级，几乎零成本，但能立刻让服主有事可做。复杂房主规则编辑 UI 首发不做，首发以配置文件形态开放。

## 12. 血量、死亡、重生与观战

**血量**（定调依据 ADR 0012，由 0014 重申，单位与粒度由 ADR 0017 修订；全部数值推断待验证）：

| 项 | 规则 |
|---|---|
| 血量单位 | 权威单位是**半心点**（ADR 0017）：满血 `maxHealthPoints = 6` 点、`healthPointsPerHeart = 2`，即 **3 颗心**（整数，引用 config IntegerOnly 纪律）；重生满血；先不测 5 心 |
| 爆炸伤害 | 每颗炸弹的爆炸触及 −1 心（−2 点），与火力无关；同一爆炸链每颗炸弹各算一次，同一颗炸弹对同一人只算一次，同链对同人不超过 `maxHealthPoints`——**单发削血，连锁秒杀**（结算口径 §7.5） |
| 溺水 | 站在水方格中**每秒 −0.5 心**（−1 点），满血 6 秒溺死；离开即停止。溺死按自杀口径结算（`Killer == Victim`），死亡代价照 §9.4——这使「躲水」从最优解变成最差解，且不新增任何规则 |
| 燃烧 | 火焰弹直击后附加：每秒 −0.5 心（−1 点），L1 1s / L2 2s / L3 3s；**首版非致死**；泡泡或血包解除；燃烧中玩偶冒烟、倒计时可见 |
| 毒圈 | 决赛圈安全圈外（§4.2）：5×5 生效前**每秒 −0.5 心**（−1 点，满血 6 秒毒死），5×5 生效起**每秒 −1 心**（−2 点，满血 3 秒）；重生保护与泡泡都不免疫；毒死按自杀口径（`Killer == Victim`），`PlayerDied.Cause` 需新增「毒圈」值——契约 v2 的 `Cause` 只有 0/1/2，扩值走契约修订（原型先以 3 标注 NON-CONTRACT） |
| 留火（火地） | 木头燃烧与火焰弹爆后留火，是炸弹实体留火阶段的覆盖范围（§7.3），**不是地面材质、也不是纯特效**——它扣的血是服务器权威伤害：**每秒 −1 心（−2 点）、可致死**，满血站 3 秒烧死。留火致死记 `PlayerDied.Cause = 2`；首版「燃烧」DoT 非致死故不触发该 Cause。ADR 0017 只改了燃烧的粒度，火地速率沿用原值未改——「3 秒烧死是否比炸弹还狠」进 §15 待验证 |
| 火焰（光环 / 火墙） | 火焰熊的火焰光环与组合技火焰冲刺的火墙（§8.4）：着火格内敌人**每秒 −1 心（−2 点）、可致死**，与留火同速率；致死记 `PlayerDied.Cause = 2`（燃烧），击杀者 = 施放者；施放者、重生保护中与泡泡中的玩家免疫；区域 Effect、零方块写入 |
| 血包 | 糖果池与补给战利品；回 1 心（2 点），满血不拾取留地 |
| 回血 | 只有血包、**棉花兔专属的回春**（§8.0 / §8.4，角色例外，ADR 0030）与厚棉花 L3 的脱战回血；其他角色不做自然回血——残血必须去找血包，溺水掉的血同样拿不回来 |
| 残血表现 | 本人：HUD 精确到半心，1 心时屏幕边缘红晕 + 心跳音；**他人只表现三档整心**（玩偶破损：完好 / 露线 / 露棉花）——六档破损在俯视 55°–65° 下不可读且美术量翻倍（B6），首版可用受击后 3 秒显示的小血条代替（进 B1） |

血量要制造的是「残血逃生 / 追杀残血」的张力：被炸一下不死，但一心残血在 100 人棋盘上跑向最近的血包或补给，是全局最紧张的 10 秒。

- **死亡**：血量归零即死 + 强化每级 50% 落地（§8.5，帽塔同步变矮）+ 拾取的技能每个 50% 落地（专属不掉，§8.2）。死亡瞬间的帽子、强化与技能糖飞散要做足表现——它是全场哄抢的发令枪（表现细节归美术，世界观基线见 [`../worldview.md`](../worldview.md) §2）。
- **重生**：常规阶段 **3 秒**（A/B 3 / 4 秒）后在动态出生点满血复活（§5）；决赛圈内不复活（§4.2）；带 **3 秒重生保护**（无敌 + 闪烁，**放弹即解除**——ADR 0017 把保护从 1.5 秒抬到 3 秒，而「放弹即解除」必须保留：否则三秒无敌会被用来冲进人堆放弹；施放火焰光环 / 火焰冲刺同样解除，ADR 0030）。
- **观战**：常规阶段没有死亡观战等待（支柱 3）；观战只存在于决赛圈出局后、决赛圈锁入期与结算间歇，最长约 115 秒 + 结算。

## 13. 结算与留存

结算分两段（共约 16 秒，推断待验证；原「12–15 秒」按用户 2026-09-25 要求加入领奖台后延长）：

1. **领奖台（约 10 秒，必做）**——成就感的来源，不能只是一张表：
   - 3D（或 2D 带角色模型）的领奖台，积木搭成，第 1 / 2 / 3 名分站中 / 左 / 右三级台阶，台面标名次数字与颜色（金 / 蓝 / 橙），**不只靠颜色**。
   - 前三名玩偶**戴着本局最终的帽子塔**站上去：第 1 名跳跃欢呼 + 皇冠 + 聚光灯 + 彩纸，第 2 名挥手，第 3 名拍手；其余玩家排在台下鼓掌，决赛圈出局者垂头。
   - 每级台阶上方显示名次、名字、帽数；本人上台时显示「你拿到了第 N 名！」，未上台时显示本人名次。
   - 镜头从全景缓推到台前（本段允许镜头运动，常规对局的「不给玩家旋转」不适用）。
   - 排名按 §4（ADR 0031）：存活者在前（时间到按帽数降序），出局者在后（出局越晚越前），并列同名次。台上站前三行、台阶标真实名次（并列时出现两个「1」，都戴皇冠）；同名次按玩家 id 排版。第 1 名 = 唯一存活者，或时间到时存活者中帽数最多者。
2. **结算表（约 6 秒）**：
   - **Top-10 榜**、本人名次与「击败了 X% 的玩家」、**帽王时长**（本局持有最高塔的累计时间）
   - 击杀数、放弹数、破坏方块数、拾取数、最佳连锁、最高帽数、角色、本局技能与进化（Stage 5）、结束方式（唯一存活 / 同 Tick 全灭 / 时间到）
   - **留局 / 下一局按钮**（倒计时结束自动下一局）与「换角色」（下一局生效；选角期间暂停倒计时）
   - 连胜提示

**首次游玩提示**只有三条，完成动作后永久消失，不做独立长教程：「放炸弹，炸开积木」「捡糖，让炸弹更强」「追光柱，抢最多的帽子」。选角界面每个角色一句话技能说明（§8.0），不计入三条提示。

**首发不做账号进度系统**（等级、皮肤解锁、赛季）。留存靠局内爽感和房间社交，不靠养成。**玩家可见的完整比赛回放首发不做**（ADR 0014）；引擎侧命令录制、State Hash 与故障复现回放保留为 QA / 可靠性能力，不等于产品功能。赛后回放作为差异化能力（[`../product-direction.md`](../product-direction.md) §4）进后续路线图。帽子皮肤 / 角色与技能外观类养成另被 A5 阻塞（见 §9.5）。

## 14. 平衡原则

1. **不许滚雪球**——糖果与技能等级有上限（§10），帽子零数值加成（§9.5）
2. **重生绝对公平**——棋盘四象限对称，动态出生点远离威胁
3. **运气可以有，但不能决定胜负**——掉落与技能糖是随机的，但强化与拾取的技能都能靠杀和抢易手：财富分配由冲突决定，不由掉落决定
4. **死得快不如死得明白**——每次死亡玩家都要能立刻看出"我被什么炸死的"，爆炸范围与留火必须画在地面上，死亡回顾必须列出来源（§7.5 / §9.6）；每次掉心同理，燃烧要有倒计时
5. **技能是流动的不是终身的**——拾取的技能与组合技死亡时按 §8.2 落地易主；否掉绑定 / 不可掉落的拾取技能；唯一例外是角色专属技能（身份不是财富，不计帽数，ADR 0030）
6. **同一套规则从 8 人到 100 人**——数值不随人数改变，只有地图随人数缩放
7. **爆点可以有，但必须有时限、可反制、来源可争夺**——狂暴糖 6 秒有界、不免疫他人、只出自中央补给；否掉常驻或不可反制的强化
8. **表现可以像无限，实现必须有界**——活跃炸弹、掉落物、表现对象都有配置上限；任何「无限」都有服务端预算
9. **排名只有一个公式**——先看有没有活到最后，再看帽数（§4，ADR 0031）；不加双倍分、不扣落后者分，任何阶段都不引入第二计分公式（ADR 0025）
10. **角色只换打法不换数值**——四个角色基础属性完全相同，差异只在一个专属技能；否掉角色专属数值加成、角色解锁与付费角色（ADR 0030，约束 7）

## 17. 遥测与门槛

逻辑层从 Stage 0a 起就产出遥测（ADR 0013：数据优先）；事件定义归本仓玩法层，Sink 归宿主。

### 17.1 玩法事件（必埋）

```text
match_join            first_move            first_bomb_place
first_block_destroyed first_pickup          first_damage_taken
first_damage_dealt    first_kill            powerup_picked
powerup_dropped_death hat_king_changed
supply_announced      supply_opened         death
respawn               match_end             next_match_stay
water_enter           water_exit            drown_death
final_circle_start    ring_shrink           eliminated
final_chest_opened    powerup_dropped       poison_death
character_select      skill_cast            skill_pickup
skill_pickup_rejected skill_evolve          skill_dropped_death
regen_heal            ring_clear
```

事件至少携带：`matchId`、`playerId`、`tick`、`elapsedMs`、`zoneId`、`hatCount`、`health`（半心点）、`bombPower`、`bombCapacity`、`movementSpeedTier`、`joinElapsedMs`、`characterId`、`skills`（三槽技能与等级）、`killer / source / chainId`（适用时）；`match_end` 另带 `endReason`（sole_survivor / all_down / time_cap）、`survivorCount`、`rank`。

**强化经济指标**（帽子 = 强化数，ADR 0028；改规则前必看）：每分钟发行量（砖 / 箱 / 宝箱）、玩家持有总量、地面总量、一次死亡平均掉落量、被击杀者掉落被敌人捡走的比例、帽王持有比例、顶到上限的人数、每局帽王更替次数。

**技能与决胜指标**（ADR 0030 / 0031）：每局技能糖发行（木箱 / 宝箱 / 死亡）、拾取被拒次数、进化次数与各组合出现率、各角色选择率与胜率、各技能释放次数与致死占比；结束方式占比、时间到时存活人数、平均局长、毒死占比、1×1 可进入断言。

### 17.2 性能指标（必埋）

Tick P50 / P95 / P99 与 Overrun；每秒放弹、引爆与最大活跃炸弹；连锁宽度、深度与单链体素写入；每秒体素批量修改数；权威拾取对象数；每连接 AOI 实体数与复制字节；Snapshot / Delta 比例、Resync 次数；客户端可见特效、粒子、音源与 Draw Call；服务器与客户端内存趋势。

### 17.3 首轮门槛（内部决策线，不是行业基准）

| 维度 | 首轮门槛 |
|---|---|
| 目标理解 | ≥ 80% 新玩家 30 秒内正确说出胜负目标 |
| 首次行动 | 首次放弹中位数 ≤ 10 秒 |
| 进入循环 | 首次拾取 ≤ 15 秒，首次受伤 ≤ 25 秒，首次击杀 ≤ 45 秒 |
| 帽王戏剧 | 每局（≤ 7 分钟）帽王更替 3–6 次；至少一次 10+ 帽倒台 |
| 决胜 | ≥ 85% 局以唯一存活者结束；时间到结束的局存活人数中位 ≤ 2；平均局长 ≤ 7 分钟 |
| 角色平衡 | 各角色胜率与 25% 的偏差 ≤ 10 个百分点 |
| 留局 | 首次测试 ≥ 60% 玩家自愿留满 3 局，后续按样本扩大复核 |
| 死亡可解释 | ≥ 90% 玩家能从现场或回顾判断主要死因 |
| 新人保护 | 中途加入后 5 秒受伤率 < 10%，20 秒内完成一次有效行动 |
| 稳定性 | 100 Bot 30 分钟无崩溃、无状态发散；6 小时无持续内存增长 |
| Tick | P99 ≤ Tick 周期 80%，Overrun < 0.1% |
| 无障碍 | 关键目标不只靠颜色；震动 / 抖动可为 0；通过光敏检查 |

「留满三局」不达标时，不先加账号成长与签到奖励掩盖问题；先判断核心循环是否真的提供了第二局理由。**用户测试从灰盒阶段开始**，由真实目标玩家测试，观察行为、不在现场替玩家解释；问题按影响排序并附录像证据。
