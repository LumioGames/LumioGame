# 帽王乱斗房间与机器人补位

> **状态**：实施中
> **适用范围**：当前正式测试服 Legacy8 / 19×19
> **上游**：[玩法策划案](design.md)、[工作区边界](../../../.spec/knowledge/standards/repository-architecture.md)

## 玩家流程

玩家通过正常平台登录进入现有 DS 房间。空白加载入口替换为房间页面：连接中显示“正在进入房间”；连接成功显示真实名单、真人与机器人数量、总人数和席位上限。选角放在房间内，人数未齐时留在房间，不展示不能操作的对局地图。

房间默认等待真人。玩家点击“机器人补齐”后，DS 每 3 秒加入一名机器人，姓名依次为 bot001、bot002 等。点击“等待真人”停止后续补位；重复点击不能加速补位或产生多个计时器。满 8 人停止添加，按既有 Warmup 进入对局。

数值来源：8 人 / 19×19 引用当前用户指定的交付档位；3 秒间隔和 botxxx 命名引用 2026-10-12 用户指令；默认等待、手动补齐与替换空白入口引用同日用户确认。bot001 的三位序号为该命名的具体呈现。

## 权威状态与行为

房间即现有 DS World；不另建匹配服务。名单、人数、补位开关、补位截止 Tick 和对局阶段来自 DS 复制。界面只发送合法输入意图，收到权威确认后更新。倒计时以权威 Tick / tickRateHz 计算，不用浏览器时间产生机器人。

机器人由 DS 创建为真实游戏实体，进入同一空间和玩法系统，使用正常移动与放弹 Ability，遵守碰撞、引信、爆炸、伤害、死亡、重生、缩圈、结算和下一局。机器人身份明确显示为机器人，不伪装平台账号或制造准入票据。真人仍需正常平台准入。

## 房间页面

- 显示“等待玩家 N/8”、真人数、机器人数量及 8 个席位。
- 每个占用席位显示真实复制的名称与角色；机器人显示 botxxx 和机器人标记。
- 默认说明“等待真人加入，也可使用机器人补齐”。
- 补位时显示“机器人补位中，下一名将在 X 秒后加入”；满员后改为开局倒计时。
- 连接失败或房间拒绝显示明确错误及正常重连入口；不得把失败显示为已入房。
- 阶段范围与未验收项保留在紧凑说明中；加载内部术语不作为玩家主界面。

## 验证标准

默认单人等待超过补位间隔不会增加机器人；手动启用后逐次间隔与命名符合规定，停用与重复点击有效，真人同时进入时不超过容量。正常浏览器独立完成房间、补齐、开局、移动、放弹、完整结算及同房下一局；每一项保留真实 DS 与浏览器证据。构建或进入地图不能替代战斗验收。
