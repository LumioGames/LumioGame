This review reads the six private drafts, all five existing-file diffs, nine preserved dependency before-images, actual RED log/JSON/raw exit, existing production consumers, current Game specification/ADR0048 and official07 Runtime APIs/public Voxel contract. **Verdict: narrowly implementable Game-owned first-wave design, but revision02 quality HOLD for two concrete P2 source defects below.** The existing public contract supports atomic block+binding mutations and Original-only settlement; no Engine contract change or new Native slot is needed by this proposal. ## Findings

### P2-1: three new material/revision reads bypass the shared two-layer Tick photo

`BomberIceBridges.Server.cs.draft:500` directly calls `adapter.Read(rowsAddresses)` on every Tick through `Begin:56`. The matching Original path then performs a second subset read at `ValidateAppliedBatch:307`; the rejection path separately reads its subset at `Reject:368`. Ordinary `BomberTerrainRead.For` calls at Ice `End:158,210`, Round and other processors only cache the complete read made inside their own `ForTick`, so neither earlier subset read populates that cache. A normal Original acceptance Tick with an existing owner performs the owner subset read, accepted cohort subset read, and then the full `width*depth*2` photo. Even an idle Active bridge adds an owner read every Tick.

This conflicts with `docs/specs/bomber/stage0-kernel-contract.md:241` and `.spec/knowledge/standards/repository-architecture.md` terrain seam: frame-start one complete two-layer photo, reused throughout the frame. Revision02 preserves Root's existing Regeneration photo fix, but the new Ice code bypasses it. This is a source-path finding, not an executed candidate Native count.

Minimal correction: authorize the additional private `BomberTerrainRead.Server.cs` domain. Add a narrowly guarded bridge-owner observation entry that first validates the full persistent owner set, runtime header and every corresponding pending tuple; it may read only committed Native facts through the existing same-Tick/same-adapter complete `ForTick` cache. It must not clear debt, settle success or enable ordinary rules. Add a bridge-only Original entry used only after the existing complete transaction, null operation, prior submitted Tick, current match, status/Applied/Original/token and receipt section/byte/revision guards. Make owner, Original and rejection material/revision checks pure indexed reads from that one photo. Keep `For`'s ordinary pending gate and the existing Regeneration kind guard. Preserve actual `BindingGet` validation; this slice concerns material/revision batching, not a claim of zero binding ABI calls. A real forwarding-ABI count regression should witness first freeze Original, active owner and water Original paths.

### P2-2: an already committed water cut can outlive the occupant Fuse before its Original is consumed

Revision02 holds only the original Freeze source (`Begin:58–59`, `RequestContact:101`) and checks that hold only in the later Danger/Burn retirement loop added to BombSystem. It does not guard the earlier due-Fuse queue/`FuseElapsed` loop. Once Native has accepted the WaterPending mutation, withhold its Original beyond a colocated ordinary/Frenzy FuseEndTick or Remote fallback deadline. Ordinary `BomberTerrainRead.For` remains unavailable because the debt is pending; `BomberSplitBombs.ExtinguishWater` cannot run and only covers split children in any event. `ProcessBombs` still sends real Native `FuseElapsed` and explodes the occupant. A later bridge Original calls `Occupants:464`, which selects only **current Fuse** rows, and therefore omits that bomb or finds it already retired. This violates the actual-water all-unexploded-bomb extinguishment/refund boundary in ADR0048, design§5.3 and core§6.

The existing11does not exercise this case: its withheld window is3ticks and it explicitly requires the occupants' Fuse deadlines to remain future. The candidate plan accurately labels the long-delay frontier unproved, but source inspection reveals a concrete missing guard; it is not yet an actual Native RED for this candidate.

Minimal next step is a real Native regression extending only the withheld water interval past a genuine occupant deadline, preserving the stored matching Original, full identities, journal, inventory/Frenzy and no-early-refund assertions. A bounded production fix can derive a **temporary eligibility hold** from the exact WaterPending owner plus its verified current committed water/null-binding photo and the occupant's actual cell, then check it before both initial due-Fuse admission and the final `FuseElapsed` send (including a subsequently chained bomb). Do not change FuseEndTick, write a phase, grant inventory, consume a receipt or extinguish before Original. At Original consumption use the existing real Native Extinguish/refund path. If the photo still shows the pre-mutation ice cut, or debt is rejected, the hold must not assume water success. This requires Root authorization and TDD separately from the photo-only repair; it must not be silently folded into a formatter/rebase change.

- The StrongChest sixth domain is necessary. Its existing missing-chest-policy branch replaces the complete policy with a chest-only list. After Ice establishes1031's policy this would erase Ice and possibly Barrel qualification. Concatenating the missing chest entry preserves existing entries. InitialResources already preserves unrelated policy entries and needs no change. `TrySetBindingPolicy` derives declared live candidates from the actual World; the candidate does not inject a fabricated candidate list. Existing policy conflicts are rejected.
- Freeze input comes from actual Trace/Resume contacts; Standard/Freeze Danger do not supply melt. Retained Fire requires ReservedFire plus a currently live Danger/Burn window and actual recorded reaches. Transient contacts are collected before birth, persistent melt latches survive pending/Unknown, and same-Tick losing Freeze does not issue a structural order. Favorite trail/FireZone producer remains explicitly absent.
- All23JSON properties are required by count plus typed unknown-property rejection; duplicate properties, nulls, byte/row overflow, duplicate token/generation/cell/fullBridge, noncanonical/full foreign IDs, bad phases/clocks/header/source tuples and orphan publications reject. All rows and all corresponding pending detail columns are validated. Canonical transaction numbers are bounded by the recorded allocation high-water. New generations use checked `max(1,observed,runtime)+1`; source identities retain exact original Life/generation/Participant/chain and are not rebound to a successor. The captured accepted source may naturally retire; Birth/FrozenPending still require its actual source.
- Creation/debt is saved before structural issuance or Native stage; absent observed publication remains owned without timeout/recreate. A full bridge is observed by token and checked against generation/match/clocks before binding. Atomic freeze is water+empty-binding to ice+exact bridge; melt is ice to water+null-binding at the same explicit revision. Bridge settlement bypasses ordinary chest reward/statistics/dig-destroy rules. `Staged` and Unknown are not credited as Applied.
- The eight-second clock is assigned exactly once from the durable successful stage Tick, not delivery Tick, after matching Original acceptance; checked conversion uses the actual configured Tick rate. Repeated Freeze finds the existing owner and does not extend its clock. Late freeze acceptance with an already due deadline goes into owned melt at End. Prior transaction/generation/bridge correlation and the single pending header prevent an old Original from selecting a replacement owner.
- On actual water Original the entire bridge cohort and every actual Fuse Native HFSM projection are validated before accounting. Existing `BomberBombLifecycle.Send(Extinguish)` handles the current stable fullID-ordered Fuse occupants; Danger/Burn are excluded. Existing `ReturnBombCapacity` retains original current-Life/generation guards; Frenzy only marks capacity returned and remains under its original participant ledger, rather than minting ordinary inventory. Bridge destroy follows its persisted retirement witness; credit is released only after its exact full row disappears.
- Hydration performs pure all-row checks and keeps `requiresActiveResumeSupport`; Native owner phase-cut validation occurs on Begin. Results ending latches an owned melt and Round waits until the bridge debt/publication/retirement clears before restoring the map. No string-clearing shortcut is introduced.

The source checks above are static findings, not runtime acceptance. In particular, multi-row atomic side-effect failure, all paired recovery cuts, structural Unknown interruption, rejection/stale revisions, source-credit saturation, long withheld results, real kick/movement, Favorite trails and the official19/23/27 producer set remain unexecuted for this candidate.
