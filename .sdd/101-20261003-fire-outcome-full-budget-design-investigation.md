## The exact semantic trace that must survive

Fire has two different algorithms in one root. `Gameplay/BomberFireReducer.Server.cs:19–48` executes participant-major order. For each actual roster slot it reads FireFacts presence/count, captures five correlation values once, scans results in vector order, retains the **last** six-part match (type, full World/Instance/Generation, target, source), then performs exactly one real `Claim` and `SetAt`. There is no early pending-status guard. A nonpending or corrupt row matching a retained result must still reach the original Claim refusal. `:49–86` then processes Aura results in ascending order; these reads observe all preceding fire-status writes and each preceding Aura mutation.

Outcome `Gameplay/BomberOutcomeReducer.Server.cs:51–90` independently searches three channels for each participant: last Initial/Applied/CrossedZero damage-or-burn result; last Initial10105 result regardless of outcome; last Initial/Applied10105 result. Has<PlayerState> and participant association precede type/outcome tests for **every** visited result, including irrelevant types. Selection is before the later full correlation. A later candidate that fails full correlation still shadows an earlier candidate: moving acceptance into the search changes behavior.

The remaining trace is lethal correlation and possible11 writes (`:91–165`), then seven applied-restore witness writes (`:166–176`), then five last-restore receipt writes (`:177–185`), then the next participant. The applied and last-restore channels can name different results. For example earlier Applied A followed by later Rejected B publishes A's target/restoration witness but B's full handle and restoreOutcome2; one “last restore” register is insufficient. `:188–237` runs the final-circle census/deadline after all participant publication, even on an empty result vector; winner ties retain the original roster order.

Settlement's prior ambiguity refusal must remain before its status write: `Gameplay/BomberSettlementReducer.Server.cs:35–50` scans target rows, marks duplicate targets, then deliberately claims with default owner to refuse. Outcome's damage lookup is a **different** scan: it keeps the last full handle+target row and checks status/full hit/fact participant+generation (`BomberOutcomeReducer.Server.cs:98–119`). Do not conflate these algorithms or remove the16-row scan because an internal association already knows a row.

`EffectOperationClaim.cs:30–68` requires the actual retained association, exact row object/owner/index, pending status, current invocation and every original immutable column/storage identity. `EffectFactAssociation.cs:139–153` checks full handle/type/target/source/AppliedTick/Ordinal/actual settlement Tick/Initial/outcome, keys, completed certificate or original rejected reservation. No new receipt may substitute for this certificate. Claim and SetAt must stay in one finalization-root invocation; this design transfers no claim.

Faults are part of the trace: earlier successful Game writes and consumed work remain; an original failing read/claim/hook suppresses later participant/match publication. No rollback, retry, acknowledgement or completion is invented. Native result uniqueness in a healthy stream is not permission to replace the required last-selection or malformed-association behavior.

## Smallest owning Runtime algorithm: ordered batch selection registers

**Proposal for Architecture/Runtime ownership, not an existing07 API:** provide an Engine-owned, batch-scoped *ordered selection group* to generated operation programs. It is deliberately a tiny index constructed by the existing original search, not a global result dictionary, result copy, ECS shadow row or durable Game truth. It permits bounded root decomposition while preserving all current source reads. There is no quota or public limit increase in this proposal.

The group is a startup-frozen descriptor of its exact scalar captures, channels, ordered member root IDs, source operation positions and contiguous result intervals. Generation creates it from a single verified original Reduce graph. Author code cannot construct/serialize an arbitrary token or read another group's storage. The only needed new operations are:

- **Begin/capture** at the original source position: bind World incarnation, actual Tick, result batch generation, frozen group identity, outer roster count, current participant and the captured scalar inputs already read by the source. Initialize each channel to absent. Fire has one channel; Outcome has three. Do not capture a Result value, fact certificate or claim. Do not reread Fire keys at every window boundary.
- **Step/remember** for each actual result in original vector order: run the exact original predicate graph; then update the appropriate channel(s) to the actual `ResultAt` reference when the source originally assigned its local last index. Advance a checked cursor. No predicate is replaced by a claimed business receipt. Result-derived candidate is certified by current lease and current vector bounds; no authored constant/result constructor or Native ordinal is accepted. Fire steps preserve its six comparisons. Outcome preserves original Has/read/association then type/kind/outcome/CrossedZero order.
- **Redeem** after the full scan: check the group/owner/World/Tick/batch generation/member position and complete cursor; absent stays absent, present loads the selected actual vector entry under the *current* root lease. This is O(1) lookup of a previously certified index. It creates no claim. Fire then executes the unchanged complete Claim/SetAt; Outcome then executes its unchanged full lethal/restore correlations and writes.
- **End** only after the original participant finalization, then start the next roster slot. Clear/invalidate the group in F's finally path on any fault and at result-window disposal. There is no save, restore, network projection, subsequent-Tick use, replay or callback of the selection group.

This is the missing cross-root capability expressed as explicit construction/search. It **does not reduce O(P·R) predicate work**: every original iteration still runs. It changes only the placement of typed Engine scratch and the root work boundaries. A generic hash lookup that skips Outcome's Has/Player.participant reads cannot offer this same trace contract; do not add such a shortcut under this proposal.

### Source-equivalence proof obligation

For participant p, let S[k] be the original source locals after visiting vector prefix0..k-1. Inductively the group stores exactly the same captured scalars and last-index channels as S[k]. Begin establishes the original -1/absent state; Step executes the same source predicate and replaces precisely the original assigned channel with index k; no-match leaves it unchanged. Concatenated consecutive windows visit each actual k exactly once and in order. Redeem reads precisely the same actual entry as original `c.Result(lastIndex)`. Finalization is unchanged. End occurs after the original participant's writes; the next participant's reads remain after them. Fire Aura roots begin only after all Fire claims/statuses. Thus the sequence of ordinary storage reads, Result projections, Claim/SetAt, ordinary writes and hook calls is preserved; new operations touch only charged internal Engine scratch between those operations.
