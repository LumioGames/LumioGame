## Why inventory, chain damage, RNG and Native mutation counts do not close a small Q proof

`BombSystem.Server.cs:254–282` first resumes every retained terrain source, processes all due/chain sources, reserves all contacts and submits every distinct family before F. `ReserveBlastContacts` filters phase/protection/Bubble/full identity, but does not read a per-chain pre-admission health budget. `BomberDamageEffect.CanSettle` checks health/actual dependency at F. Death removes/refuses later outcomes only after those pending snapshots, identities, result credits and fact certificates have been acquired. Native chain propagation rewrites the ChainId, while family owners remain distinct. A shared chain is therefore not a pending-request deduplication key.

Fuse inventory is tightly counted by `BomberInventory.Available`: current ordinary Fuse rows not yet CapacityReturned. Native FuseElapsed returns it; old Danger/Burn held on terrain/ice/fire facts no longer spends it. Public `PlaceBombAbility.HasFuseBombAt` checks only Fuse, not an expired-window held Danger at the same origin. Placement reservations impose the actual per-Tick/terrain/inventory guards, but do not impose a lifetime bound on accepted terrain cursors.

The128 Initialize/Clear mutation limit is a different operation bound.

A fully Game-owned delayed-history diagnostic is therefore required before excluding these families: withhold an **actual captured Original** for a first destruction elsewhere; repeatedly publicly place/move away/let inventory return from later sources at still-soft barriers; preserve their Unstarted cursors after Danger; deliver the first Original when an authored FinalCircle clear is already due. `FinalCircle.Advance` executes before `ProcessBombs`. The competing frame/pending transaction keeps later arms retained; after genuine Native clear/Original, all cursor sources can traverse the empty lanes together. No Native receipt or successful fact may be fabricated. This is a concrete source route defeating a64/128 damage-family cap, but its largest numerical jointly reachable cohort is **UNRUN and not asserted as B** here. Config Fuse/Danger, match/final-circle schedule, spawn chest/clear flags and per-Tick placement overlays must be loaded, validated and recorded, rather than assuming default16 or timing relationships.

The public placement draft uses actual skill pickup and existing attribute maxima6, avoiding fabricated inventory and an assumed all-source public placement rate. For resident legal producer histories, each player finite type has at most one nonexpired row after F, and at most old+new2 transiently during the next boundary. ## Accepted Favorite future-slot obligation

`CanReserve` currently reserves whole regional **entity** duration and global entity census, then checks static L/Q/C/I/Due/R/PerTarget lower floors. It does not reserve future pending snapshots/facts/result credits against the competing sources. `Prepare`/Submitted precedes irreversible Create/Apply, and known rejection/Unknown correctly retains or releases its existing ledger, but that commitment ordering does not make the future110 birth slots available.

There are two implementable Game-owned proof routes; neither uses a second GAS queue or rewrites Runtime:

1. **Cohort guarantee:** validate every loaded source budget, source/no-refusal pending envelope, residence/control/identity/result/fact/projection budget and complete generated reducer extent before opening Favorite. The same bounded P/B/Z/lease invariants hold on every future birth Tick. At the earliest purported resource refusal, all admitted workload remains inside those declared capacities, so each owed birth can acquire its real Runtime snapshot/handle. Unknown closes a lease's further emission while preserving its whole reservations; source death closes new births without clearing existing accepted contacts or regions. This proof is unchanged by a later bomb refill because B was charged from the beginning.
2. **Durable shared source-credit ledger:** every Game producer that can create a future mandatory GAS obligation charges the same Game-owned credits **before** admitting that obligation. This includes bomb family/target exposure capacity, promised barrels/Split/Frenzy before their irreversible source commitment, successor/reset facts and whole Favorite lease births/residence. All producers respect held Favorite credits; purely per-Tick counters reset only at a confirmed ordinary F boundary and restore with the same supported cut. Requests/handles still live only in Runtime; the ledger is reservation ownership, not a replay queue. An already accepted Original contact cannot be refused simply because another caller spent its reserved capacity. Global source-credit release requires genuine retirement/result evidence. A Favorite-only pending counter, or giving births priority while discarding competing owed contacts, cannot prove this route.

The whole-cohort route is the concrete capacity proof this delivery develops. The source-credit route requires broader independently reviewed Game owner changes; no partial production patch is proposed here because all producer commitments must participate. The present static264/704 gate proves neither. All false paths must precede cast cooldown/protection removal/inventory/statistics/NextChain mutation. Do not “reserve” by spending any of those and then refuse later. The early accepted-lease Native test accepts a real public Favorite first, keeps its source healthy outside the blast, and examines its third owed birth when a competing25×7 production cohort demands350 slots. It records the exact retained lease and lifetime handle after any actual rejection before asserting success.
