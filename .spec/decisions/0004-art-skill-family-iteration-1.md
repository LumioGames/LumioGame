# 0004 · art-* 技能族第一次迭代:骨架对齐实际文档、技术合规门禁前置

- 日期:2026-08-28
- 状态:生效

## 背景

art-* 技能族([0001](0001-art-director-skill-family.md))是初版,首批美术规范落地后暴露出四处与实际不符:

1. **骨架与实际文档完全对不上。** art-bible 规定的骨架是一套通用手游美术宝典(色彩系统 / 2D UI / 原画 / 特效 / 3D 场景),而实际的 `docs/specs/art-direction.md` 是围绕本项目关键决策组织的(方块尺寸 / 相机俯角 / 角色朝向数 / 接地阴影)。**这套「体素 + 2D 角色 + 俯视」组合里最要命的几个决策,骨架里一个都没有。**
2. **art-review 的门禁顺序把最可判的一层放在最后。** 原顺序 L1 风格 → L2 可读性 → L3 技术合规,但技术合规(尺寸、压缩、图集、命名)是机器可判且最致命的——尺寸就不对,风格评得再细都是白评。
3. **P2 存在循环依赖。** 「各域细则由该域首个过审资产反推成文」,但 art-review 审查依赖规范,规范又等资产过审,环没有出口。
4. **平台框架与产品定位不符。** 硬约束速查通篇按移动端写,而本仓 Windows 优先、移动端后置;且规范里的数值(触控热区 ≥44pt 是标准引用,粒子数上限是推断)可信度差一个数量级却无从区分。

## 决策

- **art-bible 骨架重构**:新增「2 世界与呈现」(相机投影与俯角、世界单位 / 方块尺寸、角色比例与朝向数、高度表达、接地策略)并声明为本仓地基——这些参数互相咬死,任一改动会让已产资产作废,必须先于任何域细则锁定;新增「0 唯一目标」「4 反面清单」「11 待验证项」,五大域细则降为 P2。
- **art-review 门禁重排**:技术合规提到 L1,风格一致性降到 L2;设计稿阶段 L1 只查可机器判定的部分,资产阶段查全部。与 [0003](0003-design-director-skill-family.md) 的 design-review 保持同一取向(可判者先行),闭合 0003 中「art-review 是否跟进调整留待其迭代时决定」。
- **临时基准升格机制**:art-review 降级模式用的临时基准,一旦对应资产过审,由 art-bible 当场写成正式条款并注明「由 <资产> 反推」——这是 P2 细则的唯一合法来源,循环由此打开。
- **数值来源纪律扩展到美术**:每条带数值的规范标注「标准引用 / 实测 / 推断待验证」,与 design-doc 同一取向。
- **平台框架改为 Windows 优先**:硬约束速查标 `[M]` 区分移动端专属条目,其余两端通用。

## 后果

- art-bible 的骨架从「通用手游模板」变成「本项目形状」,通用性下降、可用性上升;若未来产品形态改变(非体素、非俯视),第 2 章需随新 ADR 重写。
- 五大域细则降为 P2 后,美术规范在首批资产产出前会保持较薄——这是有意的,避免空想规范。
- art-* 与 design-* 现在共享三条机制(可判者先行的门禁、数值来源纪律、临时基准升格),后续两族迭代应保持同步,分歧须记新 ADR。
