# 0027 · 炸弹人吃一个强化铸一顶帽,帽子塔同时表示「谁最富」

- 日期:2026-09-25
- 状态:被 0028 取代

## 背景

用户 2026-09-25 试玩 101 网页原型(ADR [0024](0024-per-game-directories-and-101-web-prototype.md))后问「为什么只有一顶帽子」。现行规则(ADR [0011](0011-bomber-100-player-io-gear-slots.md) 起、0014 重申)是帽子只来自击杀:三颗心下要命中 3 次才算一次击杀,原型无界面实测一局 150 秒里敌对命中 12 次、击杀 4 次、全场只铸出 4 顶帽子,多数死者头上是 0 顶,散落也就散不出东西,玩家读到的是「帽子不掉落、帽子很少」。

用户定调:**吃一个技能(强化)加一个帽子,这样才能知道某个人富有;死亡也会掉落帽子。**

## 决策

- **新增铸帽通道「吃强化 = 铸造」**:每吃一个火力+ / 炸弹+ / 速度+(含死者掉出的与决赛圈宝箱喷出的)+1 顶帽,铸到拾取者头顶;血包不是强化,不铸;强化已达上限而不能拾取时不铸。配表 `hatsPerPowerup = 1`(推断待验证,A/B 0 / 1)。
- **击杀铸造与死亡全散保留**:击杀仍 +1 顶;死亡时头上帽子全部散落可抢(ADR 0025 的死亡掉一半强化同样保留)。帽子因此同时是「发育财富」与「战斗掠夺」的读数,富有的人更显眼、也更值得杀。
- **修订的旧条款:** ADR 0011 / 0014 与 `design.md` §8.6「帽子只来自击杀」、§9.3「帽子不随技能等级增加」、§9.5「帽子只代表击杀与掠夺」——改为帽子随**吃到的强化**增加,但仍**不随装备技能等级**增加;补给与宝箱本身仍不直接出帽子。
- **锁与不锁:** 锁「吃强化铸帽 + 击杀铸帽 + 死亡全散」三通道结构;不锁每个强化铸几顶。

## 后果

- 帽子产量明显上升(原型一局约 40 次强化拾取 + 10–18 次击杀),帽子塔在发育期就会长高,「谁最富」一眼可读;帽王倒台的哄抢量随之变大。
- 风险:帽子更多来自发育而非对抗,可能削弱「炸人抢帽」的主线。由 `design.md` §15「吃强化铸帽」一项验证(目标:击杀 + 掠夺带来的帽子 ≥ 50%),不达标先调 `hatsPerPowerup` 或强化掉率。
- 原型实现:拾取当 Tick 铸帽,发表现事件 `HatMinted`(`VictimNetEntityIdRaw = 0`、`Count` 为顶数,NON-CONTRACT);帽子守恒账把两条铸造通道一起计入。
