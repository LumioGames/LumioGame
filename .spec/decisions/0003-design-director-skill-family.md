# 0003 · 策划总监做成 design-* 技能族而非子 Agent

- 日期:2026-08-28
- 状态:生效

## 背景

项目需要覆盖策划全域(玩法 / 系统 / 数值 / 关卡 / 商业化 / UGC)的「策划总监」能力,含四个功能:方向讨论与定调、策划案沉淀、需求翻译、方案评审。首批 7 份策划案已产出,但落点、骨架、数值来源纪律、验收写法等规范全是隐性的,只存在于产出当时的会话里。

`agents/` 的准入门槛是「隔离本身即是产出价值」(当前仅 `reviewer`),而策划顾问需要与用户同上下文对话,隔离有害无益——与 [0001](0001-art-director-skill-family.md) 对美术顾问的判断一致。

## 决策

- 以 4 个技能承载,与 art-* 技能族 1:1 对称:`design-director`(hub,讨论与定调)、`design-doc`(策划案沉淀与维护)、`design-request`(需求翻译)、`design-review`(方案评审);不新增子 Agent。
- 单一权威分工:六大策划域分类与**架构约束速查**在 `design-director` 快速参考;策划案落点与**数值来源纪律**在 `design-doc`;上游 ADR 判定速查在 `design-request`。
- 策划需求落 Workflow 平台(仓库已绑定 `lumiogamesengine` 项目),复用现成的 `workflow:*` 技能,不自建需求跟踪、不写 `.spec/tasks/` 任务卡。
- 相对 art-* 的两处刻意改进:审查门禁把**架构可行性提到 L1**(art-review 把技术合规放在 L3,意味着要先人工过风格与可读性才发现资产根本不合规);新增**数值来源纪律**,强制每个数值标注已验证 / 推断待验证 / 引用。

## 后果

- `design-review` 在主 loop 同上下文执行,无「写 ≠ 审」独立性——可接受,因其审查对象是策划文档而非本会话代码产出;未来若需对抗式策划评审,按准入门槛新增 agent 并以新 ADR 取代本条。
- 方向未锁定期间,design-request / design-review 以「显式标注假设」的降级模式工作,产出不具约束力。
- art-* 与 design-* 出现可对照的两套门禁顺序,art-review 是否跟进调整留待其迭代时决定。
