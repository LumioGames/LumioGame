# 0017 · 炸弹人爆炸与血量模型修订:炸弹实体持有火焰、血量改半心点、水改为可溺死

- 日期:2026-09-04
- 状态:生效

## 背景

与 ADR [0016](0016-bomber-terrain-out-of-ecs-3d-coords.md) 同批的场景讨论,在爆炸与血量两处发现已冻结口径的问题:

1. **爆炸格是每格一个 Entity。** `BomberExplosionCell` / `BomberExplosionCellEntity` 承载的是只活 0.35–0.4 秒(`dangerWindowMs`)的判定数据,而 [`design.md`](../../docs/specs/bomber/design.md) §7.4 估算 100 人满负载每秒 100–300 格破坏——意味着同量级的 Entity 生灭与复制。
2. **水盆使人绝对无敌。** `design.md` §5.1 写着「阻断爆炸:是(爆炸到水边停)」,字面即火焰停在水格之外;配合「水可通行、移速 −30%」,结果是站在水里永远炸不到。帽王在终局跳水即可锁定胜利,使 §17.3「六分钟内帽王更替 3–6 次」不可能达成,也使 §9.3 的帽王光柱指向一个打不到的人。
3. **整颗心的粒度不够用。** `heartsMax = 3`、伤害单位是整颗心,导致若干处口径互相矛盾:§12 的火地「每秒 −1 心」意味着 3 秒烧死、比炸弹更狠;§8.4 燃烧写着「最多追加 1 心**或**非致死」,两个口径互斥正说明整数粒度不足。

## 决策

- **删除 `BomberExplosionCell` 与 `BomberExplosionCellEntity`,火焰由炸弹实体持有。** 炸弹引信到点后不立即销毁,转入爆炸态:`ExplodedAtTick` 起至 `DangerUntilTick` 为火焰阶段(每颗炸弹对同一玩家最多命中一次,§7.5 不变),至 `BurnUntilTick` 为留火阶段(Stage 5 的火焰弹与木头材质),随后销毁。100 人满负载下同时存在的爆炸态炸弹约 12 个,取代原先每秒 100–300 个爆炸格实体。
- **十字用四个到达长度描述,不引入形状枚举。** `BomberBombState` 增加 `ReachUp / ReachDown / ReachLeft / ReachRight`,存的是**传播算完后的实际臂长**(已含地形阻断);客户端据此直接绘制火焰,无需重跑地形扫描,中途加入者也能看到进行中的爆炸。`design.md` §8.4 的五种炸弹形态(标准、冰冻、火焰、穿透、分裂)几何上**全部是十字**——分裂弹的子弹是 0.5 秒后独立的新爆炸、各自又是一次十字——故不设 ShapeId。形态差异用 `BombKind`(伤害与余烬语义)与 `PierceLayers`(遇软砖后可继续的层数)表达。
- **火地(留火)的伤害速率不在本 ADR 变更范围。** 背景第 3 条提到「每秒 −1 心 = 3 秒烧死比炸弹更狠」,但本 ADR 只改**燃烧** DoT 的粒度(改为每秒 −0.5 心且非致死);**火地沿用原值每秒 −1 心(−2 点)、可致死**,「3 秒烧死是否过狠」进 `design.md` §15 待验证。留火致死记 `PlayerDied.Cause = 2`。
- **留火是炸弹实体的第二阶段,不是材质、也不是纯特效。** §12 的火地每秒扣血是权威伤害,不能只在客户端。木头燃烧(Stage 5)在该格生成一个四个到达长度均为 0 的同类实体,复用同一条路径。`design.md` §5.1「区域 Effect,不改方块」的原意因此得以保持:留火不产生任何方块写入。
- **同弹命中记忆不进契约。** §7.5「同一颗炸弹对同一玩家最多命中一次」需按炸弹记录已命中集合,它不复制、不持久,落在服务端临时结构,不作为 Component 字段。
- **血量单位改为半心点。** `BomberPlayerState.Hearts: i32` 更名为 `HealthPoints: i32`,取值 0–6;config 增 `maxHealthPoints = 6` 与 `healthPointsPerHeart = 2`,`heartsMax` 退役。炸弹伤害仍是一颗心(= 2 点),语义不变。取代 ADR [0014](0014-bomber-v04-stage0-convergence.md) 重申的「三颗心」条款中的**表示方式**,三颗心的产品语义不变,只是内部粒度加倍。表现层 `hearts = floor(HealthPoints / 2)`;**他人身上仍只表现三档破损**,半心只在本人 HUD 显示——[`risks-and-engine-asks.md`](../../docs/specs/risks-and-engine-asks.md) B6 已把「8 向 × 3 态的美术量与 100 人下他人血量的读数」列为风险,六档破损在俯视 55°–65° 下不可读且美术量翻倍。§7.5「同一 ChainId 对同一玩家的结算伤害不超过其心数上限」改为不超过 `maxHealthPoints`。
- **「水盆」统一改称「水方格」,火焰覆盖水面第一格后停止。** 水是一种地面层方块,连片构成池塘或护城河;「水盆」一词全仓退役,含世界观与美术文案。火焰打到水会**覆盖该格**再停止、不再穿过——护城河作为地形屏障的设计意图保留,但站在水里会被炸到。
- **水中缓慢溺水。** 站在水方格中每秒 −0.5 心(−1 点),满血 6 秒溺死;离开即停止,且没有自然回血(§8.5 的血包与 §8.4 厚棉花 L3 之外)。溺死按 §9.1 已有的自杀口径结算(`Killer == Victim`),帽子走 §9.4 的全散路径。这使「躲水」从最优解变为最差解,且不新增任何规则。水原有的「进入即解除燃烧」「踢弹入水即拆弹」保持不变。
- **重生保护 1.5 秒改为 3 秒**(`respawnProtectionMs` 1500 → 3000),「放弹即解除」必须保留——否则三秒无敌可被用来冲进人堆放弹。
- **`design.md` §5.3 断言修订。** 删除「出生后 3 秒内不存在不可反应的夹击格」这条硬断言:它未被形式化因而不可机器判定,且重生保护 3 秒(可走约 10 格)、「距任一玩家与炸弹 ≥ 6 格」、L 形 3 格安全区三重保障已覆盖其意图。「掩体」定义为「相邻四格中至少有一个是硬砖的可通行格」,「3 秒内可达」按可通行路径长度 10 格判定(3 秒 × 3.5 格/秒),软砖全清后重算。两个密度指标只统计**可放弹格**(可通行且非水),水另由比例断言约束,并新增连片水域长度上限——现有三条约束(≤5% 格子、3–6 格池塘、不封死分区缺口)都允许一条贯穿全图的护城河。取消象限地色(材质目录不为纯外观差异加 4 行),方位语言由 §5.3 断言 8 已有的象限地标轮廓承担;B6 与 §9.6「关键目标不只靠颜色」也不支持纯地色方案。
- **锁与不锁:** 锁爆炸由炸弹实体持有、四个到达长度的表示、半心点血量与三档表现、水覆盖第一格后停止、溺水存在、溺死按自杀结算、断言修订。不锁数值——溺水速率、重生保护时长、掩体距离、连片水域上限全部进 Config 与 A/B 变体,按 `design.md` §15 的数值来源纪律标「推断待验证」。

## 后果

- 取代 [0014](0014-bomber-v04-stage0-convergence.md) 重申的「三颗心与『单发削血、连锁秒杀』」中的血量表示;三颗心的产品语义与手感目标不变。0014 其余条款继续有效。
- 取代 [0015](0015-bomber-stage0a-runtime-capability-finding.md)「六个实体类型与组件挂载」一条中关于 `BomberExplosionCellEntity` 的部分(其余五个实体类型不变);与 [0016](0016-bomber-terrain-out-of-ecs-3d-coords.md) 一并构成对 0015 该条的取代。
- `stage0-kernel-contract.md` 升 v1.1、`design.md` §5 / §5.1 / §5.2 / §5.3 / §7 / §8.4 / §8.5 / §9.1 / §9.4 / §12 / §15 / §17、`stage0-test-matrix.md` §2 / §3 / §6 / §7、以及 **G-1 / G-4 / G-5 / G-6 / G-7 卡**按本 ADR 改写。
- 半心点让火地、燃烧、厚棉花三处得以表述自洽,代价是全部血量相关数值要换算一遍,且实现者可能把 `HealthPoints = 6` 误读为六颗心——改名即为此。
- 水从「绝对避难所」变成「用血换时间的地方」:被追杀时可入水躲避火焰,代价是每秒半心且拿不回来。终局最后 10 秒跳水已不足以保命(6 秒溺死)。
- 删除夹击格断言后,出生点质量不再有生成器硬门;若 §17.3「中途加入后 5 秒受伤率 < 10%」在测试中不达标,须回头检查地图而不是直接调保护时长。
