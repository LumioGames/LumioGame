# 0049 · 炸弹人容器容量与本地候选 Schema

- 日期:2026-09-30
- 状态:生效
- 决策依据:Owner 已授权记录并修复引擎缺陷，以及继续候选集成；本决定不授权公开发布，也不表示整局验收通过。

## 背景

八观察者、两波正常放弹的 journal 回归测得单个 WorldChange 达 291408 字节，超过既定 65536 字节上限。上游在 ADR-137 明确容器容量声明，在 ADR-138 定义有界分片；Game 必须以成套候选消费新的 Runtime、Server 和 Client，并重建生成物。

## 决策

1. 官方 v0.0.4 发布物保持不可变。只在独立 Game 副本切换到验证通过的本地候选包，两端一起构建；产品候选身份和 Schema 与旧版本区分，不将候选用作已发布产品的原地替换。
2. 第一轮 19×19、8 人验收声明沿用当前产品边界：journal 128 条；结果保留 2 局、每局 8 人；炸弹命中记忆 8 人、接触宝箱 5 个；宝箱最多记 3 颗独立炸弹；放弹预留最多 361 格；待决体素事务 1 个、两层共 722 格；HFSM 路径分别以现有主图最多 7 状态、决赛圈 5 状态为声明上界。配表在绑定世界前与容量核对，超限明确拒绝，不截断。M2 地图/人数扩展仍需重新计算对应声明。
3. 容量是 Schema 的一部分；uint 持久化修复也必须反映在生成输出和审计中。新增明确的本地候选 Schema，并保存旧 v3 活跃身份的原形、证据和退休记录。旧 tombstone 不改写；审计支持可追溯、无环、所有者不变的跨版本替换链，不因候选迁移删检查或自动刷新基线。
4. Game 不实现容器或分片解码器。浏览器消费 Client 的公共重组器后走既有副本提交；回归加载实际生成的客户端程序集，检查每 tick 已提交 journal，保留事件身份、来源、顺序、保留期与过期断言。
5. 候选保持 `freezeEligible=false`。未完成的 Effect、恢复、后继绑定与整局验收事项继续显式记录，局部测试通过不解除其门槛。

## 验证与兼容

记录脏源码差异与哈希，通过官方 pack-release/verify-release 生成并验证独立候选。容器容量、异常事务原子拒绝、晚加入/重连完整基线和传输分片分别有回归证据，再运行真实八 Bot 诊断。旧持久化读取是否兼容以引擎提供的恢复路径为准；不假定新旧 Schema 可直接互通。
