# 0047 · 炸弹人 M2 保留中毒为第六形态，固定无等级数值与袋鼠最爱

- 日期:2026-09-28
- 状态:生效
- 决策依据:Owner 要求按今日原型更新正式版，并明确授权“剩下的你自己决定不要问我了”；以下是协调者依授权作出的正式迁移决策，不冒称原型已有实现或 Owner 逐项指定数值。

## 背景

ADR0041 选择一槽五种特殊炸弹，ADR0044 又明确保留中毒、加入第五角色并加强冰冻，但将中毒的 M2 位置留待定稿。无等级 M2 还需要单一冻结时长和袋鼠最爱。目标仍为 ADR0038 的易懂成长爽局：玩家只需选择当前一种炸弹，四分钟内能理解效果，避免多份中毒叠加造成难解释的持续掉血。

## 决策

1. M2 保持一个特殊炸弹槽，六种形态为火焰、冰冻、遥控、集束、穿透、中毒。中毒沿用相同来源、替换、同种留地和死亡掉落规则；池内六种等权。六种内容不增加槽位、等级或按键。保留其他五种的区别，不为保留中毒而删除另一种。此条取代 ADR0041 的“五种”数量与池权重；中毒保留本身来自 ADR0044。
2. 无等级冰冻弹固定冻结 **2 秒**，受伤解除与解除后 **1 秒**控制免疫保持不变。取 ADR0044 已采用候选区间的中值；不把旧三级继续暴露为隐含等级。泡泡鸭最爱破泡冻结仍为 **1 秒**，不随冰冻弹时长放大。
3. 中毒直击仍减 **1 心**；存活者获得 **4 秒**中毒，首跳在施加后 **2 秒**，末跳在 **4 秒**，每跳 **半心**，单次完整中毒共 **1 心**，可致死。每个当前生命至多一个中毒实例；已中毒时的新命中只结算本次直击，不新增、刷新、延长中毒，不改其原来源。泡泡或血包清除中毒；保留ADR0033的解毒例外：满血但中毒仍可消耗一份血包，回血量为零、正常解毒，满血且未中毒则不拾取。死亡销毁该生命的状态，不转给后继生命。周期结果仍保留原投弹者、炸弹与生命身份，来源实体销毁不改归属。
4. 飞腿袋鼠最爱 **穿透弹**。成功飞踢时，若当前槽为穿透弹，冷却 **3 秒**；否则 **4 秒**。作用于角色技，不要求被踢的炸弹属于本人或也是穿透弹，不改变炸弹主人、形态和滑行。无合法目标不进入冷却。冷却按成功施放时的槽位取值并固定，之后拾取、丢失或切换炸弹不会重置或缩短已经开始的冷却。
5. 其余角色技无等级基础值沿用 design§8.4 的 ADR0034 一级值：回春20秒、泡泡3.5秒/CD14秒、闪现3格/CD10秒、光环5.5秒/CD16秒。最爱组合是独立条件，不恢复旧合成或等级。原型旧三级数据只供历史与迁移测试。

全部数值为首轮候选，须经真实五角色平衡与12/23、16/27矩阵验证；“生效”表示本次实现依据已确定，不表示数值验收或正式玩法已完成。

## 同 Tick 边界

以下是游戏应提交的准入条件和控制意图，消费Engine的initial requests、duration/control、period、removal顺序，不新增游戏结算循环。解毒提交抑制和移除，抑制在period前生效，不能只提交末阶段移除而意外再毒一跳。每次中毒使用独立Effect完整身份，并与受害生命、原炸弹及参赛者关联；不能仅凭生命或技能类型匹配结果。同Tick确认解毒的生命本Tick不接纳新中毒，下一Tick恢复可施加；这一帧门防止解毒后立即被同批命中重新挂毒。

| 场景（假定直击后仍存活） | 预期 |
|---|---|
| 同Tick两次首次命中，来自A/B | 按既有确定性提交序号处理，首个成功中毒为唯一实例；两次合法直击各自结算，另一请求不产生中毒、不改变来源。只保留该实例的两次未来周期 |
| 原中毒最后一跳/到期Tick又命中 | initial阶段仍视原实例占用，不接纳新中毒；本次直击照常，原来源在period阶段最后扣半心，再由removal退场；本Tick结束无毒，下一Tick才可重新施加 |
| 应跳Tick确认解毒 | duration/control抑制该实例，尚未执行的本Tick周期不扣血，随后移除；未来跳数为零。已在更早Tick执行的伤害不回滚 |
| 解毒与新命中同Tick；下一Tick重施加 | 解毒帧的新命中只有直击、没有新中毒；下一Tick可生成新Effect身份B，其首跳从B的施加Tick计算。A的已执行结果仍须恰好处理一次，但不能清除、延长、重记B来源或转给新生命 |
| A的已发行结算结果在后续业务处理阶段才被消费 | 保留原Effect身份、dueTick及来源，按已提交事实完成统计/归属；状态清理必须比较当前Effect完整身份。不能因A已解毒丢弃已有结果，也不能把A的事实当成B的结果。结果借用期和复制到有界业务记忆的规则遵守Engine，不创建无限结果历史 |

这些边界须在真实phase9、结果消费和死亡屏障测试中证明；引擎尚未提供相应能力时保持未冻结，不能以手写字段或丢弃已接纳结果替代。

## 取舍与代价

- 不将中毒做成额外被动槽或所有炸弹附魔：那会增加并行概念，破坏一槽替换规则。第六形态只增加一条内容、一个剪影与 Bot 权重项，身份须保留并由 schema ledger核验。
- 不用叠层或刷新维持中毒：固定两跳更容易解释并限制单生命持续实例；重复直击仍有正常战斗收益。代价是连续中毒命中的附加收益下降，需观察选择率与击杀归属。
- 袋鼠最爱复用已有冷却参数与HUD，不增加穿墙、额外伤害或地形生产者。代价是强化主要由操作频率感知，需在选角和技能冷却上明确呈现。
- 六种池不会增加每次奖励数量；中毒至多参与人数个同时有效实例，仍须纳入完整生产预算、重复命中顺序和入场/死亡屏障验收。这里只给产品上界，不代替 Engine 容量证明。

## 后果与验收

同步 design§7.3/8.2/8.4/12/15 与正式收敛计划。已发布 ADR0041/0044 的决策正文保留历史，本 ADR只覆盖以上缺口。Game仍消费真实GAS Effect、WorldManager.Tick、Native HFSM和生成配表；不在游戏侧建立计时字典或手改生成物。

冻结前验证：六形态替换与来源数量守恒；冰冻2秒与鸭子1秒可区分；中毒Tick40/80两跳、同生命重复命中不续期、死亡和解毒取消后续跳、来源销毁不改归属；袋鼠无目标零冷却、成功时3/4秒、换槽不重置；技能关闭时不发行和不施放。20Hz转换仅用SDK，其他Tick频率按配置验证。
