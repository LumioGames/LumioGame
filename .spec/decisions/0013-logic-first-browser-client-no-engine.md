# 0013 · 交付顺序逻辑先行、表现最后接;后续客户端暂定浏览器,首发不接任何游戏引擎

- 日期:2026-09-04
- 状态:生效

## 背景

炸弹人 v0.4 建议稿把「Gate 0」定义为一条从输入到表现的全链路纵切,并按 8–10 人团队给出 14–16 周排期。对照 [`docs/specs/risks-and-engine-asks.md`](../../docs/specs/risks-and-engine-asks.md),A1 网络传输、A2 Rust↔C# 桥、A3 渲染与 Unity 工程仍标「阻塞 ①」;仓内策划文档与 [`AGENTS.md`](../AGENTS.md) 沿用架构 v1.4 §2.1 / §10 的口径,默认客户端是 Unity/HybridCLR,Windows 优先。若继续以「可玩表现」作为首个验证物,炸弹人会被引擎侧三项阻塞整体卡住,而玩法规则、帽子经济、地图生成、Bot 与遥测这些不依赖表现的部分同样无法开工。

用户 2026-09-04 定调:优先级是数据、稳定性、正确性;把所有逻辑先跑通,表现最后再接;后续客户端暂定浏览器,先不接任何游戏引擎。本仓已有先例:entity-chat 纵切(ADR [0010](0010-entity-chat-requires-mvp-host.md))先以 100 Bot 跑通权威链路,再接 1 个 Browser 页面。

## 决策

- **交付顺序 = 逻辑先行、表现最后接。** 任何新玩法先做成无渲染(headless)的服务器权威逻辑:确定性仿真、Bot 驱动、命令流回放、断言与遥测;正确性门与稳定性门在这一层通过后,才接客户端表现。表现层不得成为逻辑层的验收前置。
- **验证物的优先级 = 数据 > 稳定性 > 正确性证据 > 可玩表现。** 「跑得动、跑得对、可重放」先于「看得见」;玩法门(好不好玩)延后到客户端接上之后测,不以此阻塞逻辑层交付。
- **后续客户端暂定浏览器。** 客户端载体以浏览器为当前唯一方向;桌面浏览器优先,触屏浏览器不承诺。「暂定」= 可由后续 ADR 取代,但在取代前所有客户端侧需求只按浏览器提。
- **首发不接任何游戏引擎。** Unity / HybridCLR 路线降级为后续候选,不进首发、不建工程、不为其提需求;架构 v1.4 §2.1「Unity Host、HybridCLR Capability」与 §10 目标平台列表在本仓视为「后续候选平台」,不构成 ① 的前置。
- **公共契约不因此变更。** 浏览器宿主属 `LumioClient` 仓能力;架构 v1.4 §10 目标平台未列浏览器,登记为引擎侧需求(`risks-and-engine-asks.md` A3 改写),不在本仓改写公共语义。
- **锁与不锁:** 锁交付顺序、验证物优先级、首发不接游戏引擎;浏览器作为「暂定长期载体」锁到被新 ADR 取代为止。不锁浏览器内的渲染技术选型(归 `LumioClient`)、不锁移动端策略。

## 后果

- `risks-and-engine-asks.md`:A3 由「渲染与 Unity 工程」改写为「浏览器客户端宿主与渲染」,仍是 ① 表现层的前置但不再阻塞逻辑层;B1 的「抛弃型纯 Unity 原型」应对作废,画面验证改为逻辑层跑通后在浏览器渲染原型上做;B3 移动端改为「触屏浏览器不承诺」。`product-direction.md` §6 增「首发不接 Unity 等游戏引擎」;`AGENTS.md` 项目描述同步。
- 炸弹人切片按本 ADR 重排:Stage 0 拆为 0a(headless)与 0b(浏览器客户端),见 [0014](0014-bomber-v04-stage0-convergence.md)。
- 代价:逻辑层交付期间没有可玩的东西给人看,玩法门与手感验证整体后移;美术 B1「好不好看」的验证也随之后移,风险在于画面问题更晚暴露。接受这个代价,换取不被 A1–A3 卡住。
- 代价:架构 v1.4 以 Unity 为默认客户端的假设与本决策不一致;若架构侧后续要求 Unity 首发,须新 ADR 取代本条。
