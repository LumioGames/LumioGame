# 0006 · 炸弹人核心循环改为帽子计分乱斗,会话模型改为滚动房间

- 日期:2026-08-28
- 状态:被 0011 取代

## 背景

首发产品 ①(体素炸弹人)的原设计稿采用经典淘汰制:最后存活者胜、明确不做局内重生、房间码开局制、150 秒死亡收缩逼终局。用户为首个游戏定调时提出「帽子」机制——击杀掉帽、捡帽垒高、帽王显赫并招致围攻,另可从宝箱获得帽子——并要求会话尽可能简单:服务器一局接一局连轴转,玩家随时进出,默认入口是「快速加入」。

帽子经济(死亡 → 散落 → 拾取 → 流转)依赖持续的死亡-重生循环,与淘汰制(人越死越少、死者出局观战)结构性冲突;滚动房间(中途可加入)进一步排除了「出局等本局结束」的可能。属核心循环与会话模型的方向变更,须记 ADR。当前仓库零玩法代码,变更没有工程返工成本。

## 决策

- **核心循环**:炸弹人底盘(即死、炸弹、炸软砖、道具)+ 帽子计分。击杀 = 帽子**转移**(死者帽子散落可拾),宝箱 = 帽子**发行**(挂进软砖掉落池,解决开局零帽冷启动);帽子纯计分物,无数值加成、无种类差异。
- **死亡与重生**:一击即死、帽子散落、数秒重生;取消死亡观战等待;死亡不清道具成长(死亡代价单一化)。
- **胜负**:局内计时结束,帽子最多者胜;并列同胜不加赛。死亡收缩从核心规则摘除,降级为「终局演出候选」进待验证项——与中途加入冲突,且违背「尽量简单」诉求。
- **会话模型**:房间常驻、局滚动(5–10 分钟一局连轴转,结算间歇后自动下一局),玩家任意时刻进出;退出者帽子当场散落回流;局末锁入期不放新人。
- **入口**:「快速加入」(进未满的官方参数房)为产品默认入口,依赖引擎侧「房间目录」轻量能力——按 design-request 速查属引擎能力类,登记进 `docs/specs/risks-and-engine-asks.md`(A6 细化),不在本仓落地;**房间码保留为保底入口与好友开黑/自定义房通道**,故不硬阻塞 ①。技能/段位匹配仍不做。
- **核心情绪**:欢乐混战派对(笑点优先、轻操作重戏剧);五条产品支柱落设计稿 §3,作为后续提案的否决依据。
- **锁与不锁**:锁支柱、品类、核心循环、胜负、会话模型、局时人数区间(5–10 分钟 / 8–12 人弹性)、平台优先级(Windows 优先,沿用 0004);不锁具体数值(掉帽比例、宝箱权重、局时取值、重生参数等,全部进设计稿待验证表)。

## 后果

- 推翻旧稿「最后存活者胜」「明确不做局内重生」两条核心条款;`docs/specs/bomber/design.md` 全文修订,`product-direction.md`(① 局时、匹配口径、成功判据)与 `ugc-ladder.md`(L0 例举)同步一句话口径。
- 淘汰制「最后存活」的生存张力被让渡;纯计分制的终局张力未经验证,若平淡须补终局演出(候选已留)。
- 帽子持续发行有通胀风险,接受用数值阀门(发行封顶 / 散落超时消失)在原型期解决。
- 美术新增负担:帽子 8 向 sprite 资产、帽子塔在俯视 55°–65° 下的可读性进 B1 画面验证清单,归 art-* 技能族接手。
- 「房间目录 + 快速加入」成为提给引擎侧的新登记需求;落地前仅房间码入口,快速加入的产品体验依赖引擎排期。
- 帽子皮肤类外观商业化想象被账号级持久化(A5)阻塞,明确记远期,不进首发。
