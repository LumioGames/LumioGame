# Design Doc(策划案维护)

把 [design-director](../design-director/SKILL.md) 定调的结论写成可对照执行的策划案,并长期维护。策划案是 design-request 与 design-review 的共同基准——只沉淀已定调的结论,不收探索中的想法。

## 何时使用

- 策划讨论定调,结论需要落档。
- 既有策划案要修订(方向变更提案通过、审查回流补条款)。
- 需要查「策划案放哪、长什么样」时(本技能是落点定义的单一权威)。

## 操作步骤

1. **判落点(单一权威)。** 策划案落 `docs/specs/`,**不落 `knowledge/`**——`knowledge/` 下每篇文档都进强制载入上下文(导航税),而策划案会持续增长,不该付这笔钱。三种落点:
   - 平台级(跨产品共用)→ `docs/specs/<name>.md`
   - 单产品完整设计 → `docs/specs/<product>/design.md`
   - 单产品方向级(只定调、不展开)→ `docs/specs/<product>/direction.md`

   常驻策划案用稳定名、**不带日期**;`brainstorming` 的 `docs/specs/YYYY-MM-DD-<topic>-design.md` 是一次性探索稿,两者形态不同、不混用。
2. **写文档头。** `docs/specs/` 不受 spec-lint 的 frontmatter 校验,用 H1 下的引用块承载元信息:`状态`(设计中 / 实施中 / 已交付 / 历史归档,沿用本仓枚举)、`序位` 或 `适用范围`、`上游`(相对链接)。方向级文档在状态后注明「方向级,不展开细节」。
3. **写正文。** 结构见快速参考骨架。每条结论必须是**可对照判据**(供 design-review 直接引用),**每个数值必须标来源**(见数值来源纪律);只保留当前有效结论,历史在 git;域分类指回 [design-director](../design-director/SKILL.md) 快速参考,此处不复述。
4. **同步导航。** 在 `docs/specs/README.md` 索引表加一行(不存在则新建),与文档头「状态 + 一句话」同口径。一篇一行,**修订不新增行**。
5. **校验。** `node .spec/tools/spec-lint.mjs` 通过;文档内相对链接可达。

## 快速参考(策划案骨架)

```markdown
# <标题>

> **状态**:设计中
> **序位 / 适用范围**:<这份文档管到哪>
> **上游**:<相对链接>

## 使命            ← 这份文档要回答什么问题;不写「介绍本功能」
## 定位 / 核心循环  ← 一句话说清玩家在做什么
## 规格            ← 局时、人数、胜负、地图、操作;每个数值标来源
## 系统与内容      ← 道具 / 技能 / 经济,按需
## 平衡原则        ← 可证伪的原则,不是「要平衡」
## 待验证项        ← 推断待验证的逐条列出,并写清怎么验
## 验收            ← 一个能回答是 / 否的问题
```

**渐进式建立**:P0(定调即立)= 使命 + 定位 + 验收;P1(开工前)= 规格 + 待验证项;P2 = 系统与内容细则由**首个可玩版本反推成文**,不空想。方向级文档只需 P0 + 待解决,不展开规格。

### 数值来源纪律(全仓策划案强制)

每个数值必须可归类,三选一,标在数值旁或章节开头:

| 标注 | 含义 |
|---|---|
| 已验证 | 有实测或对局数据支撑,注明来源 |
| 推断待验证 | 设计推断,**必须同时进「待验证项」并写清验证方式** |
| 引用 | 来自其他文档或架构约束,给出出处 |

来源不明的数字视为文档未完成——design-review 的第三层门禁专查这一项。

## 注意事项(Pitfalls)

- **未定调不入库。** 只写用户拍板过的结论;探索假设留在会话。
- **文档必须可判。** 「要好玩」不行,「一局 2-3 分钟、8-12 人、最后存活者胜」才行——写不成判据的条款 design-review 用不了。
- **不落 knowledge/。** 策划案进 `knowledge/` = 每会话永久付费,且会随产品数量线性增长。
- **单一权威。** 域分类在 design-director、落点定义在本技能第 1 步,同一规则不写两处。
- **维护有触发器。** [design-review](../design-review/SKILL.md) 同类退回 3 次 → 必须补条款,不靠口头传承。

## 验证

- spec-lint 通过;`docs/specs/README.md` 索引行已加,与文档头同口径。
- 每条结论可被 design-review 直接引用对照。
- 每个数值都有来源标注;推断值均已进「待验证项」。
- 文档里只有已定调结论,无「待定」「可能」类条款。
